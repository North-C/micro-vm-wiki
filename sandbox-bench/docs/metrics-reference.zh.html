    SBench Prometheus 指标参考

    本文档列出 sbench agent 暴露的所有 Prometheus 指标，按功能分类说明含义、数据来源和常用查询方式。

    指标访问

    # 查看所有指标
curl http://127.0.0.1:8888/metrics

# 过滤特定类别
curl http://127.0.0.1:8888/metrics | grep sbench_devkit_topdown

    指标命名规则

    • 所有指标以 sbench_ 开头
    • gauge 类型：当前值，可增可减（如 CPU 使用率、内存带宽）
    • counter 类型：累计值，只增不减（如 CPU 时间、上下文切换次数）

    通用标签

    以下标签在大多数业务指标中出现：

    标签 说明
    deployment_id 关联的 deployment 标识
    collector 采集器名称（perf_stat、devkit_topdown 等）
    task 采集任务名称
    target_type 采集目标类型（host、cpu_range、pid_group、block_device）
    target_cpus 目标 CPU 范围
    target_pids 目标 PID 列表
    target_devices 目标设备列表
    segment context switch 观测区间，如 arch_switch、total
    stat 聚合统计口径，如 avg、p50、p90、p99

    1. Agent 状态

    sbench_agent_scrape_timestamp_seconds

    • 类型：gauge
    • 含义：Agent 最近一次数据刷新的 Unix 时间戳
    • 数据来源：time.Now().Unix()
    • 用途：判断 Agent 是否在正常运行
    time() - sbench_agent_scrape_timestamp_seconds
# 值大于 refresh 间隔说明 Agent 可能卡住

    sbench_agent_last_refresh_success

    • 类型：gauge
    • 含义：最近一次刷新是否成功（1=成功，0=失败）
    • 数据来源：读取 state/results 文件是否出错
    • 用途：监控 Agent 健康状态

    2. 调度器状态

    以下指标仅在 Agent 使用 --schedule 启动时出现。

    标签 说明
    job 任务名称
    mode 运行模式（attached / standalone）
    config 采集配置文件路径
    resource_lock 资源锁名称

    sbench_agent_scheduler_job_enabled

    • 类型：gauge
    • 含义：任务是否启用（1=启用）
    • 数据来源：调度配置文件中的 enabled 字段

    sbench_agent_scheduler_job_running

    • 类型：gauge
    • 含义：任务当前是否正在执行（1=运行中）
    • 数据来源：运行时状态

    sbench_agent_scheduler_job_last_run_timestamp_seconds

    • 类型：gauge
    • 含义：任务最近一次运行的 Unix 时间戳
    • 数据来源：任务执行完成后记录
    time() - sbench_agent_scheduler_job_last_run_timestamp_seconds
# 距上次运行的时间，判断任务是否卡住

    sbench_agent_scheduler_job_last_success

    • 类型：gauge
    • 含义：最近一次运行是否成功（1=成功，0=失败）

    sbench_agent_scheduler_job_last_duration_seconds

    • 类型：gauge
    • 含义：最近一次运行的耗时（秒）
    • 数据来源：任务执行前后时间差

    sbench_agent_scheduler_job_runs_total

    • 类型：counter
    • 含义：任务累计运行次数

    sbench_agent_scheduler_job_failures_total

    • 类型：counter
    • 含义：任务累计失败次数
    # 失败率
rate(sbench_agent_scheduler_job_failures_total[5m])
/ rate(sbench_agent_scheduler_job_runs_total[5m])

    sbench_agent_scheduler_resource_lock_held

    • 类型：gauge
    • 含义：资源锁当前是否被持有（1=被持有）
    • 标签：resource_lock（锁名称）、holder（持有者任务名）
    • 用途：监控 PMU 等共享资源是否被占用，避免并发冲突

    3. Deployment 状态

    sbench_deployment_info

    • 类型：gauge
    • 含义：deployment 元数据，值固定为 1
    • 标签：deployment_id、name、hypervisor、status
    • 数据来源：state/deployments/*.json
    • 用途：通过标签查询 deployment 信息
    sbench_deployment_info{hypervisor="firecracker"}

    sbench_deployment_status

    • 类型：gauge
    • 含义：deployment 状态编码
    • 值：1=steady/running/completed，0=destroyed/stopped，-1=failed
    • 数据来源：deployment state 中的 status 字段
    sbench_deployment_status{status="steady"} == 1

    sbench_deployment_sandboxes

    • 类型：gauge
    • 含义：deployment 中配置的 sandbox 数量
    • 标签：deployment_id

    4. Sandbox 信息

    sbench_sandbox_info

    • 类型：gauge
    • 含义：sandbox 元数据，值固定为 1
    • 标签：deployment_id、sandbox_id、pid、cpus、numa_node
    • 数据来源：deployment state 中的 targets.sandboxes
    count(sbench_sandbox_info{deployment_id="xxx"})
# 查看 deployment 中有多少 sandbox

    5. VMM 进程（实时）

    以下指标仅在未使用 --no-proc 时出现，数据实时从 /proc 读取。 默认情况下，Agent 会遍历 deployment state 中的全部 VMM PID；高密度实验中应在 --schedule 配置的 agent.proc.target 中写入显式 PID，避免把 1000+ 沙箱全部展开为实时 /proc 时序。该过滤只影响 sbench_vmm_*，不替代 collector job 自己的 target.pid_group 配置。

    agent:
  proc:
    deployment_id: json-parse-20260521-010203
    target:
      type: pid_group
      pids: [12345]

    sbench_vmm_up

    • 类型：gauge
    • 含义：VMM 进程是否存在（1=存在，0=不存在）
    • 数据来源：读取 /proc/<pid>/stat 是否成功
    • 标签：deployment_id、sandbox_id、pid
    sbench_vmm_up{deployment_id="xxx"} == 0

    • 标签：metric（事件名，如 "LLC Miss Rate" / "TLB Miss Rate"）、function（函数名）、module（模块名）、rank（排名）
    • 数据来源：DevKit stdout 中 "Function Module" 表格

topk(10, sbench_devkit_miss_event_rate_percent{metric="LLC Miss Rate"})

sbench_devkit_miss_event_rate_percent{module="kernel"}

    14. Context Switch Cost — 内核切换开销

    数据来源：定制内核 tracepoint sched:sched_context_switch_cost。该指标要求运行 sbench-cscost 内核，并安装 bpftrace。collector 默认通过 bpftrace 抓取原始事件，再由 sbench 聚合为 Prometheus 指标。

    sbench_context_switch_cost_events

    • 类型：gauge
    • 含义：最近一次 context_switch_cost collector run 中采集到的事件数
    • 标签：deployment_id、collector、target_type、target_pids
    • 用途：判断采样窗口是否实际抓到目标 PID 的切换事件
    sbench_context_switch_cost_events

    sbench_context_switch_cost_cycles

    • 类型：gauge
    • 含义：context switch 开销的 cycles 聚合统计
    • 标签：segment、stat、target_pids
    • segment：core_pre_finish、arch_switch、finish、total
    • stat：avg、min、p50、p90、p99、max
    # switch_to 附近架构切换段 p99 cycles
sbench_context_switch_cost_cycles{segment="arch_switch",stat="p99"}

# 完整 context_switch 观测段 p50 cycles
sbench_context_switch_cost_cycles{segment="total",stat="p50"}

    sbench_context_switch_cost_ns

    • 类型：gauge
    • 含义：context switch 开销的 ns 聚合统计
    • 计算：ns = cycles * 1000000000 / cntfrq
    • 标签：同 sbench_context_switch_cost_cycles

    cntfrq 来自 tracepoint payload，不应在脚本中硬编码。当前验证机器 cntfrq=100000000，因此 1 cycle = 10ns。p50/p90/p99 来自 bpftrace lhist bucket 的中点估算。

    # switch_to 附近架构切换段 p99 ns
sbench_context_switch_cost_ns{segment="arch_switch",stat="p99"}

# 完整 context_switch 观测段 max ns，用于观察长尾
sbench_context_switch_cost_ns{segment="total",stat="max"}

    sbench_context_switch_cost_cntfrq_hz

    • 类型：gauge
    • 含义：CNTVCT counter 频率
    • 用途：验证 cycles 到 ns 的换算因子
    sbench_context_switch_cost_cntfrq_hz

    数据更新策略

    指标类别 更新方式 说明
    Agent/Scheduler 状态 每次 refresh 实时计算 默认每秒刷新
    Deployment/Sandbox 读取 state 文件 文件变更后下次 refresh 生效
    VMM 进程指标 实时读取 /proc 需要 --proc 模式（默认开启）
    采集任务元数据 遍历所有 collection 包含历史记录
    业务指标（perf/devkit/sysstat/context_switch_cost） 取最新一次采集结果 每个 deployment+collector 组合只暴露最新值，不包含 collection_id，便于 Grafana 按时间线展示
