AgentENV Sandbox 生命周期与 E2B-shaped API 链路

问题与结论

问题：一个 E2B-shaped sandbox 请求如何进入 AgentENV、变成 ready sandbox，pause/resume/snapshot/fork 又如何处理状态和失败？

结论：固定提交 00ba6cb74f309a0cbd65f6ec415640e9e674a371 的链路是 API handler → SnapshotManager/request translation → Orchestrator 状态机 → SandboxBackend → Firecracker backend。Create 可以从 committed snapshot 或 explicit image 启动；pause、resume、snapshot 和 fork 都有显式状态转换及 recoverable/terminal failure 区分。

本文确认的是源码 contract 和仓内 test/CI 配置。没有运行 E2B SDK、AgentENV server 或 Firecracker，因此不能表述为“本轮验证与所有当前 E2B SDK 完全兼容”。

OpenAPI title 是 E2B API，并声明 API-key、bearer 与 team auth scheme；同一 spec包含 sandbox create/list/get/delete/pause/resume/fork/snapshot，以及 template、snapshot、node routes。

二、warm create：Template ID 到 runnable snapshot

warm POST /sandboxes 首先调用 SnapshotManager::load_runnable(template_id)，把 committed template/snapshot解析成当前节点可用的 runnable artifact；handler随后构造 CreateSandboxRequest 并调用 Orchestrator::create_sandbox。

证据：src/api/impls/sandbox.rs:561-647。

Orchestrator create 同时支持 committed snapshot 与 explicit image launch source，并校验 snapshot 与 node 的 virtualization mode。状态 enum包括 Creating、Resuming、Running、Snapshotting、Forking、Pausing、Paused、Killing。

证据：

  • src/orchestrator/types.rs:56-66
  • src/orchestrator/service.rs:315-480

三、pause 与 resume：状态、artifact 和失败语义

Pause 使用 compare-and-set 状态、artifact protection、paused-state capture 与 persistence。recoverable failure 会把状态恢复为 Running；terminal failure 则不再把 backend 当作安全可运行实例。

证据：src/orchestrator/service.rs:985-1145。

Resume 会对并发重复调用进行 join/复用，校验 virtualization mode，并从 persisted paused state重新 launch。

证据：src/orchestrator/service.rs:1210-1345。

合理推断：CAS、join 和 recoverable/terminal 分类共同保护的是“一个生命周期操作的状态所有权”，不能简化成所有失败都 retry，也不能把 HTTP 成功直接等同于远端 artifact 已 durable。

四、snapshot 与 fork

Orchestrator snapshot 使用 Running → Snapshotting → Running；recoverable failure 回滚状态，terminal failure会 stop/remove backend。

证据：src/orchestrator/service.rs:1348-1462。

SandboxBackend contract分别定义 start/readiness、pause/resume、snapshot、fork 与 stop。Firecracker实现的 snapshot先 pause-to-dir，再 resume源实例，最后返回 opaque captured handle；fork会 capture源实例、resume源实例并并发启动 children。

证据：

  • src/sandbox/backend.rs:49-80
  • src/sandbox/backend.rs:122-236
  • src/sandbox/firecracker/sandbox.rs:273-383

捕获结果如何成为 committed snapshot/template，见 Snapshot、Template、OverlayBD 与 ublk 链路。
