crosvm ARM64 与 x86_64 架构差异链路

本文沿着 crosvm 的 Linux 启动骨架，分析 ARM64 与 x86_64 在 VM 构造、内存布局、中断控制器、机器描述、设备枚举、vCPU 初始化和热插拔能力上的差异。

源码基线：当前仓库工作树。

1. 核心结论

crosvm 的架构差异不是两套完全不同的 VMM。共同骨架是 run_config -> run_kvm/run_* -> run_vm -> Arch::build_vm -> run_control。

差异发生在编译期绑定的 Arch 类型。ARM64 使用 aarch64::AArch64，x86_64 使用 x86_64::X8664arch：src/crosvm/sys/linux.rs。

LinuxArch trait 是关键抽象。它定义内存布局、系统 allocator、VM 构造、vCPU 配置和 PCI 注册能力：arch/src/lib.rs。

ARM64 以 FDT、GIC、PSCI、MMIO 和 platform bus 为中心。x86_64 以 ACPI/MPTABLE、PIC/IOAPIC/LAPIC、I/O port、PCI config I/O 和 PC boot protocol 为中心。

热插拔边界很明确。运行期 PCI hotplug 当前只实现并允许在 x86_64 上使用，非 x86_64 会在 run_vm() 中拒绝：src/crosvm/sys/linux.rs。

2. 共同启动骨架

run_config() 先构造 VmComponents，再选择 hypervisor kind。KVM 是通用路径，ARM64 还可能有 Geniezone、Halla、Gunyah feature-gated 路径：src/crosvm/sys/linux.rs。

get_default_hypervisor() 先查 /dev/kvm。在 ARM64 且启用特性时，还会按顺序尝试 Geniezone、Halla、Gunyah 设备：src/crosvm/sys/linux.rs。

run_kvm() 为两种架构共用。它创建 KVM、调用 Arch::arch_memory_layout()，创建 guest memory 和 KvmVm，再按 irqchip 类型进入 run_vm()：src/crosvm/sys/linux.rs。

3. LinuxArch 抽象层

VmComponents 保存通用 VM 构造输入，但字段带有架构条件。x86_64 有 break_linux_pci_config_io、force_s2idle、smbios；ARM64 有 sve_config、virt_cpufreq_v2：arch/src/lib.rs。

RunnableLinuxVm 是 build_vm() 的产物。它保存 irq_chip、io/mmio/hypercall bus、PCI root、platform devices、vCPU init、VM request tubes 和 vCPU 数量：arch/src/lib.rs。

LinuxArch::build_vm() 接收已经创建好的 VmArch、IrqChipArch、设备列表和 allocator。每个架构在这里决定设备如何挂到总线、机器描述如何写入 guest memory。

LinuxArch::configure_vcpu() 在每个 vCPU 线程内调用。共同线程逻辑在 runnable_vcpu() 中，先 irq_chip.add_vcpu()，再调用 Arch::configure_vcpu()：src/crosvm/sys/linux/vcpu.rs。

4. 内存布局差异

ARM64 guest RAM 从 0x80000000 开始，并保留低地址区域给 GIC、平台 MMIO、pVM firmware 和 pvtime 等结构：aarch64/src/lib.rs。

ARM64 guest_memory_layout() 创建主内存 region。若 protected VM 需要 firmware，会额外加入 protected firmware region；若设置 swiotlb，也加入静态 SWIOTLB region：aarch64/src/lib.rs。

ARM64 allocator 把 I/O port 设为 None，低 MMIO 由 PCI mem 决定，高 MMIO 是平台 MMIO 之后的剩余 guest phys 空间，platform MMIO 单独存在：aarch64/src/lib.rs。

x86_64 保留 PC 传统内存洞、BIOS、LAPIC、IOAPIC、HPET 和 32 位以下 PCI MMIO。常量里能看到 high MMIO 上限、PCIe config MMIO 和 zero page 偏移：x86_64/src/lib.rs。

x86_64 allocator 有 I/O port 区间 0xc000..0xffff，低 MMIO 来自 PCI 32 位以下窗口，高 MMIO 来自架构布局，没有单独 platform MMIO：x86_64/src/lib.rs。

5. 中断控制器差异

IrqChip trait 是共同抽象，覆盖 IRQ event 注册、路由、service、EOI、注入、halt wait、MP state、finalize 等操作：devices/src/irqchip/mod.rs。

ARM64 的 IrqChipAArch64 额外要求查询 VGIC 版本、是否有 ITS、finalize，并声明 snapshot/restore 目前默认未实现：devices/src/irqchip/aarch64.rs。

x86_64 的 IrqChipX86_64 额外覆盖 PIC、IOAPIC、LAPIC、PIT、lapic frequency，以及完整 irqchip snapshot/restore：devices/src/irqchip/x86_64.rs。

KVM ARM64 irqchip 会创建 VGICv3，失败时退到 VGICv2。若允许且支持，还会创建 VGIC ITS，并设置 ITS base address：devices/src/irqchip/kvm/aarch64.rs。

KVM x86_64 irqchip 调 create_irq_chip() 和 create_pit()，再依据 IOAPIC pin 数生成默认路由。0-15 同时走 PIC/IOAPIC，16 以后只走 IOAPIC：devices/src/irqchip/kvm/x86_64.rs。

KVM split irqchip 只允许 x86_64。run_kvm() 在非 x86_64 上遇到 split 会直接报错：src/crosvm/sys/linux.rs。

6. 机器描述：FDT 与 ACPI

ARM64 主要通过 FDT 描述机器。AArch64::build_vm() 计算 FDT 放置位置、加载 kernel/initrd，然后调用 fdt::create_fdt() 写入 guest memory：aarch64/src/lib.rs。

ARM64 FDT 中包含 GIC、timer、PMU、PSCI、serial、PCI host、RTC、battery、vm watchdog、cpufreq 等节点。GIC 节点会根据 VGICv2/v3 和 ITS 能力变化：aarch64/src/fdt.rs。

ARM64 vcpu_init() 给 boot CPU 设置 PSTATE、PC 和 X0。X0 是 FDT 地址；若 protected firmware 参与，还会把 payload entry 和 image size 放入 X1/X2：aarch64/src/lib.rs。

x86_64 主要通过 ACPI/MPTABLE/SMBIOS 和 Linux boot params 描述机器。build_vm() 设置 identity map、TSS、PCIe config MMIO、PCI config I/O，再生成 ACPI：x86_64/src/lib.rs。

x86_64 create_acpi_tables() 生成 RSDP/FACS/DSDT/FADT/MADT 等。MADT 写入 LAPIC 地址、PCAT compat、Local APIC、IOAPIC 和 PCI interrupt override：x86_64/src/acpi.rs。

x86_64 也有 FDT，但它不是常规 PC 启动描述。只有 Android fstab、DT overlay 或 protected firmware 场景才把 DTB 放入 setup_data：x86_64/src/lib.rs。

7. 设备枚举与总线

ARM64 build_vm() 把 PCI 设备和非 PCI 设备分开。PCI 设备进入 generate_pci_root()，平台设备再走 generate_platform_bus()：aarch64/src/lib.rs。

ARM64 使用 PciConfigMmio 暴露 PCI config space，没有 x86 那种 CF8/CFC I/O port 配置入口。PCI host 信息会写入 FDT：aarch64/src/lib.rs。

generate_platform_bus() 要求 VFIO platform device 有 DT symbol，分配 platform MMIO 和 IRQ。若 protected VM 隔离内存，还会提前 mmap device regions：arch/src/sys/linux.rs。

x86_64 build_vm() 创建 MMIO、I/O port、hypercall 三个 bus。它创建 PciConfigIo 并插入 I/O bus 0xcf8，同时创建 PCIe ECAM MMIO：x86_64/src/lib.rs。

x86_64 设备 AML 会汇聚到 ACPI DSDT。PCI 中断映射、GPE scope AML 和 ACPI device resource 共同决定 guest OS 如何发现设备和电源事件。

8. vCPU 初始化差异

vCPU 线程共同入口是 start_vcpu_thread()。线程内设置调度、发送 pid/tid、调用 runnable_vcpu()，然后进入 vcpu_loop()：src/crosvm/sys/linux/vcpu.rs。

ARM64 configure_vcpu() 很薄，只把 VcpuInitAArch64.regs 中的寄存器写入 vCPU。更重的初始化在 build_vm() 中完成，包括创建全部 vCPU、计算 PMU/PVTime/SVE feature：aarch64/src/lib.rs。

ARM64 vCPU feature 包括 PSCI、PMU、PowerOff 和 SVE。build_vm() 会在创建完所有 vCPU 后，逐个调用 vcpu.init(features)：aarch64/src/lib.rs。

x86_64 configure_vcpu() 会设置 CPUID、regs、sregs、FPU、MSR，并调用 interrupts::set_lint() 配置 LAPIC LINT0/LINT1：x86_64/src/lib.rs。

x86_64 set_lint() 把 LINT0 设成 external interrupt，把 LINT1 设成 NMI。这是 PC APIC 语义的一部分：x86_64/src/interrupts.rs。

9. 热插拔边界

运行期 PCI hotplug 当前是 x86_64 能力。run_vm() 注释直接说明 pci-hotplug 只为 x86_64 实现，非 x86_64 使用 pci_hotplug_slots 会报错：src/crosvm/sys/linux.rs。

ARM64 LinuxArch::register_pci_device() 直接返回 unsupported，注释说明 hotplug function 在 AArch64 未验证：aarch64/src/lib.rs。

x86_64 register_pci_device() 调通用 arch::configure_pci_device()，负责分配 PCI address/BAR、注册 irqfd 和能力、并把设备加入 PCI root：x86_64/src/lib.rs。

PciHotPlugManager::hotplug_device() 会找空的 downstream port，为每个 function 分配地址和 IRQ，再通知 worker 发 hotplug 信号：src/crosvm/sys/linux/pci_hotplug_manager.rs。

10. Snapshot 差异

x86_64 irqchip snapshot 覆盖 PIC、IOAPIC、LAPIC、PIT、chip-specific state 和 MP state。恢复时会逐项写回这些状态：devices/src/irqchip/x86_64.rs。

ARM64 IrqChipAArch64 的默认 snapshot/restore 返回“not yet implemented”。这说明 ARM64 设备和 vCPU 以外，中断控制器状态恢复还不是同等级能力：devices/src/irqchip/aarch64.rs。

这会影响“可迁移/可恢复”的边界判断。即使 Suspendable 设备和 guest memory 能保存，irqchip 架构状态仍可能成为 ARM64 snapshot 完整性的限制。

11. 能力边界表

维度 ARM64 x86_64 源码依据
默认机器描述 FDT ACPI/MPTABLE/SMBIOS + boot params aarch64::create_fdt / x86_64::create_acpi_tables
中断控制器 VGICv2/v3，可选 ITS PIC、IOAPIC、LAPIC、PIT IrqChipAArch64 / IrqChipX86_64
PCI config MMIO config space CF8/CFC I/O + PCIe ECAM MMIO PciConfigMmio / PciConfigIo
platform device 有 platform bus，依赖 DT symbol 主要走 PCI/ACPI generate_platform_bus()
vCPU 初始化 PSCI、PMU、PVTime、SVE、X0=FDT CPUID、sregs、FPU、MSR、LAPIC LINT configure_vcpu()
PCI hotplug 当前不支持 支持 pci-hotplug feature run_vm() 非 x86 拒绝
irqchip snapshot 默认未实现 PIC/IOAPIC/LAPIC/PIT 可保存恢复 irqchip trait 实现
protected VM KVM/Geniezone/Halla/Gunyah 路径更突出 pVM firmware 和 x86 boot protocol 结合 run_config() hypervisor 分发

12. 调试阅读路线

先读 src/crosvm/sys/linux.rs 的 import 和 run_config()。这里能看到目标架构如何选择 Arch，以及 ARM64 额外 hypervisor 路径如何被编译进来。

再读 arch/src/lib.rs 的 VmComponents、RunnableLinuxVm 和 LinuxArch。这是理解所有架构差异的稳定接口。

然后并排读 aarch64/src/lib.rs 和 x86_64/src/lib.rs 的 build_vm()。重点看 allocator、bus、machine description、vCPU init 和 register_pci_device()。

最后读 devices/src/irqchip/*。中断控制器是 ARM64/x86_64 在 snapshot、hotplug、halt/wakeup 和 vCPU 运行时表现差异最大的区域。
