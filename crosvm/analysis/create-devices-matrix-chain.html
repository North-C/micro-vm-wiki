crosvm create_devices 设备矩阵与隔离链路

本文继续展开 crosvm 深入路线 中的 create_devices 后续路线。

焦点是普通 VM 设备创建矩阵、Minijail/ProxyDevice 隔离边界、virtio PCI 包装，以及 ARM64/x86_64 的设备落点差异。

本文不展开 protected VM 专题。protected VM 相关边界见现有 protected VM 系列文档。

1. 核心结论

create_devices() 是 Linux crosvm 普通设备构造的主聚合点。它返回 Vec<(Box<dyn BusDeviceObj>, Option<Minijail>)>。

这个返回值同时表达两件事：设备对象本身，以及该设备是否需要被 Minijail 隔离到子进程。

多数 virtio 设备先在 create_virtio_devices() 中变成 VirtioDeviceStub。随后 create_devices() 给每个 stub 包一层 VirtioPciDevice。

真正是否 fork 到设备子进程，不在 create_devices() 内完成，而是在架构层 generate_pci_root() 中根据 Option<Minijail> 决定。

因此 crosvm 的设备隔离不是“所有设备都外置进程”。它是设备创建时携带 jail 意图，PCI root 生成时转为 ProxyDevice。

2. 总体流程图

这条链路说明：设备类型、transport 类型和隔离方式是三个不同维度。

3. create_devices 顶层

Linux 主路径的 create_devices() 定义在 src/crosvm/sys/linux.rs。它接收 config、VM、allocator、control tube 注册器、IOMMU endpoint map 和 VFIO manager。

源码证据：src/crosvm/sys/linux.rs。

函数先处理 VFIO。每个 VFIO config 调用 create_vfio_device()，返回 PCI 或 platform 设备、jail 和可选 viommu mapper。

源码证据：src/crosvm/sys/linux.rs。

如果 VFIO 或 coIOMMU 需要锁住 guest memory，代码会提高 RLIMIT_MEMLOCK。

源码证据：src/crosvm/sys/linux.rs。

随后它调用 create_virtio_devices()，把所有普通 virtio 设备先构造成 stub。

源码证据：src/crosvm/sys/linux.rs。

对每个 virtio stub，create_devices() 创建 MSI tube、shared memory tube、ioevent tube 和 device control tube，然后构造 VirtioPciDevice。

源码证据：src/crosvm/sys/linux.rs。

最后它按配置追加 xHCI、stub PCI device 和 PvPanicPciDevice。

源码证据：src/crosvm/sys/linux.rs。

4. virtio 设备矩阵

create_virtio_devices() 是普通 virtio 设备矩阵的主函数。

源码证据：src/crosvm/sys/linux.rs。

GPU 和窗口输入在函数开头处理。若启用 GPU，它会创建 GPU control tube，并把 display mouse/keyboard 变成 virtio input 设备。

源码证据：src/crosvm/sys/linux.rs。

virtio console 来自 serial parameters 中 VirtioConsole 的条目。

源码证据：src/crosvm/sys/linux.rs。

block disk 每个都创建 disk control tube，再通过 DiskConfig::create_virtio_device_and_jail() 生成 device stub。

源码证据：src/crosvm/sys/linux.rs。

SCSI、pmem、pmem-ext2、rng、pvclock、vtpm、input、balloon、net、snd、media、video、vsock、vhost-scmi、shared dir、sound 和 vhost-user 都在同一函数分支中创建。

源码证据：src/crosvm/sys/linux.rs、src/crosvm/sys/linux.rs、src/crosvm/sys/linux.rs。

shared directory 按 SharedDirKind 分为 virtio-fs 和 9p。virtio-fs 会创建 Fs control tube；9p 直接创建 9p device。

源码证据：src/crosvm/sys/linux.rs。

vhost-user frontend 明确不创建本地 sandbox，因为 virtqueue 处理已经导出到另一个进程。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

5. VirtioDeviceBuilder 与 jail

VirtioDeviceBuilder 是“配置对象如何生成 virtio device 和 jail”的统一 trait。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

默认 create_jail() 会根据 VirtioDeviceType 和设备名选择 seccomp policy，再调用 simple_jail()。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

默认 helper create_virtio_device_and_jail() 先创建 jail，再创建 virtio device，最后返回 VirtioDeviceStub { dev, jail }。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

网络设备覆盖了 create_jail()。如果使用 vhost-net，就选择 vhost_net policy；否则选择 net policy。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

rng 这类简单设备也返回 VirtioDeviceStub，但 jail 仍由 simple_jail() 决定。

源码证据：src/crosvm/sys/linux/device_helpers.rs。

6. ProxyDevice 边界

BusDevice 是 MMIO/IO/Hypercall 地址空间上的设备访问抽象，并且要求实现 Send + Suspendable。

源码证据：devices/src/bus.rs。

ProxyDevice 包装一个运行在 fork 子进程中的 BusDevice。它本身也实现 BusDevice，对主进程表现得像普通设备。

源码证据：devices/src/proxy.rs。

ProxyDevice::new() 调用 ChildProcIntf::new()，把设备、jail 和保留 fd 传给 fork 出来的子进程。

源码证据：devices/src/proxy.rs。

ChildProcIntf::new() 创建 parent/child tube，把 tube fd 加入 keep list，fork 后在子进程里调用 device.on_sandboxed() 和 child_proc()。

源码证据：devices/src/proxy.rs。

主进程里的 ProxyDevice 通过 tube 向子进程发送 read/write/config/snapshot/restore 等命令。

源码证据：devices/src/proxy.rs。

ProxyDevice 也实现 Suspendable。snapshot 和 restore 会转发到子进程，并等待返回结果。

源码证据：devices/src/proxy.rs。

7. PCI root 如何落实隔离

x86_64 和 aarch64 都先把 devs 分成 PCI device 和其他 device，再把 PCI device 交给 arch::generate_pci_root()。

源码证据：x86_64/src/lib.rs、aarch64/src/lib.rs。

generate_pci_root() 首先给设备分配 PCI address，生成 PCI topology，分配 legacy INTx，并注册 IRQ event。

源码证据：arch/src/lib.rs。

随后它把有 jail 的设备排在前面。注释说明这样可避免某些设备在其他 sandbox 建好前启动线程。

源码证据：arch/src/lib.rs。

真正的隔离发生在这里：如果 jail 存在，就创建 ProxyDevice；如果 jail 不存在，就直接 device.on_sandboxed() 并留在主进程。

源码证据：arch/src/lib.rs。

因此 create_devices() 返回的 jail 不是装饰字段，而是后续是否 fork 设备子进程的决策输入。

8. 架构差异

x86_64 架构层创建 IO bus、MMIO bus 和 Hypercall bus，并通过 ACPI/PCI root 暴露设备。

源码证据：x86_64/src/lib.rs。

aarch64 也创建 MMIO、Hypercall 和空 IO bus，但注释明确 ARM 并不真正使用 IO bus。

源码证据：aarch64/src/lib.rs。

aarch64 还会把非 PCI platform device 单独分出，交给 platform bus 生成路径；vfio-platform 是该路径的主要来源。

源码证据：aarch64/src/lib.rs。

x86_64 还有 pflash、fw_cfg、debugcon 等 legacy/firmware 设备可通过 ProxyDevice 包装。

源码证据：x86_64/src/lib.rs、x86_64/src/lib.rs。

create_virtio_devices() 中也有 aarch64 特化设备，例如 vhost_scmi。

源码证据：src/crosvm/sys/linux.rs。

所以普通设备矩阵的主体是共享的，但最终落点由架构层决定：x86_64 更偏 PCI/ACPI/IO bus，aarch64 更偏 MMIO/FDT/platform device。

9. 能力边界

第一，create_devices() 只构造设备列表，不负责把每个设备插入具体 bus。

第二，普通 virtio 设备在 create_devices() 内都会被包装成 VirtioPciDevice，但是否进入子进程由 jail 决定。

第三，vhost-user frontend 本地没有 jail，因为数据面已经在外部 backend 进程。

第四，ProxyDevice 让主进程看到的仍然是 BusDevice，但 read/write/snapshot/restore 都会通过 tube 转发到子进程。

第五，aarch64 的 platform device 路径和 x86_64 的 legacy/firmware 设备路径不能用同一个 PCI-only 模型解释。
