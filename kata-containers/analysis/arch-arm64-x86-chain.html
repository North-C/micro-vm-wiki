Kata Containers ARM64 与 x86_64 架构支持链路

本文从源码解释 Kata 在 ARM64 与 x86_64 上的差异：runtime/hypervisor/device manager/guest agent/host check 链路。

源码基线：当前仓库工作树。不展开 CoCo。

相关：hypervisor plugin lifecycle、QEMU launch params、横向 ARM64/x86_64。

0. 术语与背景

架构差异不在单一文件

分布在 runtime config（runtime handler gate）、QEMU arch（machine/kernel/irqchip/IOMMU）、device manager（PCI/MMIO bus）、guest agent（sysfs device path）、host check（kata-ctl）中。

关键差异矩阵

维度 x86_64 ARM64
QEMU binary qemu-system-x86_64 qemu-system-aarch64
machine type Q35/microvm virt
kernel params tsc/no_timer_check/PCI lastbus iommu.passthrough=0/gic-version=host
IOMMU 支持 Intel IOMMU（add_iommu → split irqchip） virt 不支持 Intel IOMMU（appendIOMMU 返回错误）
interrupt IOAPIC/LAPIC/MSI GIC/ITS
vIOMMU 可选 arm64 明确不支持（appendIOMMU 返回 "Arm64 architecture does not support vIOMMU"）
NVDIMM 支持 aarch64/powerpc64le/x86 支持（microvm 禁用）
VFIO host check cmdline iommu= 检查 由 BIOS 设置，不走 cmdline 检查
guest device path PCI/ACPI MMIO/FDT

1. QEMU arch 差异（核心代码已在 QEMU launch params 展开）

x86_64 默认 Q35/microvm + kernel_irqchip=split（IOMMU 场景）；ARM64 默认 virt + gic-version=host + iommu.passthrough=0。appendIOMMU 在 arm64 virt 上直接返回错误（不支持 Intel IOMMU）——这是 Kata ARM64 网络的已知限制。

2. guest agent 设备路径差异

agent 等待设备出现的方式按架构不同：x86_64 经 ACPI/PCI 枚举；ARM64 经 FDT/MMIO。agent wait_for_pci_net_interface 等 helper 的超时和重试逻辑跨架构共享，但底层 sysfs 路径不同。

3. 能力边界

Kata 在 ARM64/x86_64 上的差异不在 runtime API 层——Go runtime/runtime-rs 的 sandbox/container/agent RPC 主链路架构无关。差异在 QEMU arch（machine/irqchip/IOMMU）、guest kernel driver、agent device handler、host capability check。
