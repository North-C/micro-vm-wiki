Kata Containers shim v2 到 sandbox/container 生命周期链路

本文沿 containerd shim v2 的 Create 和 Start 请求，追踪 Kata 如何从 host 侧 RPC 进入 virtcontainers、hypervisor 和 kata-agent。

源码基线：当前仓库工作树。不展开 CoCo/TDX/SEV/SNP/CCA。

相关：hypervisor plugin lifecycle、agent RPC boundary、shim exit event recovery。

0. 术语与背景

四层分工

层 职责
shim v2 containerd 协议与事件（Create/Start/Wait/Delete/Pause/Resume）
katautils OCI/config → virtcontainers config
virtcontainers sandbox 状态机（StartVM + agent）
kata-agent guest 内 container 操作（rustjail）

Kata 的 workload 不在 host 上直接 fork/exec——host 侧看到 shim/VMM/辅助进程；真正 container 进程由 guest 内 agent 管理。

1. shim v2 Create（加载 spec + CreateSandbox）

// src/runtime/pkg/containerd-shim-v2/create.go:76
func create(ctx context.Context, s *service, r *taskAPI.CreateTaskRequest) (*container, error) {
    ociSpec, bundlePath, err := loadSpec(r)              // 加载 OCI spec
    containerType, err := oci.ContainerType(*ociSpec)     // sandbox container vs pod container
    // :180  sandbox 级 → katautils.CreateSandbox
    sandbox, _, err := katautils.CreateSandbox(s.ctx, vci, *ociSpec, *s.config, rootFs, r.ID, bundlePath, /*...*/)
    s.sandbox = sandbox
    // container 级 → katautils.CreateContainer
}

首个 container（sandbox container）触发 CreateSandbox（建 VM + 连 agent）；后续 container 只建 container 记录。

2. shim v2 Start（sandbox.Start vs StartContainer）

// src/runtime/pkg/containerd-shim-v2/start.go:37
if c.cType.IsSandbox() {
    err := s.sandbox.Start(ctx)                           // sandbox 级：启动整个 sandbox（VM + agent）
    s.monitor, err = s.sandbox.Monitor(ctx)               // 启动 monitor + watchSandbox
    go watchSandbox(ctx, s)
} else {
    _, err := s.sandbox.StartContainer(ctx, c.id)          // pod container：只在已运行 sandbox 内启动 container
}

sandbox Start = virtcontainers.Sandbox.Start → hypervisor.StartVM + agent.createSandbox。pod container Start = sandbox.StartContainer → agent.startContainer。

3. 能力边界

Kata 分层清晰：shim（containerd 协议）→ katautils（配置转换）→ virtcontainers（sandbox 状态机）→ agent（guest 内操作）。host 不直接 fork workload——workload pid 在 guest 内，由 rustjail 管理。ARM64/x86_64 在 shim 层不分支——差异在 hypervisor/guest kernel/agent device handler。
