Kata Containers storage/device 到 agent RPC 链路

本文追踪 kataAgent.createContainer() 如何构造 CreateContainerRequest 中的 Storages/Devices/OCI spec，解释 rootfs/share-fs/block volume/VFIO/CDI 的边界。

源码基线：当前仓库工作树。不展开 CoCo。

相关：share-fs/rootfs/volume agent、guest agent CreateContainer。

0. 术语与背景

Go 路径 storage/device 构造

Container.create() → attachDevices → getSystemMountInfo → c.sandbox.agent.createContainer()。kataAgent 构造 CreateContainerRequest（ContainerId/ExecId/Storages/Devices/OCI/SandboxPidns）。

关键边界

  • rootfs 经 fsShare.ShareRootFilesystem() → shared rootfs 或 storage。
  • block OCI mounts → agent Storage。
  • VFIO/CDI → guest device path。
  • host 编码，guest 解码——host 构造 request，agent 在 guest 内落地。
// src/runtime/virtcontainers/container.go:1398
func (c *Container) create(ctx context.Context) error {
    c.attachDevices(ctx); c.getSystemMountInfo()
    process, err := c.sandbox.agent.createContainer(ctx, c.sandbox, c)
    c.process = *process
}

1. 能力边界

Go 路径的 storage/device 边界：rootfs（share-fs 或 block）、volume（share-fs/block/ephemeral/local/hugepage）、device（block/CDI/VFIO）。所有这些最终收敛到 CreateContainerRequest.Storages + Devices + OCI。ARM64/x86_64 在 request 构造层不分支——差异在 guest 内 device path/storage handler（见 guest agent CreateContainer）。
