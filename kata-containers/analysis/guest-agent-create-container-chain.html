Kata guest agent CreateContainer 落地链路

本文追踪 guest 内 kata-agent 如何处理 CreateContainerRequest：解析 OCI spec → add_devices → add_storages → setup_bundle → rustjail LinuxContainer + init Process。

源码基线：当前仓库工作树。不展开 CoCo。

相关：storage/device agent、agent RPC boundary、agent container lifecycle。

0. 术语与背景

CreateContainerRequest 的 guest 内落地

host 编码 rootfs/storage/device/OCI spec/IO 端口 → guest agent 解码并落地为 bundle/mount/device/rustjail process。

do_create_container 顺序

is_allowed → parse OCI → add_devices → add_storages → setup_bundle → LinuxContainer::new → Process::new（init process 准备态，等 StartContainer 驱动 exec）。

// src/agent/src/rpc.rs:199
async fn do_create_container(&self, req: CreateContainerRequest) -> Result<()> {
    add_devices(&cid, &sl(), &req.devices, &mut oci, &self.sandbox).await?;
    let m = add_storages(sl(), req.storages.clone(), &self.sandbox, Some(req.container_id)).await?;
    let mut ctr: LinuxContainer = LinuxContainer::new(cid, CONTAINER_BASE, Some(s.devcg_info.clone()), opts, &sl())?;
    s.add_container(ctr);
}

1. 关键步骤

步骤 做什么 源码
add_devices 处理 devices + CDI + trusted storage agent/src/rpc.rs:202
add_storages rootfs + volume → mount to MountPoint（同一套 storage handler） agent/src/rpc.rs:212
setup_bundle 写 bundle spec agent/src/rpc.rs:238
LinuxContainer::new 创建 rustjail container agent/src/rpc.rs:252
Process::new init process（阻塞在 exec fifo 等待点） agent/src/rpc.rs:257

rootfs 和 volume 用同一套 storage 流程——add_storages 遍历 storage 列表，按 driver 从 STORAGE_HANDLERS 找 handler（virtio-blk-pci/mmio/ephemeral/local/pmem/overlayfs/scsi/virtio-fs/bind-watcher/image-pull/multi-layer-erofs），先 mount 到 MountPoint，rustjail 再按 OCI mounts 绑定。

2. 能力边界

CreateContainer 只创建准备态——init process 阻塞在 exec fifo 上，等后续 StartContainer 的 ctr.exec() 才释放运行。agent 不直接信任 host mount 路径——先 add_storages 转成 guest 内真实挂载点，再让 rustjail 按更新后的 OCI spec 创建容器。
