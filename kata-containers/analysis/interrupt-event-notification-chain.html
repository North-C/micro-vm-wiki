Kata Containers 中断与事件通知委托链路

本文展开 Kata 如何表达设备/IOMMU/kernel_irqchip/网络/存储中断状态——Kata 不实现 irqfd/MSI/GIC 注入，而是委托给 hypervisor plugin。

源码基线：当前仓库工作树。不展开 CoCo。

相关：hypervisor plugin lifecycle、横向 interrupt。

0. 术语与背景

Kata 的中断 = 委托

Kata runtime 不实现 irqfd/MSI-X/GIC/IOAPIC 注入——它只表达"需要什么中断能力"，由 QEMU/CH/FC/Dragonball plugin 实现。

三层表达

层 表达什么
Go QEMU kernel_irqchip/splitIrqChipMachineOptions/add_iommu（QEMU 命令行参数）
runtime-rs Hypervisor trait add_device/use_generic_irq/use_shared_irq（设备 IRQ 参数，实际注入由 plugin）
agent guest 可见设备状态（经 RPC 查询，不直接注入中断） 
// src/runtime/virtcontainers/qemu_amd64.go
func (q *qemuAmd64) splitIrqChipMachineOptions(machine string) string {
    return fmt.Sprintf("%s,accel=kvm,kernel_irqchip=split", machine)
}

1. Go QEMU irqchip 配置

amd64 QEMU splitIrqChipMachineOptions = accel=kvm,kernel_irqchip=split。IOMMU 场景 add_iommu 设 kernel_irqchip=split。arm64 virt machine 不支持 Intel IOMMU（appendIOMMU 返回错误）。

2. runtime-rs CH plugin irq 参数

ch/inner_device.rs:651-652 暴露 use_generic_irq/use_shared_irq——实际中断注入仍由 CH 执行。Kata 只表达"这个设备需要哪种 IRQ 模式"。

3. 能力边界

Kata 的中断边界是runtime 语义：要知道何时需 split irqchip/IOMMU/VFIO/热插拔，但不应把 QEMU/CH 的 irqfd/MSI 路由逻辑复制到 runtime。"Kata 支持中断"的真实含义是"Kata 经 hypervisor plugin 委托中断"——具体能力取决于 plugin。
