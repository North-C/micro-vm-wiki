Kata Containers Snapshot / Restore / Persist 链路

本文展开非机密计算路径下，Kata 的 state persist、VM save 和 container checkpoint 边界。

源码基线：当前仓库工作树。不展开 CoCo。

相关：shim sandbox lifecycle、shim exit event recovery、横向 snapshot。

0. 术语与背景

persist ≠ snapshot ≠ checkpoint

概念 含义
persist virtcontainers 落盘 sandbox/container/hypervisor/agent/network state（用于 shim 重启恢复）
snapshot hypervisor save_vm + runtime state（用于迁移/恢复 VM）
checkpoint containerd Checkpoint 接口（完整 VM + runtime 状态）

persist 权威在 virtcontainers 层

shim service 的 containers map/events channel/exitCh 是进程内结构；virtcontainers persist 是落盘的权威。shim 崩溃后 persist 能重建 virtcontainers 对象，但不能恢复 shim 进程内 channel 状态。

// src/runtime/virtcontainers/persist.go:278
func (s *Sandbox) Save() error {
    s.dumpState(&ss, cs); s.dumpHypervisor(&ss); s.dumpDevices(&ss, cs)
    s.dumpProcess(cs); s.dumpMounts(cs); s.dumpAgent(&ss); s.dumpNetwork(&ss); s.dumpConfig(&ss)
    return s.store.ToDisk(ss, cs)
}

1. Sandbox.Save/Restore

已在 shim exit event recovery §8 详细展开（Sandbox.Save() dump state/hypervisor/devices/process/mounts/agent/network/config → ToDisk；Restore() FromDisk → load state/hypervisor/devices/agent/network）。

2. 能力边界

Kata persist 是 sandbox/resource/hypervisor 层状态——不等于 containerd task 的完整 process map checkpoint。runtime-rs VirtSandbox::save() 保存 hypervisor + resource state 写 SandboxState（只含 sandbox type/resource/hypervisor state，不含 container process map）。restore 只支持部分 hypervisor 分支（Dragonball/QEMU 有 restore 分支，其他报 unsupported）。
