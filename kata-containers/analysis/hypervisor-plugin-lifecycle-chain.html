Kata runtime-rs Hypervisor Plugin 生命周期链路

本文展开 runtime-rs 的 Hypervisor trait、VirtSandbox start、ResourceManager、Dragonball/Firecracker/Cloud Hypervisor capability 和 ARM64/x86_64 边界。

源码基线：当前仓库工作树。不展开 CoCo。

相关：shim sandbox lifecycle、runtime-rs resource device agent。

0. 术语与背景

Hypervisor trait 是 runtime-rs 的虚拟化后端抽象

runtime-rs 不直接面对 KVM——它定义 Hypervisor trait（prepare_vm/start_vm/stop_vm/add_device/resize 等），由 Dragonball/Firecracker/Cloud Hypervisor plugin 实现。

VirtSandbox::start 的 VM 生命周期

prepare_vm → prepare_for_start_sandbox（资源）→ prepare_before_start_vm（设备）→ start_vm → agent 连接 → setup_after_start_vm → create_sandbox。

1. Hypervisor trait（后端抽象）

// src/runtime-rs/crates/hypervisor/src/lib.rs:98
#[async_trait]
pub trait Hypervisor: std::fmt::Debug + Send + Sync {
    async fn prepare_vm(&self, id: &str, netns: Option<String>, annotations: &HashMap<String, String>, selinux_label: Option<String>) -> Result<()>;
    async fn start_vm(&self, timeout: i32) -> Result<()>;
    async fn stop_vm(&self) -> Result<()>;
    async fn pause_vm(&self) -> Result<()>;
    async fn save_vm(&self) -> Result<()>;
    async fn resume_vm(&self) -> Result<()>;
    async fn resize_vcpu(&self, old_vcpus: u32, new_vcpus: u32) -> Result<(u32, u32)>;
    async fn resize_memory(&self, new_mem_mb: u32) -> Result<(u32, MemoryConfig)>;
    async fn add_device(&self, device: DeviceType) -> Result<DeviceType>;
    async fn remove_device(&self, device: DeviceType) -> Result<()>;
    async fn update_device(&self, device: DeviceType) -> Result<()>;
    // ... get_agent_socket / hypervisor_config / capabilities ...
}

这是 runtime 语义，不是 KVM 语义——Dragonball/Firecracker/Cloud Hypervisor/QEMU 各自实现。

2. VirtSandbox::start（VM 启动顺序）

// src/runtime-rs/crates/runtimes/virt_container/src/sandbox.rs:571
async fn start(&self) -> Result<()> {
    if inner.state != SandboxState::Init { return Ok(()); }    // 必须 Init
    self.hypervisor.prepare_vm(id, netns, annotations, selinux_label).await?;
    let resources = self.prepare_for_start_sandbox(id, network_env).await?;
    self.resource_manager.prepare_before_start_vm(resources).await?;
    self.hypervisor.start_vm(10_000).await.context("start vm")?;  // 启动 VM（10s timeout）
    // ... OCI hook → agent.start → setup_after_start_vm → create_sandbox → Running ...
}

3. 能力边界

Dragonball = Kata 自研轻量 VMM（进程内）；Firecracker plugin = 内嵌 FC 二进制；Cloud Hypervisor plugin = 内嵌 CH 进程；QEMU = govmm QEMU 命令行。各 plugin 的 capability（热插拔/share-fs/vsock/numa）不同——Kata 的能力边界 ≠ Hypervisor trait 本身，必须看具体 plugin 实现。ARM64/x86_64 在 trait 层不分支——差异在 plugin + guest kernel + 设备 transport。
