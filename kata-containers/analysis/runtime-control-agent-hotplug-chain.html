Kata Containers 运行期控制、Agent RPC 与设备更新链路

本文从源码解释 Kata 运行中 container/sandbox 如何处理 pause/resume/exec/kill/stats/update、网络更新、设备热插拔和资源 resize。

源码基线：当前仓库工作树。不展开 CoCo。

相关：shim sandbox lifecycle、agent RPC boundary、横向 runtime control。

0. 术语与背景

运行期控制经 shim v2 → virtcontainers → kataAgent → guest agent

操作 shim v2 virtcontainers kataAgent guest agent
Pause/Resume PauseContainer/ResumeContainer sandbox.Pause/Resume — agent pause/resume handler
Update UpdateContainer sandbox.UpdateContainer updateContainer update_container → OCI resources → rustjail set
Stats StatsContainer sandbox.StatsContainer statsContainer stats_container → cgroup stats
Exec Exec sandbox.Exec exec exec_process → rustjail run
Kill Kill sandbox.KillContainer signalProcess signal_process → libc::kill

双层资源语义

host runtime 改 VM 拓扑（resize_vcpu/resize_memory）；guest agent 改容器 cgroup（UpdateContainer）。两层都必须完成。

1. shim v2 Pause/Resume

// src/runtime/pkg/containerd-shim-v2/service.go:709
func (s *service) Pause(ctx context.Context, r *taskAPI.PauseRequest) (*emptypb.Empty, error) {
    c.status = task.Status_PAUSING
    err = s.sandbox.PauseContainer(spanCtx, r.ID)
    if err == nil { c.status = task.Status_PAUSED }
}
// :750  Resume 同理
func (s *service) Resume(ctx context.Context, r *taskAPI.ResumeRequest) (*emptypb.Empty, error) {
    err = s.sandbox.ResumeContainer(spanCtx, c.id)
    if err == nil { c.status = task.Status_RUNNING }
}

2. UpdateContainer（OCI resources → gRPC → agent）

// src/runtime/virtcontainers/kata_agent.go:2051
func (k *kataAgent) updateContainer(ctx context.Context, sandbox *Sandbox, c Container, resources specs.LinuxResources) error {
    grpcResources, err := grpc.ResourcesOCItoGRPC(&resources)    // OCI → gRPC resources
    req := &grpc.UpdateContainerRequest{ ContainerId: c.id, Resources: grpcResources }
    _, err = k.sendReq(ctx, req)                                 // → guest agent update_container
}

guest update_container 校验请求、找 container、protobuf resources 转 OCI resources、调 container.set（rustjail 更新 cgroup manager）。运行期资源限制最终在 guest 内 cgroup 生效——host runtime 成功 ≠ guest 内限制已生效。

3. 能力边界

Kata 运行期控制是双层：host runtime（shim/virtcontainers/kataAgent）管 VM 级；guest agent 管 container cgroup 级。ARM64/x86_64 在 RPC 层不分支——差异在 hypervisor 设备热插拔 capability 和 guest kernel 是否支持对应 cgroup controller。
