Kata Containers CPU / 调度边界链路

本文展开 Kata 的 CPU 资源语义如何跨 hypervisor config、QEMU arch topology、runtime-rs resize 和 guest agent online。

源码基线：当前仓库工作树。不展开 CoCo。

相关：hypervisor plugin lifecycle、runtime control agent hotplug、横向 resource QoS。

0. 术语与背景

CPU 资源三层

层 做什么
VM 配置层 hypervisor config 定义 vCPU 数/topology（cpuTopology）
VM resize 层 runtime-rs Hypervisor::resize_vcpu 改 VM vCPU 数
guest online 层 agent online_cpu_mem 在 guest 内 online 新 CPU（写 sysfs）

host resize ≠ guest 可用——VM 侧加 vCPU 后，guest kernel 还需 online 才能使用（类似 Firecracker/CH）。

1. QEMU CPU topology

// src/runtime/virtcontainers/qemu_arch_base.go:327
func (q *qemuArchBase) cpuTopology(vcpus, maxvcpus uint32) govmmQemu.SMP {
    return govmmQemu.SMP{
        CPUs: vcpus, Sockets: maxvcpus, Cores: defaultCores, Threads: defaultThreads, MaxCPUs: maxvcpus,
    }
}

QEMU SMP 参数：CPUs（当前 vCPU 数）vs MaxCPUs（最大）。热插拔在 MaxCPUs 范围内增减 CPUs。

2. agent online_cpu_mem（guest 内 online）

// src/agent/src/rpc.rs:1497
async fn online_cpu_mem(&self, ctx, req: OnlineCPUMemRequest) -> ttrpc::Result<Empty> {
    is_allowed(&req).await?;
    sandbox.online_cpu_memory(&req).map_ttrpc_err(same)?;    // 写 guest sysfs online CPU/memory
    Ok(Empty::new())
}

Go runtime 侧 onlineCPUMem 发 OnlineCPUMemRequest（NbCpus/CpuOnly）。agent 在 guest 内写 sysfs probe/online 路径——host resize 后必须调 agent online，否则 guest kernel 不认识新 CPU。

3. 能力边界

Kata CPU 资源是双层：host hypervisor config + resize 管 VM vCPU 数；guest agent online 管 guest kernel 可用性。ARM64/x86_64 差异在 QEMU machine type（Q35 vs virt）+ GIC/APIC 中断控制器 + guest kernel 是否支持 CPU hotplug driver。
