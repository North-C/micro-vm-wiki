    Kata shim v2 Exit / Event / Recovery 链路

    本文补齐 Kata shim v2 生命周期的可靠性侧链：containerd 的 Wait/Delete/Shutdown、exit event 和 persist/recover 边界。

    源码基线：当前仓库工作树。本文不分析 CoCo/TDX/SEV/SNP/CCA。

    相关：shim v2 到 sandbox/container 生命周期、Agent Container 生命周期、Snapshot/Restore/Persist。

    0. 术语与背景

    两层状态，权威不同

    Kata shim v2 的可靠性分两层，权威不同：

    层 持有什么 权威性
    shim service（进程内） containers map、events chan、ec（exit chan）、exitCh 进程内结构，shim 崩溃即丢
    virtcontainers（persist 落盘） sandbox/hypervisor/devices/process/mounts/agent/network/config 落盘，shim 重启可恢复对象

    关键：persist 保存 virtcontainers 状态，不保存 shim service 的 Go channel 队列状态。shim 崩溃后 persist 能重建 virtcontainers 对象，但不能天然恢复旧 shim 进程的 Wait channel 队列或未发布 event。

    两条独立通道（易混）

    通道 走向 用途
    TaskExit event 后台 wait() goroutine → cReap() → s.ec → processExits → forwarder → containerd 通知 containerd "进程退出了"
    WaitResponse containerd Wait() 读 container/exec 的 exitCh 返回退出码给 Wait 调用方

    TaskExit 不是由 containerd Wait() 发送的，而是后台 wait() goroutine 经 cReap() 发送。

    host pid（再次强调）

    shim 返回给 containerd 的 PID 是 hypervisor PID（hpid），不是 guest workload PID（源码注释明确：shimv2 无法从 VM 取容器进程 pid，故需 pid 处直接返回 hypervisor pid，service.go:123）。

    1. 核心结论

    • 可靠性两层：shim service（进程内 map/channel）+ virtcontainers（persist 落盘）。
    • containerd Wait 不等 host 子进程——后台 wait() goroutine 调 guest agent WaitProcess，结果写 exitCh。
    • TaskExit event 与 WaitResponse 是两条不同通道。
    • persist 权威在 virtcontainers 层；shim service 的 map/channel 是进程内结构。

    2. Service 内存结构

    // src/runtime/pkg/containerd-shim-v2/service.go:123
type service struct {
    sandbox    vc.VCSandbox
    containers map[string]*container    // 进程内 container 状态
    monitor    chan error
    ec         chan exit                // exit channel
    events     chan interface{}         // 事件 channel
    cancel     func()
    hpid       uint32                   // hypervisor pid（返回给 containerd 的 pid）
    pid        uint32                   // shim pid
    // ...
}

    New() 初始化 containers/events/ec，启动 processExits() 与 forwarder：

    // src/runtime/pkg/containerd-shim-v2/service.go:95
s := &service{
    containers: make(map[string]*container),
    events:     make(chan interface{}, chSize),
    ec:         make(chan exit, bufferSize),
    pid:        uint32(os.Getpid()),
    // ...
}
go s.processExits()
forwarder := s.newEventsForwarder(ctx, publisher)
go forwarder.forward()

    container 对象保存 exitIOch/exitCh/status/exit code/exit time/OCI spec/exec map（container.go:21/54）；exec 也有自己的 exitIOch/exitCh（exec.go:22/121）——主进程与 exec 在 Wait 层分开。

    3. Event Forwarder

    forwarder 两种实现：无 TTRPC_ADDRESS 只写日志，否则用 containerd publisher：

    // src/runtime/pkg/containerd-shim-v2/event_forwarder.go:56
func (cf *containerdForwarder) forward() {
    for e := range cf.s.events {
        ctx, cancel := context.WithTimeout(cf.ctx, timeOut)        // 5s timeout
        err := cf.publisher.Publish(ctx, getTopic(e), e)
        cancel()
        if err != nil { shimLog.WithError(err).Error("post event") }  // 失败只记日志
    }
}

    publisher publish 失败只记日志，不回滚已完成的生命周期动作。vendor remote publisher 遇 ttrpc.ErrClosed 会 reconnect 重试一次（连接恢复，非状态恢复，publisher.go:147/151）。

    4. Start 后的 Watcher

    主 sandbox 启动时 startContainer() 调 sandbox.Start() 后启 Monitor()/watchSandbox()/异步网络 rescan/watchOOMEvents()（start.go:37/42）。普通 pod container 调 sandbox.StartContainer()（不重启 monitor，:65）。watchSandbox() 收非 nil 错误时停删 sandbox、卸载 rootfs，明确不发 async exit event（wait.go:114/151）。OOM watcher 经 sandbox.GetOOMEvent() 读事件发 TaskOOM（:155/176）。

    5. Wait 结果链路（核心）

    后台 wait() 等 IO 结束 → 调 sandbox.WaitProcess → 更新状态/exit code/exitTime → 写 exitCh → cReap() 写 s.ec：

    // src/runtime/pkg/containerd-shim-v2/wait.go:24
<-c.exitIOch                                          // 先等 IO copy 结束
ret, err := s.sandbox.WaitProcess(ctx, c.id, processID)  // 调 guest agent WaitProcess
if err != nil && ret == 0 { ret = exitCode255 }       // 失败且返回码 0 改 255
c.status = task.Status_STOPPED; c.exit = uint32(ret); c.exitTime = timeStamp
c.exitCh <- uint32(ret)                               // 写 exitCh（供 containerd Wait 读）
go cReap(s, int(ret), c.id, execID, timeStamp)        // 写 s.ec（供 processExits 转 TaskExit）
    sequenceDiagram participant W as wait goroutine participant S as sandbox participant C as container/exec participant EC as s.ec participant F as event forwarder W->>W: wait exitIOch W->>S: WaitProcess(container, process) W->>C: set status/exit/exitTime W->>C: exitCh <- code W->>EC: cReap(exit) EC->>F: TaskExit event

    cReap() 把 exit 记录写 s.ec（utils.go:24）；processExits() 从 s.ec 取 → checkProcesses() 构造 TaskExit 经 forwarder 发 containerd：

    // src/runtime/pkg/containerd-shim-v2/service.go:1118
func (s *service) processExits() {
    for e := range s.ec { s.checkProcesses(e) }
}
func (s *service) checkProcesses(e exit) {
    s.sendL(&eventstypes.TaskExit{ ContainerID: e.id, ID: id, Pid: e.pid, ExitStatus: uint32(e.status), /*...*/ })
}

    containerd Wait() 只读 exitCh，读完写回 channel 供多 Wait 拿同退出码（:1093/1097）：

    // src/runtime/pkg/containerd-shim-v2/service.go:1093
if r.ExecID == "" {
    ret = <-c.exitCh
    c.exitCh <- ret                    // refill，供其他 Wait
} else {
    execs, _ := c.getExec(r.ExecID)
    ret = <-execs.exitCh
    execs.exitCh <- ret
}
return &taskAPI.WaitResponse{ ExitStatus: ret, ExitedAt: timestamppb.New(c.exitTime) }, nil

    边界：exec Wait() 读的是 execs.exitCh，但返回的 ExitedAt 仍用 c.exitTime（不是 execs.exitTime，:1105/1112）。

    6. Delete 语义

    Delete() 主 container 调 deleteContainer() + 发 TaskDelete + 返回 exit status/exit time/hypervisor PID：

    // src/runtime/pkg/containerd-shim-v2/service.go:517
if r.ExecID == "" {
    deleteContainer(spanCtx, s, c)                     // StopContainer + DeleteContainer + poststop hooks + 卸 rootfs
    s.send(&eventstypes.TaskDelete{ ContainerID: c.id, Pid: s.hpid, ExitStatus: c.exit, /*...*/ })
    return &taskAPI.DeleteResponse{ ExitStatus: c.exit, Pid: s.hpid }, nil  // Pid = hpid
}
// exec 删除：只删 exec map
c.deleteExec(r.ExecID)
return &taskAPI.DeleteResponse{ ExitStatus: uint32(execs.exitCode), Pid: s.hpid }, nil

    Delete() 返回的 exit status 来自先前 wait() 保存的状态——没完成 wait 链路，Delete 语义就不完整。

    7. Shutdown 与 Cleanup

    Shutdown() 只在 containers 为空时真正关闭；否则只停 tracing 返回（:960/971）。真正关闭时 cancel() + 对 hpid 发 SIGKILL（确保 hypervisor 进程退出）+ os.Exit(0)：

    // src/runtime/pkg/containerd-shim-v2/service.go:986
s.cancel()
syscall.Kill(int(s.hpid), syscall.SIGKILL)    // 注释：stopSandbox 只发 qmp shutdown 没等 qemu 退出，这里兜底
os.Exit(0)                                     // defer 不执行，故显式补日志/metrics

    os.Exit(0) 不执行 defer——代码显式补写日志和 metrics。Cleanup() 是 shim binary cleanup 路径，解析 OCI spec 按 container type 调 cleanupContainer() 返回 SIGKILL 风格 delete response（:347/381）。

    8. Persist / Restore 边界

    virtcontainers Sandbox.Save() 落盘全套状态：

    // src/runtime/virtcontainers/persist.go:278
func (s *Sandbox) Save() error {
    s.dumpState(&ss, cs); s.dumpHypervisor(&ss); s.dumpDevices(&ss, cs)
    s.dumpProcess(cs); s.dumpMounts(cs); s.dumpAgent(&ss); s.dumpNetwork(&ss); s.dumpConfig(&ss)
    return s.store.ToDisk(ss, cs)
}
// :374
func (s *Sandbox) Restore() error {
    ss, _, err := s.store.FromDisk(s.id)
    s.loadState(ss); s.loadHypervisor(ss.HypervisorState); s.loadDevices(ss.Devices)
    s.loadAgent(ss.AgentState); s.loadNetwork(ss.Network)
    return nil
}

    createSandbox() 后尝试 s.Restore()，newContainer() 也先尝试 c.Restore()（成功跳过新建临时盘/mount/devices，sandbox.go:731、container.go:777）。PodContainer StartShim() 从 OCI spec 取 sandbox ID 返回已有 sandbox shim 的 socket——复用同一 shim，不是新 shim 恢复旧内存状态（utils.go:99/104）。

    containerd shim vendor 代码明确 shim plugin root 为空（shim 不支持持久存储，用 state directory，清理/重启时销毁，shim.go:408）。所以 persist 权威在 virtcontainers 层，shim service 的 map/channel 是进程内结构。

    9. ARM64 与 x86_64 / 容易误读

    本链路几乎不按架构分叉（TaskService/channel/publisher/Wait/Delete/Shutdown 都是通用 Go）。差异来自下层 hypervisor/agent/kernel/设备——如 WaitProcess 能否稳定返回取决于 guest agent 与 VM 状态。异步网络 rescan 注释提到"慢架构场景"，是容忍时序差异的机制（start.go:49）。

    七个常见误读：① 返回的 PID 是 hypervisor PID 不是 guest workload pid；② TaskExit 由后台 wait() 经 cReap() 发，不是 Wait() 发；③ watchSandbox() 异常不发 async exit event；④ Delete() exit status 来自先前 wait() 保存状态；⑤ persist 存 virtcontainers，不存 shim channel 队列；⑥ PodContainer 复用 shim socket ≠ shim 进程重启恢复；⑦ publisher reconnect 只恢复事件连接，不恢复 TaskService 状态。
