Kata Containers QEMU 启动参数构造链路

本文展开 Go runtime 的 QEMU 后端启动参数构造：HypervisorConfig → CreateVM()/AddDevice()/StartVM() → govmm Config。

源码基线：当前仓库工作树。不展开 CoCo。

相关：arch ARM64/x86_64、hypervisor plugin lifecycle。

0. 术语与背景

Go runtime QEMU 后端

Go runtime 的 HypervisorConfig 定义 kernel/image/initrd/machine/devices。QEMU 经 CreateVM() + AddDevice() + StartVM() 构造 govmm Config，最终启动 QEMU 进程。

关键参数构造

参数 x86_64 ARM64
machine Q35/microvm virt
kernel params tsc/no_timer_check/PCI iommu.passthrough=0/gic-version=host
irqchip kernel_irqchip=split（IOMMU 场景） GIC
CPU topology cpuTopology(vcpus, maxvcpus) 同
NVDIMM 支持 aarch64 支持（microvm 禁用） 
// src/runtime/virtcontainers/qemu_arch_base.go:327
func (q *qemuArchBase) cpuTopology(vcpus, maxvcpus uint32) govmmQemu.SMP {
    return govmmQemu.SMP{ CPUs: vcpus, Sockets: maxvcpus, Cores: defaultCores, Threads: defaultThreads, MaxCPUs: maxvcpus }
}

1. 能力边界

Go QEMU 后端是 Kata 最成熟的 hypervisor plugin。CreateVM() 建 QEMU 进程 + QMP 连接；AddDevice() 经 QMP hotplug 设备；StartVM() 启动 VM。ARM64 virt machine 不支持 Intel IOMMU（appendIOMMU 返回错误）。splitIrqChipMachineOptions = accel=kvm,kernel_irqchip=split（IOMMU 场景）。
