Kata ARM64 功能与测试覆盖边界链路

本文区分两类结论：源码机制是否存在，以及 ARM64 集成测试是否覆盖。二者不能混为同一个支持结论。

源码基线：当前仓库工作树。不展开 CoCo。

相关：arch ARM64/x86_64、横向 ARM64/x86_64。

0. 术语与背景

两类结论的区分

问题 证据来源 含义
源码机制是否存在 源码 grep/cfg gate/函数定义 功能可以工作
ARM64 集成测试是否覆盖 aarch64 测试过滤/CI matrix 功能已被验证

"源码存在" ≠ "ARM64 已验证"。很多功能在源码层跨架构共享，但 ARM64 CI 可能跳过或未覆盖。

// src/runtime/virtcontainers/qemu_arm64.go
func (q *qemuArch64) appendIOMMU(options *govmmQemu.Options, machine string) error {
    return fmt.Errorf("Arm64 architecture does not support vIOMMU")
}

1. 关键发现

功能 源码存在？ ARM64 测试覆盖？
hotplug（CPU/memory/net/block） ✓（QEMU SMP + agent online） 部分（aarch64 测试过滤部分 hotplug case）
virtio-fs ✓ 部分
vsock ✓ 部分
block device ✓ 部分
network ✓ 部分（arm64 virt 不支持 vIOMMU）
vIOMMU ✓（QEMU arch 层） ✗ arm64 virt 不支持 Intel IOMMU

2. 能力边界

Kata ARM64 的"支持"应区分三层：①源码机制跨架构共享（多数是）；②QEMU arch 有 arm64 分支（machine type/GIC/IOMMU 差异）；③集成测试 aarch64 过滤。当前 ARM64 测试覆盖不如 x86_64 完整——hotplug/virtio-fs/vsock/block/network 的部分场景在 aarch64 CI 被过滤。不能把"源码共享"等同于"ARM64 端到端验证通过"。
