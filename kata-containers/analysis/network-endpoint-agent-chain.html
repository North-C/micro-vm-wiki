Kata Containers 网络 Endpoint 到 Agent 链路

本文解释 Kata 普通非机密计算路径下，网络如何从 host network namespace 接口变成 VM 网卡设备，再由 guest agent 配置 IP/route/ARP。

源码基线：当前仓库工作树。不展开 CoCo。

相关：shim sandbox lifecycle、横向 network connectivity。

0. 术语与背景

网络三层 ready

层 做什么 谁负责
host endpoint host netns 扫描接口（TC filter/CNI） virtcontainers network
VM NIC endpoint attach 到 hypervisor（AddDevice/HotplugAddDevice） hypervisor plugin
guest interface agent UpdateInterface/UpdateRoutes 配置 IP/route/ARP kata-agent

关键边界

  • Kata 不自己实现 virtio-net 数据面——委托给 hypervisor plugin（QEMU/CH/Dragonball）。
  • network ready = host endpoint 可达 + VM NIC 设备存在 + guest agent 配置完成。三层都收敛才算网络 ready。
  • ARM64 virt machine 不支持 Intel IOMMU；amd64 在 IOMMU 场景切 split irqchip。

1. 网络链路

// src/runtime/virtcontainers/veth_endpoint.go:108
func (endpoint *VethEndpoint) HotAttach(ctx context.Context, s *Sandbox) error {
    return s.hypervisor.HotplugAddDevice(ctx, endpoint, NetDev)  // 热插拔网卡到 hypervisor
}
// agent 侧：UpdateInterface 按 MAC 查 link → 设 IP/MTU/UP

CNI/TC → host netns 扫描 endpoint → hypervisor.AddDevice/HotplugAddDevice → VM NIC
→ kata-agent UpdateInterface（按 MAC 查 link → 设 IP/MTU/UP）
→ kata-agent UpdateRoutes（删旧路由 + 添加新路由）
→ kata-agent UpdateARPNeighbors（手工 RTM_NEWNEIGH）

Kata 的网络设备数据面委托给 hypervisor plugin——runtime 只编排 endpoint attach + agent 配置。不实现 virtqueue/irqfd。详见 interrupt event notification（委托链路）。

2. 能力边界

Kata 网络能力边界 = hypervisor plugin 是否支持对应 endpoint 类型（TAP/vhost-user/vDPA）+ guest kernel 是否支持对应 virtio driver + agent 是否能等待设备出现并配置。ARM64 差异：virt machine 不支持 Intel IOMMU（appendIOMMU 返回错误），amd64 IOMMU 场景切 kernel_irqchip=split。
