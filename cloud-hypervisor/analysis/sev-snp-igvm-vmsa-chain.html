Cloud Hypervisor SEV-SNP IGVM / VMSA / isolated page 链路

本文分析 SEV-SNP 如何通过 MSHV、IGVM、VMSA 和 isolated page import 启动 guest。

源码基线：当前仓库工作树。

相关：CoCo TDX/SEV-SNP、TDX TDVF/HOB。

0. 术语与背景

SEV-SNP 启动链

Vm::hypervisor_specific_init → init_sev_snp：IGVM 加载（PageData/ParameterArea/VMSA）→ import_isolated_pages（isolated page import）→ complete import → SEV control register → page access proxy → device DMA 经 AccessPlatform。

关键概念

  • IGVM：Independent Guest Virtual Machine 格式——包含 guest firmware + memory layout + VMSA。
  • VMSA：VM Save Area——SEV-SNP vCPU 初始状态（寄存器/seg/CPUID）。
  • isolated page import：把加密页导入 guest——host 无法直接读取，经 MSHV SNP 接口。
  • page access proxy：设备 DMA 经 proxy 访问加密 guest memory。

1. IGVM 加载 + VMSA

// vmm/src/igvm/igvm_loader.rs:340  VMSA page
gpas.push(GpaPages { gpa, page_type: HV_ISOLATED_PAGE_TYPE_VMSA, page_size: HV_ISOLATED_PAGE_SIZE_4KB });
// :469  isolated page import
.import_isolated_pages(group[0].page_type, HV_ISOLATED_PAGE_SIZE_4KB, &pfns)?;

IGVM loader 解析 IGVM 文件 → 按 page type 分类（VMSA/normal/data/secrets）→ import_isolated_pages 逐组导入加密页 → VMSA 经 MSHV SNP 接口设置 vCPU 初始状态。

2. 能力边界

SEV-SNP guest memory 加密——host 无法直接读取。设备 DMA 经 AccessPlatform + SevSnpPageAccessProxy（proxy 负责解密/重加密）。snapshot/migration 类似 TDX 受限（加密内存无法直接序列化）。详见 CoCo TDX/SEV-SNP。
