Cloud Hypervisor ARM64 与 x86_64 架构差异链路

本文解释 CH 在 ARM64 与 x86_64 上的差异：VM boot、vCPU、系统描述、中断控制器、legacy device、ACPI/FDT、CoCo。

源码基线：当前仓库工作树。

相关：cpu-boot、VM create/boot、device-manager。

0. 术语与背景

共享上层框架，分叉在机器描述/vCPU init/中断注入/固件入口

Vm::boot()/CpuManager/DeviceManager/virtio 设备模型两架构共享。差异分布在 arch crate、CpuManager configure、DeviceManager ACPI/FDT、payload loader。

维度 x86_64（PC 平台） ARM64（virt 平台）
CPU 身份 CPUID/x2APIC/topology MPIDR/GICv3 or GICv2M/ITS
vCPU init CPUID/topology/Hyper-V/nested preferred target + processor features + vcpu_init
中断控制器 IOAPIC（MMIO bus 设备）+ local APIC GIC（Gic 对象，不插 device tree）+ GICR
机器描述 ACPI（DSDT/FADT/MADT/MCFG）+ boot params + mptable FDT（CPU/cache/GIC/timer/PSCI/devices）+ 可选 ACPI
固件 PVH/bzImage UEFI flash + direct kernel boot
restore CPUID/TSC/clock GICR_TYPER + MPIDR + vGIC state

1. vCPU configure 架构分叉

// vmm/src/cpu.rs:590  aarch64 init
pub fn init(&self, vm: &dyn hypervisor::Vm) -> Result<()> {
    let mut kvi = self.vcpu.create_vcpu_init();
    vm.get_preferred_target(&mut kvi)?;                // 读内核 preferred target
    self.vcpu.vcpu_set_processor_features(vm, &mut kvi, self.id)?;
    self.vcpu.vcpu_init(&kvi)?;                         // vcpu_init
}
// :1066  x86_64 configure
vcpu.configure(boot_setup, self.cpuid.clone(), self.config.kvm_hyperv, topology, self.config.nested)?;

aarch64 必须先 init(vm) + preferred target + processor features 再 vcpu_init；x86_64 用 CPUID + topology + Hyper-V + nested 一次 configure。

2. ARM64 GIC redistributor + snapshot

// vmm/src/cpu.rs:635  aarch64 set_gic_redistributor_addr
pub fn set_gic_redistributor_addr(&self, base_redist_addr, redist_size) -> Result<()> {
    let gicr_base = base_redist_addr + (arch::layout::GIC_V3_REDIST_SIZE * self.id as u64);
    self.vcpu.set_gic_redistributor_addr(gicr_base)?;
}
// :1700  aarch64 get_mpidrs/get_saved_states（restore 依赖）
pub fn get_mpidrs(&self) -> Vec<u64> { self.vcpus.iter().map(|c| c.lock().unwrap().get_mpidr()).collect() }
pub fn get_saved_states(&self) -> Vec<CpuState> { self.vcpus.iter().map(|c| c.lock().unwrap().get_saved_state().unwrap()).collect() }

ARM64 restore 依赖 get_saved_states → set_gicr_typers → restore_vgic——GIC/ITS restore 是 VM 级硬约束。x86_64 restore 关注 CPUID/TSC/clock。CoCo（TDX/SEV-SNP）feature 差异在 PlatformConfig + hypervisor VM type，见 CoCo TDX/SEV-SNP（历史/暂缓）。
