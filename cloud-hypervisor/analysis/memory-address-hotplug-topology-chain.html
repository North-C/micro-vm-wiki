Cloud Hypervisor Memory Address / Hotplug Topology 链路

本文补齐 MemoryManager 的地址空间与热插拔拓扑：guest RAM 如何分成 zones/regions、何时注册 hypervisor slot、ACPI hotplug vs virtio-mem vs zone resize 的边界。

源码基线：当前仓库工作树。

相关：MemoryManager 内存链路、VM create/boot。

0. 术语与背景

MemoryManager 不只是 GuestMemoryMmap 持有者

同时维护 guest RAM 拓扑、hypervisor memory slot、RAM allocator、device area、hotplug slot、memory zone、restore/migration 索引。

guest_ram_mappings 是内存拓扑的关键索引

每条记录保存 slot/GPA/size/zone id/是否 virtio-mem/file offset——后续 restore、dirty log、slot fd 查询都依赖它。

三种 resize 语义

resize 类型 做什么
全局 ACPI resize 新增 RAM region + ACPI 通知
全局 virtio-mem resize 只改 virtio-mem plugged size（不改 region 数量）
zone resize 只允许 user-defined zones

2. create_userspace_mapping（真正让 hypervisor 看见 guest RAM）

创建 mmap region 本身只是 VMM 进程内 host virtual memory——create_userspace_mapping() 调 vm.create_user_memory_region(slot, gpa, size, userspace_addr, readonly, log_dirty) 才真正注册到 hypervisor。

3. 能力边界 / ARM64 差异

ARM64 会额外在地址 0 映射 UEFI flash（add_uefi_flash）；x86_64 allocator 初始化 GSI/APIC IRQ 范围。userspace mapping 逻辑两架构共享。详见 MemoryManager 内存链路。
