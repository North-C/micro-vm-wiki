Cloud Hypervisor MemoryManager 内存链路函数级分析

本文展开 Vm::new → MemoryManager::new/new_from_snapshot → allocate_address_space → create_userspace_mapping → resize → snapshot/send → dirty_log 链路。

源码基线：当前仓库工作树。

相关：VM create/boot、migration memory transport。

0. 术语与背景

MemoryManager 是内存聚合根

不只保存 GuestMemoryMmap——还记住每个 RAM mapping 的 slot/GPA/size/zone/virtio-mem/file offset（服务 restore + dirty log）、hotplug slots、RAM allocator、dirty log 状态。

关键概念

  • boot_guest_memory vs guest_memory：前者是启动时内存视图（payload loader + 系统配置用），后者是 GuestMemoryAtomic（热插拔/跨组件共享）。
  • hotplug method：VirtioMem（desired>=boot_ram，走 virtio_mem_resize）或 Acpi（新增 RAM region + ACPI 通知）。
  • dirty log：合并 hypervisor dirty bitmap + VMM GuestMemoryMmap atomic bitmap（只看 KVM 会漏 VMM 经 host mapping 写的 guest RAM）。

1. MemoryManager 结构

    vm: Arc<dyn hypervisor::Vm>,

    hotplug_method: HotplugMethod, boot_ram: u64, current_ram: u64,
    shared: bool, hugepages: bool, log_dirty: bool, dynamic: bool,
    snapshot_memory_ranges: MemoryRangeTable, memory_zones: MemoryZones,
    guest_ram_mappings: Vec<GuestRamMapping>,  // slot/GPA/size/zone/virtio-mem/file offset
    ram_allocator: AddressAllocator,
}

2. create_userspace_mapping（hypervisor memory slot）

// vmm/src/memory_manager.rs:2191
pub unsafe fn create_userspace_mapping(&mut self, guest_phys_addr, memory_size, userspace_addr, mergeable, readonly, log_dirty) -> Result<u32, Error> {
    let slot = self.allocate_memory_slot();
    self.vm.create_user_memory_region(slot, guest_phys_addr, memory_size, userspace_addr, readonly, log_dirty)?;
    Ok(slot)
}

allocate_address_space() 遍历 memory zone + virtio-mem region，每 region 调 create_userspace_mapping 写 slot/GPA/size/zone id/virtio-mem 入 GuestRamMapping。

3. resize（hotplug）

// vmm/src/memory_manager.rs:2362
pub fn resize(&mut self, desired_ram: u64) -> Result<Option<Arc<GuestRegionMmap>>, Error> {
    if self.user_provided_zones { return Err(Error::InvalidResizeWithMemoryZones); }   // 拒绝 user-defined zones
    match self.hotplug_method {
        HotplugMethod::VirtioMem => { if desired_ram >= self.boot_ram { self.virtio_mem_resize(DEFAULT_MEMORY_ZONE, desired_ram - self.boot_ram)?; self.current_ram = desired_ram; } }
        HotplugMethod::Acpi => { if desired_ram > self.current_ram { region = Some(self.hotplug_ram_region((desired_ram - self.current_ram) as usize)?); self.current_ram = desired_ram; } }
    }
    Ok(region)
}

4. dirty log（hypervisor + VMM bitmap OR）

// vmm/src/memory_manager.rs:3056
fn start_dirty_log(&mut self) -> Result<(), MigratableError> {
    self.vm.start_dirty_log()?;
    for r in self.guest_memory.memory().iter() { (**r).bitmap().reset(); }   // 重置 VMM atomic bitmap
}
fn dirty_log(&mut self) -> Result<MemoryRangeTable, MigratableError> {
    for r in &self.guest_ram_mappings {
        let vm_dirty_bitmap = self.vm.get_dirty_log(r.slot, r.gpa, r.size)?;    // hypervisor bitmap
        let vmm_dirty_bitmap = region.bitmap().get_and_reset();                   // VMM bitmap
        let dirty_bitmap = vm_dirty_bitmap.iter().zip(vmm_dirty_bitmap.iter()).map(|(x, y)| x | y);  // 逐位 OR
        table.extend(MemoryRangeTable::from_dirty_bitmap(dirty_bitmap, r.gpa, 4096));
    }
}

migration dirty log 必须同时跟踪 guest CPU 写入 + VMM 侧设备模拟写入——只看 KVM dirty log 会漏掉 VMM 经 host mapping 修改的 guest RAM。Vm::dirty_log() 还合并 device_manager.dirty_log()（vhost-user/设备 backend 可能提供额外 dirty memory）。
