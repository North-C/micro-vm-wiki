Cloud Hypervisor DeviceManager 设备链路函数级分析

本文展开 Vm::create_device_manager → DeviceManager::new → create_interrupt_controller → create_devices → make_virtio_devices → add_pci_devices → ACPI/FDT → snapshot/migration 链路。

源码基线：当前仓库工作树。

相关：VM create/boot、I/O 设备数据面、设备创建矩阵。

0. 术语与背景

DeviceManager 是设备聚合点

把配置里的设备变成 guest 可见设备，接入中断/PCI/MMIO/ACPI-FDT/热插拔/迁移聚合。先建中断控制器（MSI manager → IOAPIC/GIC → legacy manager 线性依赖链），再 legacy/ACPI/console，最后 virtio → PCI。

关键边界

  • 中断控制器先于设备创建（设备依赖 MSI manager；IOAPIC/GIC 自身也用 MSI）。
  • x86_64 controller = IOAPIC（MMIO bus device）；aarch64 = GIC（不插 device tree）。
  • 设备经 add_virtio_pci_device 统一包成 VirtioPciDevice（MSI-X vector = queue 数+1，注册 ioeventfd）。

1. DeviceManager new 关键顺序

// vmm/src/device_manager.rs:1248  依赖链：msi_interrupt_manager <- IOAPIC <- legacy_interrupt_manager
let msi_interrupt_manager = Arc::new(MsiInterruptManager::new(Arc::clone(&address_manager.allocator), vm));
// :1431  CPU manager set_interrupt_controller → legacy manager → legacy devices → ACPI/GED → console
self.cpu_manager.lock().unwrap().set_interrupt_controller(interrupt_controller.clone());
let legacy_interrupt_manager = Arc::new(LegacyUserspaceInterruptManager::new(Arc::clone(&interrupt_controller)));
#[cfg(target_arch = "x86_64")] self.add_legacy_devices(self.reset_evt.try_clone()?)?;   // x86 legacy（i8042 等）
#[cfg(target_arch = "aarch64")] self.add_legacy_devices(legacy_interrupt_manager.as_ref())?;  // ARM64 legacy（PL011/RTC/MMIO）
self.ged_notification_device = self.add_acpi_devices(legacy_interrupt_manager.as_ref(), /* reset_evt, exit_evt */)?;

2. create_devices 顺序

create_devices() 先 add_interrupt_controller() → legacy → ACPI/GED → serial/console → make_virtio_devices（block/net/rng/vhost-user/fs/pmem/vsock/mem/balloon/watchdog/vDPA）→ add_pci_devices（统一 VirtioPciDevice + PCI hotplug）。

设备创建是 MetaVirtioDevice 列表收集 → 统一 PCI 包装。runtime hotplug 与启动期创建共享 add_virtio_pci_device，但 hotplug 额外通知 guest ACPI/GED。详见 I/O 设备数据面 §3-4。

3. snapshot/migration 聚合

DeviceManager 的 device_tree 是 snapshot/restore 依赖来源（virtio device node/virtio-pci parent/BDF/BAR resources）。Migratable dirty log 聚合 memory + device manager（vhost-user/设备 backend 可能提供额外 dirty memory）。详见 CPU 运行期/热插拔/迁移 §10-11。
