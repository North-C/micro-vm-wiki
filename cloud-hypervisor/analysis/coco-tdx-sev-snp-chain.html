Cloud Hypervisor CoCo：TDX 与 SEV-SNP 函数级链路

本文解释 tdx/sev_snp 配置如何改变 VM 类型、CPUID、payload、vCPU、内存、设备 DMA 和生命周期边界。

源码基线：当前仓库工作树。

相关：arch ARM64/x86_64、TDX lifecycle 限制、横向 CoCo/pVM。

0. 术语与背景

两种 CoCo 后端

后端 VM type firmware 限制
TDX KVM protected VM（KVM_CREATE_VM + TDX type） TDVF firmware + HOB CPU/Memory dynamic=false；snapshot/migration/coredump 拒绝
SEV-SNP MSHV SNP VM IGVM（PageData/ParameterArea/VMSA）+ isolated page import page access proxy；设备 DMA 经 AccessPlatform

TDX 和 SEV-SNP 都是威胁 ③（恶意 host 窥探 guest）的主防线——guest 内存加密，host 无法直接读取。

1. PlatformConfig 配置

// vmm/src/config.rs:3525
#[cfg(feature = "tdx")]
pub fn is_tdx_enabled(&self) -> bool { self.platform.as_ref().is_some_and(|p| p.tdx) }
#[cfg(feature = "sev_snp")]
pub fn is_sev_snp_enabled(&self) -> bool { self.platform.as_ref().is_some_and(|p| p.sev_snp) }
// vmm/src/vm.rs:1276  Vm::new 判断
let tdx_enabled = if snapshot.is_some() { false } else { vm_config.lock().unwrap().is_tdx_enabled() };

snapshot restore 时 tdx_enabled 强制 false——TDX VM 不支持从普通 snapshot restore。

2. TDX 路径（KVM protected VM + TDVF）

Vm::new 创建 KVM VM 时根据 tdx_enabled 选择 protected VM type。hypervisor_specific_init 中 TDX 走 init_tdx_if_enabled：TDVF firmware 解析（TdvfSectionType: BFV/CFV/Payload/PayloadParam/TempMem）→ TD HOB（memory/MMIO/ACPI/payload）→ vCPU init + measurement。详见 TDX TDVF/HOB。

3. SEV-SNP 路径（MSHV + IGVM + VMSA）

hypervisor_specific_init 中 SEV-SNP 走 init_sev_snp：IGVM 加载（PageData/ParameterArea/VMSA）→ import_isolated_pages → complete import → SEV control register → page access proxy。

// vmm/src/igvm/igvm_loader.rs:340  VMSA page
gpas.push(GpaPages { gpa, page_type: HV_ISOLATED_PAGE_TYPE_VMSA, page_size: HV_ISOLATED_PAGE_SIZE_4KB });
// :469  isolated page import
.import_isolated_pages(group[0].page_type, HV_ISOLATED_PAGE_SIZE_4KB, &pfns)?;

4. 能力边界

TDX：CPU hotplug 拒绝（max_vcpus==boot_vcpus）、memory dynamic=false、snapshot/migration/coredump 全拒绝（详见 TDX lifecycle 限制）。SEV-SNP：设备 DMA 经 AccessPlatform + SevSnpPageAccessProxy，guest memory 加密。两者都改变了威胁模型（威胁 ③），代价是失去热插拔/迁移/snapshot 等运行期能力。
