Cloud Hypervisor CPU 启动链路函数级分析

本文展开 Vm::new_from_memory_manager → CpuManager → boot vCPU → Vcpu::configure → configure_system → start_boot_vcpus 链路：vCPU 何时创建、何时配置、何时开始运行。

源码基线：当前仓库工作树。

相关：VM create/boot、arch ARM64/x86_64、CPU 运行期/热插拔/迁移。

0. 术语与背景

vCPU 三个阶段

阶段 做什么 入口
创建 create_vcpus 建空 vCPU 对象 + arch init hypervisor_specific_init
配置 configure_vcpu 写 CPUID/MPIDR/topology/boot entry Vm::boot
启动 start_boot_vcpus → activate_vcpus 起 vCPU 线程 Vm::boot 末尾

创建 ≠ 配置 ≠ 启动——三个阶段分开。vCPU 在 hypervisor_specific_init 创建，在 Vm::boot 配置 + 启动。

1. CpuManager::new（预分配 vcpu_states）

// vmm/src/cpu.rs:884
pub fn new(config, vm, exit_evt, reset_evt, hypervisor, seccomp_action, vm_ops, numa_nodes) -> Result<Arc<Mutex<CpuManager>>> {
    if config.max_vcpus > hypervisor.get_max_vcpus() { return Err(Error::MaximumVcpusExceeded); }
    let mut vcpu_states = Vec::with_capacity(max_vcpus);   // 预分配 max_vcpus 个 VcpuState
    vcpu_states.resize_with(max_vcpus, VcpuState::default);
    // ... affinity/NUMA/dynamic/core scheduling 初始化 ...
}

2. create_boot_vcpus → start_boot_vcpus

// vmm/src/cpu.rs:1552
pub fn create_boot_vcpus(&mut self, snapshot: Option<&Snapshot>) -> Result<Vec<Arc<Mutex<Vcpu>>>> {
    self.create_vcpus(self.boot_vcpus(), snapshot)   // 建 boot_vcpus 个 vCPU（有 snapshot 则从 snapshot restore）
}
// :1561
pub fn start_boot_vcpus(&mut self, paused: bool) -> Result<()> {
    self.activate_vcpus(self.boot_vcpus(), false, Some(paused))   // 起 vCPU 线程（Vm::boot 末尾调，paused=false）
}

Vm::boot() 在 configure_vcpu + configure_system 后调 start_boot_vcpus(false)（非 paused）——vCPU 线程进入 KVM_RUN 循环。create_vcpus 内部按架构计算 vCPU id（x86 用 topology 算 x2APIC id，ARM64 直接用 cpu id）+ configure_vcpu 按 arch 分叉（见 arch ARM64/x86_64 §1）。
