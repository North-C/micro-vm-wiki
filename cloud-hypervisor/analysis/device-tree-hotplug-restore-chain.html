Cloud Hypervisor DeviceTree / 热插拔 / Restore 链路

本文展开 DeviceTree 为什么是设备拓扑/热插拔/snapshot/restore 的共同骨架。

源码基线：当前仓库工作树。

相关：DeviceManager 设备链路、snapshot/restore 状态恢复。

0. 术语与背景

DeviceTree 是拓扑 + 资源 + 父子关系 + 可迁移引用

不是查询结构——它保存设备 id/resources/parent-children/PCI BDF/PCI handle/migratable 引用，是 restore 和热删除的关键索引。migratable 与 pci_device_handle 被 serde(skip)——restore 必须重新创建运行时对象并把 handle 接回 tree。

热插拔不是完整事务

插入成功 → Vm 更新 config → GED 通知；通知失败无反向 remove 或 config 回滚。

热删除两阶段

API remove 先标记 PCI down bitmap + 通知 guest；guest ACPI eject 后 eject_device() 才真正从 tree/PCI bus/IO-MMIO bus/DMA mapping/virtio_devices 移除对象。

1. add_virtio_pci_device（parent-child + 资源）

// vmm/src/device_manager.rs:4191
fn add_virtio_pci_device(&mut self, virtio_device, iommu_mapping, virtio_device_id, pci_segment_id, dma_handler) -> Result<PciBdf> {
    let id = format!("{VIRTIO_PCI_DEVICE_NAME_PREFIX}-{virtio_device_id}");
    let mut node = device_node!(id);
    node.children = vec![virtio_device_id.to_string()];          // virtio-pci parent → virtio device child
    let (pci_segment_id, pci_device_bdf, resources) = self.pci_resources(&id, pci_segment_id)?;  // 分配 BDF/BAR
    if let Some(node) = self.device_tree.lock().unwrap().get_mut(virtio_device_id) {
        node.parent = Some(id.clone());                           // virtio device → virtio-pci parent
    }
    // ... VirtioPciDevice::new + add_pci_device + ioeventfd 注册 + device tree update ...
}

2. restore_devices（遍历 + pause + restore）

restore 按 DeviceTree children→parent 反序遍历（组内并发组间等待），每个 migratable 设备 pause() + restore(snapshot)（详见 VMM device restore §7）。vfio-user 设备 restore 后还需 dma_map(new_region) 更新 guest memory。

ARM64/x86_64 共用 PCI virtio 设备管理路径。差异在 interrupt controller/legacy 设备总线/PCI config 访问/FDT-ACPI 描述/GIC-IOAPIC restore。
