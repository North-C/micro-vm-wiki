    Cloud Hypervisor ACPI / FDT 机器描述生成链路

    本文聚焦 CH 如何把 Vm/CpuManager/MemoryManager/DeviceManager 的状态变成 guest 可见的机器描述。

    源码基线：当前仓库工作树。

    相关：VM create/boot、arch ARM64/x86_64。

    0. 术语与背景

    两张机器描述面

    面 架构 承载
    ACPI x86_64 + aarch64（可选） CPU/PCI/memory hotplug/NUMA/IOMMU/TPM/power button/串口
    FDT 仅 aarch64 direct kernel boot CPU MPIDR/memory/chosen/GIC/timer/PMU/PSCI/MMIO device/PCI host bridge/NUMA

    CH 不维护独立"硬件说明书"——boot 阶段从 manager 状态生成 ACPI/FDT，运行期用 GED 把热插拔事件重新导入 guest。

    1. ACPI 生成

    // vmm/src/acpi.rs:853  create_acpi_tables_internal
fn create_acpi_tables_internal(dsdt_addr, device_manager, cpu_manager, memory_manager, numa_nodes, tpm_enabled) -> (Rsdp, Vec<u8>, Vec<u64>) {
    let dsdt = create_dsdt_table(device_manager, cpu_manager, memory_manager);  // DSDT（设备描述）
    let facp = create_facp_table(dsdt_addr, device_manager);                     // FADT（固定 ACPI）
    // MADT（中断控制器：x86 IOAPIC/LAPIC，aarch64 GIC）
    // MCFG（PCI ECAM）+ SRAT/SLIT（NUMA）+ VIOT（IOMMU）
}

    x86_64 在 Vm::boot 早期创建 ACPI（与 kernel load 并行）；aarch64 在 vCPU 配置后创建（依赖 MPIDR）。

    2. FDT 生成（aarch64）

    // arch/src/aarch64/fdt.rs:208  create_fdt
pub fn create_fdt(guest_mem, cmdline, vcpu_mpidr, vcpu_topology, device_info, gic_device, initrd, pci_space_info, numa_nodes) -> Result<FdtWriter> {
    fdt.property_u32("interrupt-parent", GIC_PHANDLE)?;   // 指向 GIC
    create_cpu_nodes(&mut fdt, vcpu_mpidr, vcpu_topology, numa_nodes)?;   // CPU（MPIDR 填 reg）
    create_memory_node(&mut fdt, guest_mem, numa_nodes)?;
    create_chosen_node(&mut fdt, cmdline, initrd)?;        // cmdline + initrd 也进 FDT
    create_gic_node(&mut fdt, gic_device)?;                // GIC
    create_timer_node(&mut fdt)?; create_psci_node(/*...*/)?;
    create_devices_node(/*...*/)?;                         // virtio-mmio 设备
    create_pci_nodes(/*...*/)?;                            // PCI host bridge
}

    aarch64 FDT 和 ACPI 可共存——FDT 描述 boot/initrd/GIC/timer/PSCI，ACPI 描述 CPU/memory hotplug/PCI。CH 在 aarch64 同时生成两者，guest kernel 按配置选择。

    3. GED 热插拔

    运行期 notify_hotplug 经 GED（Generic Event Device）通知 guest——guest ACPI driver 读 GED 事件类型（CPU_DEVICES_CHANGED/MEMORY_DEVICES_CHANGED/PCI_DEVICES_CHANGED），重新扫描 ACPI 描述完成热插拔协议。

    4. 能力边界

    机器描述是 boot 期生成物——CH 不像 Firecracker 刻意收窄设备面（CH 支持运行期 add/remove 设备 + GED 通知）。NUMA/IOMMU/TPM/VMGenID/VMClock 在 ACPI/FDT 中都有对应 node。
