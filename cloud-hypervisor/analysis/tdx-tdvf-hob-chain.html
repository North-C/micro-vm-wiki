Cloud Hypervisor TDX TDVF / HOB 启动链路

本文分析 TDX guest 启动时 CH 如何解析 TDVF metadata、处理 TdvfSectionType、生成 TD HOB，并把 HOB 地址交给 KVM TDX vCPU。

源码基线：当前仓库工作树。

相关：CoCo TDX/SEV-SNP、TDX lifecycle 限制。

0. 术语与背景

TDVF（Trust Domain Virtual Firmware）

TDX guest 的固件——类似 UEFI firmware，但在 TD（Trust Domain）内运行。CH 解析 TDVF metadata → 按 section type 处理 → 生成 TD HOB（Hand-Off Block）→ vCPU init + measurement。

TdvfSectionType

section type 含义
BFV Boot Firmware Volume（TDVF 自身）
CFV Configuration Firmware Volume（可变配置）
Payload guest OS / kernel
PayloadParam payload 参数（cmdline）
TempMem 临时内存

TD HOB

Hand-Off Block——把 memory layout / MMIO / ACPI / payload 信息传给 TDVF。类似 UEFI HOB 但在 TDX 上下文。

1. 启动链路

Vm::boot → extract_tdvf_sections → parse_tdvf_sections（按 TdvfSectionType 分类）→ populate_tdx_sections（BFV/CFV/Payload/PayloadParam 写入 guest memory）→ 生成 TD HOB（memory/MMIO/ACPI/payload）→ vCPU init + measurement（TDX measurement 约束 guest launch integrity）。

// TdvfSectionType 分类（TDVF metadata 解析后按类型处理）
// BFV:   Boot Firmware Volume — TDVF 自身，写入 guest memory 作为 entry
// CFV:   Configuration Firmware Volume — 可变配置区
// Payload: guest OS / kernel image
// PayloadParam: payload 参数（cmdline）
// TempMem: 临时内存（启动后回收）

TDVF firmware 在 TD 内运行（加密内存），CH 只负责解析 metadata + 准备 HOB + 触发 measurement。guest OS 经 TDVF 引导。

2. 能力边界

TDVF 必须创建时加载（不支持运行期 firmware 更换）。HOB 内容包含 memory/MMIO/ACPI/payload——guest launch 后不可修改。measurement 约束 guest launch integrity（host 无法篡改 guest firmware/payload 而不被发现）。
