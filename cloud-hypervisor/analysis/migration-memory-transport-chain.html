    Cloud Hypervisor Migration Memory Transport 链路

    本文展开 MemoryManager 内存链路，聚焦 guest RAM 如何纳入 snapshot/transport/restore 和 live migration dirty log。

    源码基线：当前仓库工作树。

    相关：横向 Snapshot/Restore/Clone、CubeSandbox 派生参考 Snapshot/Restore 状态恢复。

    0. 术语与背景

    memory metadata 与 memory bytes 分离

    CH 把 memory snapshot 拆两层：Snapshot（Snapshottable::snapshot()）保存 metadata（如何重建拓扑）；Transportable::send() 另写真实内存字节到 memory-ranges。state.json 不直接承载 guest RAM 内容。

    vm-migration 三层 trait

    trait 职责
    Snapshottable snapshot() 返回 Snapshot（metadata）
    Transportable send() 把自定义状态写到目标 URL（真实字节）
    Migratable 继承前两者 + start_dirty_log/dirty_log/start_migration/complete_migration

    memory snapshot 不能只看 snapshot()——真实字节在 send() 阶段写出。

    两种 restore 模式

    模式 行为 UFFD handler
    Copy（默认） 恢复阶段把 memory-ranges 全量写回 guest memory 不需要
    OnDemand 注册 UFFD，VMM 内部 handler 线程按 page fault 从文件填页 VMM 内 uffd-handler 线程

    与 Firecracker UFFD 的关键差异：Firecracker 把 UFFD fd + mapping 发给外部 handler（Firecracker 保留 fd）；CH 不交给外部进程，在 VMM 进程内起 handler 线程直接读 memory-ranges。故障边界不同（外部 handler 退出 → fault 无人服务；CH handler panic → 写 exit event + result channel 暴露错误）。

    dirty log 不是只看 hypervisor

    dirty_log() 合并 hypervisor dirty bitmap + VMM 侧 GuestMemoryMmap atomic bitmap——只看 KVM dirty log 会漏掉 VMM 经 host mapping 修改的 guest RAM。

    1. 核心结论

    • memory snapshot 两层：Snapshot 存 metadata（MemoryRangeTable），send() 写字节。
    • restore 两模式：默认 Copy 全量写回；OnDemand 注册 UFFD 由 VMM 内部 handler 按需填页。
    • live migration dirty log 合并 hypervisor + VMM atomic bitmap。
    • 与 Firecracker 不同：CH 在 VMM 进程内启 uffd-handler 线程，不交外部。

    2. 总体流程图

    flowchart TD Pause["VM paused / migration phase"] --> Snap["MemoryManager::snapshot"] Snap --> Range["memory_range_table(true)"] Range --> Data["MemoryManagerSnapshotData"] Data --> VmSend["Vm::send"] VmSend --> State["state.json + config.json"] VmSend --> MemSend["MemoryManager::send"] MemSend --> File["memory-ranges"] File --> Restore["MemoryManager::new_from_snapshot"] Restore --> Mode{"MemoryRestoreMode"} Mode -->|Copy| Copy["fill_saved_regions"] Mode -->|OnDemand| UFFD["restore_by_uffd"] UFFD --> Handler["VMM uffd-handler thread"]

    3. MemoryManagerSnapshotData 保存什么

    // vmm/src/memory_manager.rs:2970
pub struct MemoryManagerSnapshotData {
    memory_ranges: MemoryRangeTable,        // 哪些 guest RAM 要写入 memory-ranges
    guest_ram_mappings: Vec<GuestRamMapping>,  // slot/GPA/size/zone id/virtio-mem/file offset
    start_of_device_area: u64, boot_ram: u64, current_ram: u64,
    arch_mem_regions: Vec<ArchMemRegion>,
    hotplug_slots: Vec<HotPlugState>,
    next_memory_slot: u32, selected_slot: usize, next_hotplug_slot: u32,
}

    保存的是"如何重建 memory topology"，不是直接保存 guest RAM 字节。guest_ram_mappings 还服务 dirty log——后续 dirty_log() 用 slot/GPA/size 向 hypervisor 查 dirty bitmap。

    4. memory_range_table + snapshot 只生成 Range Table

    memory_range_table() 遍历 memory zone，virtio-mem 加 plugged ranges，普通 region 加完整 GPA range；MAP_SHARED + host hardlink backing file 时跳过复制（共享 backing file 由用户经原文件保存）：

    // vmm/src/memory_manager.rs:2431
pub fn memory_range_table(&self, snapshot: bool) -> Result<MemoryRangeTable, MigratableError> {
    let mut table = MemoryRangeTable::default();
    for memory_zone in self.memory_zones.values() {
        if let Some(virtio_mem_zone) = memory_zone.virtio_mem_zone() {
            table.extend(virtio_mem_zone.plugged_ranges());     // virtio-mem plugged ranges
        }
        for region in memory_zone.regions() {
            if snapshot && region MAP_SHARED && Self::is_hardlink(file) { continue; }  // 跳过共享 hardlink
            table.push(MemoryRange { gpa: region.start_addr().raw_value(), length: region.len() });
        }
    }
    Ok(table)
}

    MemoryManager::snapshot() 调 memory_range_table(true) 存入 snapshot_memory_ranges 再序列化——snapshot 结束时内存字节还没写出，只固化需复制的范围：

    // vmm/src/memory_manager.rs:2988
fn snapshot(&mut self) -> Result<Snapshot, MigratableError> {
    let memory_ranges = self.memory_range_table(true)?;
    // 注释：存本地 range table 让 send 复用，避免 send 重复决定哪些 region 要复制
    self.snapshot_memory_ranges = memory_ranges;
    Ok(Snapshot::from_data(SnapshotData::new_from_state(&self.snapshot_data())?))
}

    5. Vm::send 写三类文件

    Vm::send() 写 config.json（VM 配置）→ state.json（组件 snapshot tree）→ 找 memory manager snapshot 调 MemoryManager::send()：

    // vmm/src/vm.rs:3223
impl Transportable for Vm {
    fn send(&self, snapshot: &Snapshot, destination_url: &str) -> Result<(), MigratableError> {
        // 写 config.json + state.json
        if let Some(memory_manager_snapshot) = snapshot.snapshots.get(MEMORY_MANAGER_SNAPSHOT_ID) {
            self.memory_manager.lock().unwrap().send(&memory_manager_snapshot.clone(), destination_url)?;
        } else {
            return Err(MigratableError::Restore(anyhow!("Missing memory manager snapshot")));  // memory transport 是 VM snapshot 必需部分
        }
    }
}

    6. MemoryManager::send 写 memory-ranges

    // vmm/src/memory_manager.rs:3007
fn send(&self, _snapshot: &Snapshot, destination_url: &str) -> Result<(), MigratableError> {
    if self.snapshot_memory_ranges.is_empty() { return Ok(()); }      // range table 空 → 直接返回
    let mut memory_file = OpenOptions::new().read(true).write(true).create_new(true).open(memory_file_path)?;
    let guest_memory = self.guest_memory.memory();
    for range in self.snapshot_memory_ranges.regions() {
        // 从 GuestMemoryMmap 的 GPA 读内容，顺序写入 memory-ranges
        guest_memory.write_volatile_to(GuestAddress(range.gpa + offset), &mut memory_file, (range.length - offset))?;
    }
}

    restore 时需要 range table：文件里只是一段段连续内存内容，range table 才能把文件 offset 映射回 guest GPA。

    8. new_from_snapshot + Copy Restore

    new_from_snapshot() 先重建 topology 再按 mode 恢复内容：

    // vmm/src/memory_manager.rs:1663
pub fn new_from_snapshot(snapshot, vm, config, source_url, prefault, memory_restore_mode, /*...*/) -> Result<Arc<Mutex<MemoryManager>>, Error> {
    let mem_snapshot: MemoryManagerSnapshotData = snapshot.to_state()?;
    let mm = MemoryManager::new(vm, config, Some(prefault), phys_bits, /*...*/, Some(&mem_snapshot), /*...*/)?;  // 重建 topology
    if memory_restore_mode == MemoryRestoreMode::OnDemand {
        mm.lock().unwrap().restore_by_uffd(&memory_file_path, &mem_snapshot.memory_ranges, exit_evt)?;
    } else {
        mm.lock().unwrap().fill_saved_regions(memory_file_path, &mem_snapshot.memory_ranges)?;   // Copy
    }
}

    fill_saved_regions() 打开 memory-ranges，遍历 saved_regions 从文件读字节写入对应 guest memory 地址：

    // vmm/src/memory_manager.rs:785
fn fill_saved_regions(&mut self, file_path, saved_regions) -> Result<(), Error> {
    let mut memory_file = OpenOptions::new().read(true).open(file_path)?;
    let guest_memory = self.guest_memory.memory();
    for range in saved_regions.regions() {
        // 函数名易误导：从 snapshot 文件读字节，写入对应 guest memory 地址
        guest_memory.read_volatile_from(GuestAddress(range.gpa + offset), &mut memory_file, (range.length - offset))?;
    }
}

    Copy restore 特点：恢复完成前尽量把所有 saved ranges 填入 guest RAM（启动时延较高，但恢复后不依赖 UFFD handler）。

    9. OnDemand UFFD Restore

    // vmm/src/memory_manager.rs:844
fn restore_by_uffd(&mut self, file_path, saved_regions, exit_evt) -> Result<(), Error> {
    if saved_regions.is_empty() { return Ok(()); }
    // 要求 GPA/长度按基础页对齐
    if saved_regions.regions().iter().any(|r| r.gpa % base_page_size != 0 || r.length % base_page_size != 0) {
        return Err(UffdError::UnalignedRanges.into());
    }
    let snapshot_file = File::open(file_path)?;
    let uffd_fd = uffd::create(required_uffd_features)?;
    for range in saved_regions.regions() {
        let host_addr = guest_memory.get_host_address(GuestAddress(range.gpa))? as u64;
        uffd::register(uffd_fd.as_fd(), host_addr, range.length)?;     // 每 range 注册 UFFD
        handler_ranges.push(UffdRange { host_addr, length: range.length, file_offset, page_size });  // file_offset 递增对应 send 顺序
    }
    // spawn uffd-handler 线程（VMM 内部）
}

    uffd_handler_loop() 用 epoll 同时监听 stop event + UFFD fd，收到 page fault 对齐到 page 算 file_pos = range.file_offset + offset_in_range，从 memory-ranges seek/read 一页 + UFFDIO_COPY（EEXIST→UFFDIO_WAKE，EAGAIN→让出重试，:1016）。

    关键：CH UFFD handler 在 VMM 进程内（uffd-handler 线程），不交外部。VM 关闭/manager drop 时 stop_uffd_handler() 写 stop event + join。

    10. Dirty Log（合并 hypervisor + VMM bitmap）

    // vmm/src/memory_manager.rs:3056
impl Migratable for MemoryManager {
    fn start_dirty_log(&mut self) -> Result<(), MigratableError> {
        self.vm.start_dirty_log()?;                          // 启 hypervisor dirty log
        for r in self.guest_memory.memory().iter() { (**r).bitmap().reset(); }  // 重置 VMM atomic bitmap
    }
    fn dirty_log(&mut self) -> Result<MemoryRangeTable, MigratableError> {
        let mut table = MemoryRangeTable::default();
        for r in &self.guest_ram_mappings {
            let vm_dirty_bitmap = self.vm.get_dirty_log(r.slot, r.gpa, r.size)?;   // hypervisor bitmap
            let vmm_dirty_bitmap = region.bitmap().get_and_reset();                 // VMM bitmap
            let dirty_bitmap = vm_dirty_bitmap.iter().zip(vmm_dirty_bitmap.iter()).map(|(x, y)| x | y);  // 逐位 OR
            table.extend(MemoryRangeTable::from_dirty_bitmap(dirty_bitmap, r.gpa, 4096));
        }
        Ok(table)
    }
}

    live migration 必须同时跟踪 guest CPU 写入和 VMM 侧设备模拟写入——只看 KVM dirty log 会漏掉 VMM 经 host mapping 修改的 guest RAM。Vm::dirty_log() 还合并 device_manager.dirty_log()（vhost-user/设备 backend 可能提供额外 dirty memory，vm.rs:3283）。

    11. 能力边界 / ARM64 / 与四项目对齐

    问题 结论
    snapshot 是否直接含全部 RAM 字节 否，metadata 在 Snapshot，字节在 memory-ranges
    restore 默认是否按需填页 否，默认 Copy
    on-demand 是否需外部 handler 不需要，VMM 内 uffd-handler 线程
    prefault 能否与 on-demand 共用 不能
    dirty log 是否只来自 hypervisor 否，合并 VMM atomic bitmap
    device dirty log 是否参与 VM 级迁移 是，VM 级合并 memory + device dirty log

    memory transport/copy restore/on-demand UFFD/dirty bitmap 合并逻辑不按 ARM64/x86_64 分叉——是跨架构共用层，架构差异在它之前的 region 构造和之后的 CPU/设备状态恢复。

    CH memory transport 是 VMM 级机制（只关心 guest RAM/slots/dirty ranges/UFFD 填页）。Kata 需在其上处理 sandbox/container runtime + agent 状态；CubeSandbox 再往上处理 CubeCoW/catalog/network binding/template replica/rollback binding。Firecracker 与 CH 最适合直接对照 UFFD restore（一个外部 handler，一个内部 handler；都把"恢复拓扑"与"填充页面内容"分开）。
