Cloud Hypervisor TDX vCPU exit / VMCALL 边界链路

本文分析 TDX guest 运行后，VMM 对 TDX VM exit 与 VMCALL 的支持边界。

源码基线：当前仓库工作树。

相关：CoCo TDX/SEV-SNP、TDX TDVF/HOB。

0. 术语与背景

TDX VM exit 与普通 VM exit 不同

TDX guest 的大部分 exit 被 KVM TDX 模块内部处理（不返回 VMM）。只有特定的 TDX VMCALL（如 GetQuote、SetupEventNotifyInterrupt）会返回 VMM。

CH 支持的 TDX VMCALL

// hypervisor/src/kvm/mod.rs:130
#[cfg(feature = "tdx")]
const KVM_EXIT_TDX: u32 = 50;
#[cfg(feature = "tdx")]
const TDG_VP_VMCALL_GET_QUOTE: u64 = 0x10002;
#[cfg(feature = "tdx")]
const TDG_VP_VMCALL_SETUP_EVENT_NOTIFY_INTERRUPT: u64 = 0x10004;
#[cfg(feature = "tdx")]
const TDG_VP_VMCALL_SUCCESS: u64 = 0;
#[cfg(feature = "tdx")]
const TDG_VP_VMCALL_INVALID_OPERAND: u64 = 0x8000000000000000;
VMCALL 含义 CH 处理
GetQuote guest 请求 attestation quote CH 识别 + 转发（或返回未实现）
SetupEventNotifyInterrupt guest 注册事件通知中断 CH 识别 + 设置中断
其他 — 返回 TDG_VP_VMCALL_INVALID_OPERAND

1. 能力边界

CH 对 TDX VMCALL 的支持非常有限——只识别 GetQuote 和 SetupEventNotifyInterrupt。TDX guest 的大部分 I/O（virtio MMIO exit）由 KVM TDX 模块内部处理（TDX 直接注入中断，不经 VMM MMIO 模拟）。这与非 TDX VM 的 MMIO/PIO exit 分发模型完全不同——TDX guest 的设备模拟路径被 KVM TDX 模块接管，VMM 主要处理 VMCALL 类 exit。
