Cloud Hypervisor TDX lifecycle 限制链路

本文分析 TDX 为什么禁止 snapshot、live migration、coredump，并收窄 CPU/Memory hotplug。

源码基线：当前仓库工作树。

相关：CoCo TDX/SEV-SNP、横向 protected VM snapshot/migration。

0. 术语与背景

TDX lifecycle 限制

操作 TDX 原因
snapshot 拒绝 TD 状态含加密寄存器/measurement，无法安全序列化
live migration 拒绝 migration 需要完整 TD state（含加密 key），CH 无 TDX migration API
coredump 拒绝 coredump 会暴露加密内存明文
CPU hotplug max_vcpus==boot_vcpus TDX TD 创建时固定 vCPU 数
Memory dynamic false TD 内存布局创建时固定
firmware hotplug 校验拒绝 TDVF 必须创建时加载

1. 核心代码

// vmm/src/config.rs:3525
pub fn is_tdx_enabled(&self) -> bool { self.platform.as_ref().is_some_and(|p| p.tdx) }
// vmm/src/vm.rs:1276
let tdx_enabled = if snapshot.is_some() { false } else { vm_config.lock().unwrap().is_tdx_enabled() };

VmConfig::validate() 在 TDX 启用时强制 max_vcpus == boot_vcpus（CPU hotplug 拒绝）+ dynamic = false（Memory/CPU resize 拒绝）。Vm::snapshot() / send_migration() / receive_migration() / coredump() 都检查 tdx_enabled 并拒绝。

2. 能力边界

TDX 保护的是威胁 ③（恶意 host 窥探 guest）——guest 内存加密 + measurement 保证完整性。代价是失去 snapshot/migration/coredump/hotplug 等运行期能力。这与 CubeSandbox 的 x86_64 PVM（KvmPvm）形成对照——PVM 是轻量保护 VM（非全加密），snapshot/rollback 可用但保护更弱。
