Cloud Hypervisor VFIO / vfio-user / IOMMU / Migration 能力矩阵链路

本文补齐 VFIO/vfio-user 的 IOMMU、dirty log、migration 能力边界。

源码基线：当前仓库工作树。

相关：设备创建矩阵、I/O 设备数据面。

0. 术语与背景

VFIO vs vfio-user vs vhost-user vs vDPA

类型 对象模型 DMA dirty log
VFIO PCI VfioPciDevice（native PCI device） host physical PCI passthrough + vfio_dma_map 默认空（kernel VFIO dirty log 依赖 IOMMU 支持）
vfio-user VfioUserPciDevice（userspace PCI 协议） dma_map 经 vfio-user 协议 取决于 backend 实现
vhost-user MetaVirtioDevice → VirtioPciDevice backend 持有 guest memory backend 协商 LOG_SHMFD + VHOST_F_LOG_ALL
vDPA MetaVirtioDevice → VirtioPciDevice 内核 vhost-vDPA 内核 vDPA dirty log

VFIO/vfio-user 不走 MetaVirtioDevice——直接 PciDeviceHandle::Vfio/VfioUser 作为 native PCI device。

1. VFIO PCI DMA mapping

// vmm/src/device_manager.rs:3876
VfioDevice::new(&device_cfg.path, Arc::clone(&vfio_ops) as Arc<dyn VfioOps>)?;
if needs_dma_mapping {
    for (_, zone) in self.memory_manager.lock().unwrap().memory_zones().iter() {
        for region in zone.regions() {
            unsafe { vfio_ops.vfio_dma_map(region.start_addr().raw_value(), region.len(), region.as_ptr())?; }  // 注册 guest memory zone 到 VFIO IOMMU
        }
    }
}

VFIO DMA map 把 guest memory zones 注册到 VFIO IOMMU——virtio-mem regions 不注册（由 virtio-mem 设备自己处理）。

2. dirty log（遍历 migratable 设备）

// vmm/src/device_manager.rs:5560
fn dirty_log(&mut self) -> Result<MemoryRangeTable, MigratableError> {
    let mut tables = Vec::new();
    for (_, device_node) in self.device_tree.lock().unwrap().iter() {
        if let Some(migratable) = &device_node.migratable { tables.push(migratable.lock().unwrap().dirty_log()?); }  // 每个 migratable 设备贡献 dirty range
    }
    Ok(MemoryRangeTable::new_from_tables(tables))
}

VFIO dirty log 默认空——kernel VFIO dirty log 依赖 IOMMU 支持（IOMMU_DIRTY_TRACK). VFIO PCI 设备 dirty page tracking 是当前 migration 的最大正确性/性能张力点。

3. snapshot/restore

VFIO PCI snapshot：VfioPciDevice 实现 Snapshottable（保存 PCI config + device config）；restore 从 snapshot 重建设备 + DMA map。vfio-user snapshot：VfioUserPciDevice 类似，但 backend state 取决于外部 daemon。迁移限制：VFIO 设备迁移依赖 kernel VFIO migration API 支持（device state stop/copy/resume）。

4. 能力边界

问题 CH 表现
VFIO dirty log 默认空（依赖 IOMMU + kernel VFIO migration API）
vfio-user dirty log 取决于 backend 实现
vhost-user dirty log 协商 LOG_SHMFD + VHOST_F_LOG_ALL
VFIO snapshot 有（PCI config + device config）
VFIO migration 有 API（device state），但依赖 kernel + 硬件支持
virtio-iommu 外部映射 AccessPlatformMapping 提供 GVA→GPA 翻译
