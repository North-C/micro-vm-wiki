Cloud Hypervisor 隔离机制函数级链路（seccomp + Landlock）

本文展开 CH 作为"无 external jailer 的单进程 VMM"的进程/线程隔离机制。

源码基线：当前仓库工作树。

相关：安全隔离边界、性能设计依据。

0. 术语与背景

设计取向：线程级最小权限，不做 external jailer

CH 不做 Firecracker jailer 那种 chroot/pivot_root/netns/cgroup。代码中没有这些调用。它靠 VMM 进程内按线程类别施加 seccomp + 可选 Landlock 文件访问白名单收敛攻击面。

关键边界

  • Landlock 只覆盖 EventMonitor + SignalHandler 线程（VMM/vCPU/virtio 线程只 seccomp）。
  • seccomp 按线程类型生成独立 BPF filter：VMM/EventMonitor/SignalHandler/Vcpu + 16 种 virtio 设备线程。
  • 依赖部署侧：强隔离（chroot/netns/cgroup）需外层套 jailer/容器。

1. Landlock（配置驱动文件白名单）

// vmm/src/landlock.rs:75  apply_landlock
let file_access = AccessFs::from_all(ABI::V3);   // ABI V3
let def_ruleset = Ruleset::default().set_compatibility(HardRequirement).handle_access(file_access)?;
// vm_config.rs  apply_landlock trait → add_rule(path, access) → restrict_self()
// vmm/src/lib.rs:1777  vm_create 时调用
fn apply_landlock(vm_config: &mut VmConfig) -> Result<(), LandlockError> { vm_config.apply_landlock()?; Ok(()) }

配置类型（DiskConfig/FsConfig/PmemConfig/VsockConfig 等）实现 ApplyLandlock trait 声明需访问的路径 + 权限。Landlock 生效后只允许白名单路径。

2. seccomp（spawn_virtio_thread）

// virtio-devices/src/thread_helper.rs:17
pub fn spawn_virtio_thread(name, seccomp_action, thread_type, epoll_threads, exit_evt, f) -> Result<(), ActivateError> {
    let seccomp_filter = get_seccomp_filter(seccomp_action, thread_type)?;   // 按线程类型取 filter
    thread::Builder::new().name(name).spawn(move || {
        apply_filter(&seccomp_filter)?;   // apply seccomp → 运行 worker
        f()
    })?;
}
// virtio-devices/src/seccomp_filters.rs:273
fn get_seccomp_rules(thread_type: Thread) -> Vec<(i64, Vec<SeccompRule>)> {
    match thread_type {
        Thread::VirtioBalloon => virtio_balloon_thread_rules(),
        Thread::VirtioBlock => virtio_block_thread_rules(),
        Thread::VirtioNet => virtio_net_thread_rules(),
        // ... Console/Iommu/Mem/Pmem/Rng/VhostBlock/VhostFs/VhostNet/VhostNetCtl/Vsock/Watchdog ...
    }
}

每个 virtio 设备线程有独立 syscall allowlist（设备特定 syscall + common 集合）。EventMonitor/SignalHandler 线程也 apply seccomp + Landlock restrict_self（lib.rs:454/467）。

3. 能力边界 / ARM64 差异

维度 CH 表现
external jailer 无
chroot/pivot_root/netns 不做
seccomp 有（按线程类型 VMM/vCPU/EventMonitor/SignalHandler/16 种 virtio）
Landlock 有（ABI V3，仅 EventMonitor + SignalHandler，配置驱动路径白名单）
vhost-user 后端隔离 CH 不负责（backend daemon 自己 jail）

ARM64/x86_64：seccomp allowlist 按架构分裂（ARM64 用 *at 系列，x86 有 open/readlink/unlink）。此前引用的 CubeSandbox 对照文档未在当前工作区确认，因此不作为证据链接；Landlock 框架跨架构共享。
