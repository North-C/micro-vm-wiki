Firecracker Virtio Block 数据面链路

本文补齐 Firecracker 设备模型的 block 具体设备层：从 drive API、VmResources、启动 attach，到 virtqueue 请求、host backing file I/O、rate limiter、runtime update、snapshot 状态边界。

源码基线：当前仓库工作树。

相关：virtio device work、build_microvm_for_boot、storage/rootfs 边界、snapshot/restore。

0. 术语与背景

block 是 VMM 进程内 virtio 设备

API 插入 drive 只更新配置集合（BlockBuilder），真正 guest 可见设备在 StartMicroVm 构建阶段 attach。无单独 block worker 线程——VirtioBlock 作为 MutEventSubscriber 由 VMM event loop 驱动。

数据面 = 一个 virtqueue

guest kick queue event → VMM 解析 descriptor chain → 消耗 rate limiter token → host backing file read/write/flush → 写 used ring + 中断。

sync vs async file engine

  • SyncFileEngine：直接对 host File seek + guest memory volatile slice 读写；完成立即写 used ring。
  • AsyncFileEngine：io_uring，read/write/flush push 到 ring，completion event 回来后写 status + used ring。

关键边界

  • runtime PATCH /drives/{id} 只能换 backing file path + rate limiter，不能热插新 block。
  • snapshot 不含 backing file 字节——只存 virtio/queue/transport/rate limiter state + backing file path；恢复要求同路径 backing file 可用且内容匹配。
  • vhost-user-block 不支持 snapshot（check_unsnapshottable_devices 阻止）。

1. 核心结论

  • block 是 VMM 进程内 virtio 设备；API 插 drive 只更新配置，attach 在 StartMicroVm。
  • 单 virtqueue；guest kick → 解析 descriptor → rate limit → backing file I/O → used ring + 中断。
  • 无单独 worker 线程（VMM event loop 驱动）；支持 Sync + io_uring Async engine。
  • runtime PATCH 只换 path/rate limiter；snapshot 不含 backing 字节，vhost-user-block 不可 snapshot。
  • ARM64/x86_64 数据面基本共享，差异在 transport 枚举/启动描述。

2. API 到 VmResources / Root cmdline

parse_put_drive() 解析 BlockDeviceConfig（要求 URL id == body drive_id）→ InsertBlockDevice；pre-boot insert_block_device() 调 set_block_device() 只放 Block 进 BlockBuilder（不建 guest 设备）。BlockBuilder 保证最多一个 root block（root 始终队列首部）+ 拒绝 root block 与 pmem root 共存。attach_block_devices() 写 root cmdline：

// src/vmm/src/builder.rs:672
fn attach_block_devices(/*...*/) -> Result<(), StartMicrovmError> {
    for block in blocks {
        let locked = block.lock().expect("Poisoned lock");
        if locked.root_device() {
            match locked.partuuid() {
                Some(partuuid) => cmdline.insert_str(format!("root=PARTUUID={}", partuuid))?,
                None => cmdline.insert_str("root=/dev/vda")?,
            }
            match locked.read_only() { true => cmdline.insert_str("ro")?, false => cmdline.insert_str("rw")? }
        }
        device_manager.attach_virtio_device(vm, id, block.clone(), /*...*/)?;
    }
}

root cmdline 不按架构分支——ARM64 用 FDT 启动，但 block root 仍是 kernel cmdline 语义。

3. process_queue（数据面核心）

// src/vmm/src/devices/virtio/block/virtio/device.rs:389
pub fn process_queue(&mut self, queue_index: usize) -> Result<(), InvalidAvailIdx> {
    let queue = &mut self.queues[queue_index]; let mut used_any = false;
    while let Some(head) = queue.pop_or_enable_notification()? {            // 取 descriptor chain
        match Request::parse(&head, &active_state.mem, self.disk.nsectors) { // 解析 blk request
            Ok(request) => {
                if request.rate_limit(&mut self.rate_limiter) { queue.undo_pop(); break; }  // ops+bytes token 不足→回退
                request.process(&mut self.disk, head.index, &active_state.mem, &self.metrics)  // host file I/O
            }
            Err(err) => { /* parse 失败→错误完成 */ }
        };
        match processing_result {
            ProcessingResult::Submitted => {}                                // async 已提交
            ProcessingResult::Throttled => { queue.undo_pop(); self.is_io_engine_throttled = true; break; }
            ProcessingResult::Executed(finished) => { used_any = true; queue.add_used(head.index, finished.num_bytes_to_mem)?; }  // sync 完成
        }
    }
    queue.advance_used_ring_idx();
    if used_any && queue.prepare_kick() { active_state.interrupt.trigger(VirtioInterruptType::Queue(0))?; }  // 通知 guest
}

限速在数据热路径上：rate_limit() 同时消耗 ops + bytes token；bytes 不足时归还 ops token + undo_pop 回退 descriptor，等 limiter event。prepare_kick()（notification suppression）决定是否触发 queue interrupt。

4. File Engine（sync vs async）

// src/vmm/src/devices/virtio/block/virtio/io/mod.rs:53
pub enum FileEngine { Async(AsyncFileEngine), Sync(SyncFileEngine) }
impl FileEngine {
    pub fn from_file(file: File, engine_type: FileEngineType) -> Result<FileEngine, BlockIoError> {
        match engine_type {
            FileEngineType::Async => Ok(FileEngine::Async(AsyncFileEngine::from_file(file)?)),
            FileEngineType::Sync => Ok(FileEngine::Sync(SyncFileEngine::from_file(file))),
        }
    }
}
// async_io.rs:37
pub struct AsyncFileEngine { file: File, ring: IoUring<WrappedRequest>, completion_evt: EventFd }
// sync_io.rs:24
pub struct SyncFileEngine { file: File }   // read/write 直接对 File seek + guest memory volatile slice

sync engine 完成立即写 used ring；async engine push 到 io_uring ring，process_async_completion_event() 读 CQE 后写 status + used ring（read completion 还会把 guest memory 标 dirty）。flush = flush() + sync_all()。

5. 事件处理（两阶段注册）

block init() 未激活只注册 activate event；激活后才注册 queue event + rate limiter event + async completion event。queue event → process_queue_event（读 eventfd + 检查 limiter/throttle → process_queue(0)）；rate limiter event → process_rate_limiter_event（补 token + 重调 process_queue(0)）；async completion → process_async_completion_event（读完成队列写 used ring + 若之前 throttled 继续）。

6. Runtime Update

UpdateBlockDevice → update_block_device()：带 path_on_host → update_block_device_path → with_virtio_device(id) 找 Block + update_disk_image()（重开 backing file + 更新 config space capacity + 已激活触发 config interrupt）；带 rate_limiter → update_block_rate_limiter → RateLimiter::update_buckets。

update_disk_image 只对内置 virtio-block 生效，vhost-user-block 返 InvalidBlockBackend（见 storage/rootfs 边界）。内置 virtio-block 不支持通过 PATCH 新增设备。

7. Snapshot 状态边界

DeviceManager 存 MMIO transport 时先 prepare_save() 再存 transport + device state。VirtioBlock::prepare_save() 对已激活设备 drain/flush（async 还处理 completion queue，减少悬挂 I/O）。VirtioBlockState 存 id/partuuid/cache_type/root_device/disk_path/通用 virtio state/rate limiter state/file engine type。restore 据 disk_path 重开 backing file + 重建 queues/eventfd/config/rate limiter。

snapshot 不含 block image 数据——恢复要求相同路径 backing file 可用 + 内容与 snapshot 时 VM 状态匹配。vhost-user-block 被 check_unsnapshottable_devices 列为不可 snapshot（MMIO persist 不存它，PCI persist 跳过 + warning）。

8. ARM64/x86_64 / 能力边界

block request parse/rate limiter/sync-async engine/queue used ring/persist 不按架构分支。差异在启动暴露：未启 PCI 时 x86_64 加 virtio_mmio.device=... cmdline + AML，ARM64 在 FDT 生成 virtio_mmio@... + compatible="virtio,mmio" 节点；启 PCI 两架构都走 PCI manager。

能力 Firecracker 表现
文件系统语义 不提供，只 sector read/write/flush/get-id
只读设备 VIRTIO_BLK_F_RO 告知 guest
rate limiter 限请求节奏，不改容量/backing file
PATCH 换 backing file guest 需经 config interrupt 感知容量变化；Firecracker 不修复文件系统一致性
snapshot 一致性 依赖 prepare_save drain/flush + 外部 backing file 可恢复（非完整磁盘镜像备份）
