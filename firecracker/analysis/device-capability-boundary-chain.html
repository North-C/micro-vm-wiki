Firecracker 设备能力边界链路

本文补齐 Firecracker 设备模型中 vsock、balloon、pmem、entropy/rng、virtio-mem 的能力边界（block/net/MMDS 已在独立文档展开）。

源码基线：当前仓库工作树。

相关：virtio device work、runtime device update、snapshot/restore。

0. 术语与背景

设备集启动期固定

build_microvm_for_boot() 按配置 attach balloon/block/net/pmem/vsock/entropy/virtio-mem（builder.rs:214）。运行期只对已有设备做窄字段更新（不是任意热插拔）。

snapshot 保存协议状态 + 可重建后端引用

不保存 vsock 活跃连接、pmem backing file 内容、随机数流——只存设备协议状态（virtio state/queue/transport/config）+ 可重建后端引用（CID/UDS path/disk path等）。

1. 设备边界矩阵

设备 启动期来源 运行期可变项 snapshot 保存 不保存/不承诺
vsock VsockBuilder 无同级 PATCH CID/virtio state/UDS path/last local port 活跃连接/in-flight packet（restore 后 transport reset）
balloon BalloonBuilder target/stats/hinting stats_polling_interval/stats_desc_index/latest_stats/config_space/hinting_state/virtio_state —
pmem PmemBuilder rate limiter only file path/size/discard_writes/virtio state backing file 字节内容
entropy/rng EntropyDeviceBuilder 无同级 PATCH virtio state（随机数流不保存） 随机数流
virtio-mem MemoryHotplugConfig requested size addr/region_size/block_size/usable_region_size/plugged_blocks/requested_size/slot_size/virtio_state —

2. balloon update + virtio-mem update（关键代码）

// src/vmm/src/devices/virtio/balloon/device.rs:717
pub fn update_size(&mut self, amount_mib: u32) -> Result<(), BalloonError> {
    if self.is_activated() {
        let mem = &self.device_state.active_state().unwrap().mem;
        if u64::from(amount_mib) > mem_size_mib(mem) { return Err(BalloonError::TooMuchMemoryRequested(amount_mib)); }
        self.config_space.num_pages = mib_to_pages(amount_mib)?;
        self.interrupt_trigger().trigger(VirtioInterruptType::Config)?;   // 更新 config → 触发 Config interrupt
    } else { Err(BalloonError::DeviceNotActive) }
}
// src/vmm/src/devices/virtio/mem/device.rs:557
pub fn update_requested_size(&mut self, requested_size_mib: usize) -> Result<(), VirtioMemError> {
    if !self.is_activated() { return Err(VirtioMemError::DeviceNotActive); }
    if !requested_size.is_multiple_of(self.config.block_size) { return Err(VirtioMemError::InvalidSize(requested_size)); }
    if requested_size > self.config.region_size { return Err(VirtioMemError::InvalidSize(requested_size)); }
    if self.config.usable_region_size < requested_size { self.config.usable_region_size = requested_size.next_multiple_of(usize_to_u64(self.slot_size)); }
    self.config.requested_size = requested_size;   // 改 config space，guest 轮询感知
}

balloon update_size 更新 config → trigger Config interrupt（让 guest 立即感知）；virtio-mem update_requested_size 改 config space，guest 轮询感知（不触发 interrupt）。

3. snapshot persist（BalloonState + VirtioMemState）

// src/vmm/src/devices/virtio/balloon/persist.rs:98
pub struct BalloonState {
    stats_polling_interval_s: u16, stats_desc_index: Option<u16>,
    latest_stats: BalloonStatsState, config_space: BalloonConfigSpaceState,
    hinting_state: HintingState, pub virtio_state: VirtioDeviceState,
}
// src/vmm/src/devices/virtio/mem/persist.rs:60
fn save(&self) -> VirtioMemState {
    VirtioMemState {
        virtio_state: VirtioDeviceState::from_device(self), addr, region_size, block_size,
        usable_region_size, plugged_blocks: self.plugged_blocks.iter().by_vals().collect(),  // plugged bitmap
        requested_size, slot_size,
    }
}

virtio-mem snapshot 保存 plugged_blocks（哪些 block 已插）——restore 后 guest 能继续 plug/unplug。

4. VirtioDeviceType 枚举（设备集）

// src/vmm/src/devices/virtio/device.rs:63
pub enum VirtioDeviceType { Net, Block, Rng, Balloon, Vsock, Mem, Pmem }

Firecracker 的设备扩展点是"实现一个 VirtioDevice"，设备集刻意收窄到这 7 类。

5. 能力边界

能力 Firecracker 表现
设备集 启动期固定（7 类 VirtioDeviceType）
运行期热插拔 不支持（只窄字段 update）
vsock 连接跨 snapshot 不保持（restore 后 transport reset）
pmem backing file snapshot 不存字节，恢复要求同路径 file 可用
virtio-mem plugged_blocks snapshot 保存（restore 后可继续 plug/unplug）
entropy 随机数流 不保存（restore 后重新开始）
