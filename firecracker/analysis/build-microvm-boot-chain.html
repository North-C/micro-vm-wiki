Firecracker build_microvm_for_boot 构建链路

本文展开 build_microvm_for_boot()——StartMicroVm 之后配置如何一次性变成 KVM VM、guest memory、vCPU、DeviceManager、kernel boot state 和运行中的 vCPU。

源码基线：当前仓库工作树。

相关：VmResources 配置边界、vCPU/KVM_RUN、virtio device work。

0. 术语与背景

builder 是"配置 → 真实 microVM"的转换点

build_microvm_for_boot() 消费 VmResources（pre-boot 已聚合的配置快照），创建 KVM/VM/vCPU、注册内存、挂设备、写架构启动状态。

builder 本身不让 guest 运行——构建出的 microVM 和 vCPU 初始 paused，需 Vmm::resume_vm() 才运行。build_and_boot_microvm() 是默认 recipe：先 builder 再 resume_vm()。

关键边界

  • builder 消费已聚合快照——不是持续响应 API 变更；pre-boot API 只更新 VmResources 的 builder/config，不立刻建 guest 可见设备。
  • PCI/MMIO transport 构建期决定——pci_enabled 在 builder 决定，运行时只能复用，不能切 transport。
  • 设备集此阶段固定——运行后只能 update 有限参数，不能重新 attach 新增 block/net/vsock。
  • memory hotplug 预分配早于 DeviceManager——virtio-mem 依赖的 guest memory slot 必须早于设备构造完成。
  • seccomp 顺序：vCPU 线程先加载 vcpu filter；VMM thread 在所有构建结束后加载 vmm filter（resume 前最后一步）。

1. 核心结论

  • build_microvm_for_boot() 是 pre-boot 配置 → 真实 microVM 的转换点，消费 VmResources 建 KVM/VM/vCPU + 注册内存 + 挂设备 + 写架构启动状态。
  • 构建结果 paused，需 resume_vm() 才进 KVM_RUN。
  • ARM64/x86_64 共用 builder 主体，差异在 KVM arch init / vCPU configure / kernel entry / cmdline 放置 / FDT vs ACPI / PIO-MMIO / 少量 legacy 设备。

2. 主流程图

builder 完成"机器成形"，resume_vm() 完成"机器运行"。

3. build_microvm_for_boot 主体

// src/vmm/src/builder.rs:153
let boot_config = vm_resources.boot_source.builder.as_ref().ok_or(StartMicrovmError::MissingKernelConfig)?;
let guest_memory = vm_resources.allocate_guest_memory()?;                       // (1) guest memory
let cpu_template = vm_resources.machine_config.cpu_template.get_cpu_template()?;
let kvm = Kvm::new(cpu_template.kvm_capabilities.clone())?;                      // (2) Kvm
let mut vm = Vm::new(&kvm)?;                                                      // (3) VM
let (mut vcpus, vcpus_exit_evt) = vm.create_vcpus(vm_resources.machine_config.vcpu_count)?;  // (4) vCPU
vm.register_dram_memory_regions(guest_memory)?;                                   // (5) 注册 DRAM
// (6) memory hotplug：为 virtio-mem 预留地址 + 分配 hotpluggable region（早于 DeviceManager）
let mut device_manager = DeviceManager::new(event_manager, &vcpus_exit_evt, &vm, /* serial */)?;  // (7) DeviceManager
let entry_point = load_kernel(&boot_config.kernel_file, vm.guest_memory())?;     // (8) kernel/initrd
let initrd = InitrdConfig::from_config(boot_config, vm.guest_memory())?;
if vm_resources.pci_enabled { device_manager.enable_pci(&vm)?; }                 // (9) PCI 开关（构建期决定）
else { boot_cmdline.insert("pci", "off")?; }
// (10) attach boot timer(必须第一) → balloon → block → net → pmem → vsock → entropy → virtio-mem → legacy → vmgenid/vmclock
// (11) configure_system_for_boot（架构分叉）
// (12) Vmm::start_vcpus(paused) + apply vmm seccomp + 注册 EventManager

builder 职责是消费已聚合好的配置快照——pre-boot API 只更新 VmResources 的 builder/config，不立即建 guest 可见设备。

4. 内存 / KVM / vCPU

allocate_guest_memory() 按 mem_size_mib 调架构 arch_memory_regions() 分配 region（resources.rs:518）。配置 vhost-user block 时用 memfd-backed shared memory，否则 anonymous private memory（:480）。boot cmdline 会 clone（避免失败 boot 污染原始配置，builder.rs:163）。Kvm::new() 打开 /dev/kvm + 检查 API version + 确认默认 + CPU template modifier capability（kvm.rs:27）。x86_64 Kvm 保存 supported CPUID，aarch64 不保存 CPUID——这是后续 vCPU 配置差异起点。Vm::create_vcpus() 先 arch pre-create hook → 建 exit eventfd → 循环建 Vcpu → arch post-create hook（vm.rs:146）。register_dram_memory_regions 为每 DRAM region 分配 KVM slot + set_user_memory_region（:212）。

5. memory hotplug 预分配

配置 memory hotplug 时 builder 在建 DeviceManager 前处理（:179）：resource allocator 在 64-bit MMIO 后方为 virtio-mem 预留地址 → 分配 hotpluggable region → register_hotpluggable_memory_region。

尽早分配是为了让所有后续消费者 clone GuestMemoryMmap 时都能看到 hotpluggable memory——virtio-mem 虽是设备，但它依赖的 guest memory slot 必须早于设备构造完成。

6. 设备 attach 顺序 + virtio transport

boot timer（启用时）必须第一个 attach（保持文档/测试中的固定 MMIO 地址，:214），随后 balloon → block → net → pmem → vsock → entropy → virtio-mem → aarch64 legacy → vmgenid/vmclock。block root 写 root=/dev/vda/PARTUUID + ro/rw；pmem root 写 root=/dev/pmem{i} + alloc_region/set_mem_region。

所有普通 virtio attach 进 attach_virtio_device()（device_manager/mod.rs:266）：PCI 启用走 PciDevices::attach_pci_virtio_device，否则 attach_mmio_virtio_device（建 MmioTransport + register_mmio_virtio_for_boot，:244）。两者都保留 (VirtioDeviceType, String) 索引，区别在 guest 侧 transport，不在设备本体业务语义。

7. 架构启动配置（configure_system_for_boot）

设备 attach 后调 configure_system_for_boot()（架构分叉点，:304）：

// src/vmm/src/arch/x86_64/mod.rs:175  (x86_64)
let cpu_config = CpuConfiguration::new(kvm.supported_cpuid.clone(), cpu_template, &vcpus[0])?;  // 基于 supported CPUID + template
for vcpu in vcpus.iter_mut() { vcpu.kvm_vcpu.configure(vm.guest_memory(), entry_point, &vcpu_config)?; }
load_cmdline(vm.guest_memory(), GuestAddress(CMDLINE_START), &boot_cmdline)?;                   // cmdline 写固定地址
mptable::setup_mptable(/*...*/)?;                                                                // mptable
match entry_point.protocol { BootProtocol::PvhBoot => configure_pvh(/*...*/), BootProtocol::LinuxBoot => /*...*/ }
// 最后创建 ACPI tables（仅 x86_64）

// src/vmm/src/arch/aarch64/mod.rs:93  (aarch64)
for vcpu in vcpus.iter_mut() { vcpu.kvm_vcpu.configure(vm.guest_memory(), entry_point, &vcpu_config, &optional_capabilities)?; }
override_clidr(vcpus)?;                                                                           // CLIDR override
let vcpu_mpidr = vcpus.iter_mut().map(|c| c.kvm_vcpu.get_mpidr()).collect::<Result<Vec<_>>>()?;
let fdt = fdt::create_fdt(vm.guest_memory(), vcpu_mpidr, cmdline, device_manager, vm.get_irqchip(), initrd)?;  // cmdline/device/GIC 放 FDT
let fdt_address = GuestAddress(get_fdt_addr(vm.guest_memory()));

x86_64 = cmdline 写固定地址 + mptable + PVH/LinuxBoot boot params + ACPI；aarch64 = cmdline/initrd/设备/中断控制器由 FDT 串起来（cmdline 不写固定地址，放 FDT）。

8. VMM 对象 / vCPU 线程 / Resume

架构配置后构造 Vmm（持 instance_info/machine_config/boot_source/kvm/vm/vCPU handles/exit eventfd/DeviceManager，:316）。start_vcpus() 为每 vCPU 设 MMIO bus（x86_64 还设 PIO bus，lib.rs:485）；Vcpu::start_threaded() 建 fc_vcpu <index> 线程 + 复制 KVM vCPU fd + 注册 kick signal handler + self.run(filter)（vCPU 线程先加载 vcpu seccomp 再 paused 状态机，vcpu.rs:166/198）。builder 加载 VMM thread seccomp + 注册 EventManager（VMM seccomp 是 resume 前最后步骤，:358）。

build_and_boot_microvm() 返回后调 resume_vm()（:381）：先 kick_virtio_devices 再向每 vCPU 发 Resume 等 Resumed（lib.rs:524）；vCPU paused 收 Resume 后清 immediate_exit + 发 Resumed + 切 running；running 调 run_emulation() → kvm_vcpu.fd.run()（KVM_RUN，vcpu.rs:296/383）。

核心虚拟化闭环：KVM 执行 CPU，Firecracker 在 VM-exit 时模拟受限设备集（MMIO/PIO bus 分发到设备模拟）。

9. ARM64/x86_64 差异 / 能力边界 / 排查

阶段 x86_64 aarch64
KVM arch state 保存 supported CPUID 不保存 CPUID
kernel loader LinuxBoot / PVH LinuxBoot
vCPU configure CPUID/topology/template template/optional caps/MPIDR
cmdline 写固定 guest 地址 放入 FDT
machine description mptable + ACPI FDT
I/O bus MMIO + PIO MMIO
legacy i8042/CtrlAltDel aarch64 legacy devices
pvtime 无该分支 支持时配置 steal time

API/VmResources/builder 主体/DeviceManager attach/vCPU 线程模型两架构一致——差异是同一 builder 在最后 arch configure + 少量设备路径处分叉。

能力边界：builder 只消费 pre-boot 已备好的配置（非可重入运行时重配置入口）；snapshot load 是另一条入口（已走 boot path 则 load_snapshot 拒绝，rpc_interface.rs:625）；设备集此阶段固定（运行后只能 update 有限参数）；PCI/MMIO 构建期决定；vCPU 线程 paused，无 resume_vm 不进 KVM_RUN。

现象 优先检查
StartMicroVm 返回 missing kernel boot source builder 是否存在
guest 没启动 resume_vm 是否成功，vCPU 是否 Resumed
rootfs 不对 block/pmem root device cmdline
guest 看不到 PCI pci_enabled / 是否误写 pci=off
MMIO 设备访问异常 MMIO bus 注册 + KVM MMIO exit 分发
x86 boot 异常 CPUID template/PVH/LinuxBoot/mptable/ACPI
ARM64 boot 异常 MPIDR/CLIDR override/FDT/GIC/device 描述
