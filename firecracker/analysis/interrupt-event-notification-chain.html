Firecracker 中断与事件通知链路

本文展开 guest virtio driver 如何通知 host 有新队列工作，Firecracker 设备完成后如何经 irqfd/MSI-X/IOAPIC/GIC 把中断送回 guest。

源码基线：当前仓库工作树。

相关：DeviceManager/virtio transport、vCPU/KVM_RUN、virtio device work。

0. 术语与背景

两半方向

  • guest → host（notify）：queue notify ioeventfd（KVM 直接 signal queue eventfd，不经 vCPU exit）。
  • host → guest（完成中断）：irqfd（设备写 eventfd，KVM 按 GSI route 注入中断）。

设备侧统一入口：VirtioInterrupt

设备只区分 Config（配置变更）和 Queue(u16)（队列完成），不直接理解 APIC/IOAPIC/GIC/MSI-X route——route/GSI/mask/controller 细节在 transport/Vm 层。

MMIO vs PCI 中断

transport 中断实现 特点
MMIO IrqTrigger（irq_status + 单个 irq_evt） 单 IRQ eventfd，多队列合并成一次 vring interrupt
PCI VirtioInterruptMsix（queue 数+1 vector） 每 vector 独立 eventfd，有 mask/PBA

架构差异在控制器：x86_64 用 IOAPIC/MSI-X；aarch64 创建 GICv3（失败 fallback GICv2）+ FDT。

1. 核心结论

中断抽象压到 VirtioInterrupt：设备只区分 Config/Queue。MMIO 用 IrqTrigger（设 MMIO status + 写单个 irq eventfd）；PCI 用 VirtioInterruptMsix（选 vector + mask/PBA + 写 per-vector eventfd）。guest→host 走 ioeventfd，host→guest 走 irqfd。架构差异在控制器（IOAPIC vs GIC）。

2. guest → host：ioeventfd

register_mmio_virtio 把每 queue eventfd 注册成 KVM ioeventfd 到 NOTIFY_REG_OFFSET（mmio.rs:179）；register_notification_ioevent 把 PCI notification BAR 每 queue notify 地址注册到 queue eventfd（pci/device.rs:594）。

Firecracker 不需每次 queue notify 都让 vCPU 线程处理 MMIO exit——ioeventfd 后 KVM 直接 signal queue eventfd。

3. MMIO host → guest：IrqTrigger

// src/vmm/src/devices/virtio/transport/mmio.rs:404
impl VirtioInterrupt for IrqTrigger {
    fn trigger(&self, interrupt_type: VirtioInterruptType) -> Result<(), InterruptError> {
        match interrupt_type {
            VirtioInterruptType::Config => self.trigger_irq(IrqType::Config),    // 设 VIRTIO_MMIO_INT_CONFIG
            VirtioInterruptType::Queue(_) => self.trigger_irq(IrqType::Vring),   // 设 VIRTIO_MMIO_INT_VRING
        }   // trigger_irq: irq_status.fetch_or() + irq_evt.write(1)（已注册为 irqfd → KVM 注入）
    }
}

register_mmio_virtio 经 vm.register_irq(&irq_evt, gsi) 把 interrupt eventfd 接入 guest legacy IRQ（mmio.rs:199）。MMIO 只有一个 IRQ eventfd，trigger_queues 多队列合并成一次 vring interrupt。

4. PCI host → guest：MSI-X vector

PCI attach 按 queue 数+1 分配 MSI-X vector（pci_mngr.rs:155）。VirtioInterruptMsix::trigger() 按 Config/Queue(index) 选 vector：

// src/vmm/src/devices/virtio/transport/pci/device.rs:669  (trigger 骨架)
fn trigger(&self, int_type: VirtioInterruptType) -> Result<(), InterruptError> {
    let vector = match int_type { Config => config_vector.load(), Queue(i) => queues_vectors[i] };
    if vector == VIRTQ_MSI_NO_VECTOR { return Ok(()); }       // guest 未配 vector
    let entry = &msix_config.table_entries[vector];
    if msix_config.masked() || entry.masked() { msix_config.set_pba_bit(vector); return Ok(()); }  // mask→PBA
    msix_vectors.trigger(vector)                               // 否则写 per-vector eventfd
}

PCI 比 MMIO 多了 vector 选择 + mask/PBA + per-vector eventfd，但设备仍只调同一 VirtioInterrupt trait。

5. GSI route 与 irqfd 顺序

MsixVector::enable → register_irqfd(event_fd, gsi)；disable → unregister_irqfd（interrupts.rs:65）。MSI-X 更新时先 disable → vm.register_msi() 更新 route → vm.set_gsi_routes() → 最后 enable irqfd（interrupts.rs:138）。顺序：先 KVM_SET_GSI_ROUTING 再 assign KVM_IRQFD，避免旧内核 route 缺失时异常。register_msi 构造 KVM_IRQ_ROUTING_MSI entry（支持 KVM_CAP_MSI_DEVID 时写 device id，vm.rs:428）；set_gsi_routes 跳过 masked route 提交 KVM（:474）。

6. 典型设备触发点 / Snapshot 边界

block 完成 queue 请求后 prepare_kick() true 则触发 Queue(0)（block/device.rs:503）；runtime 换 backing file 后触发 Config 让 guest 重读配置（:536）。net/rng/vsock/balloon/pmem/virtio-mem 都经 interrupt_trigger().trigger(...) 走同一抽象。

Snapshot：MsixVectorGroup Persist 只存 vector 的 GSI（不存 enabled 状态，restore 据 MSI-X config 重新 enable，interrupts.rs:176）。PCI transport state() 存 PCI config + common config + MSI-X state + BAR address（pci/device.rs:620）；MMIO 存设备资源 + virtio common + queue + device state + irq_status（无 vector 表）。

restore 不只恢复 eventfd——eventfd 要重新创建+注册，真正必须持久化的是 GSI/MSI-X config/transport state/queue state/device state。

7. ARM64/x86_64 / 与 CH 差异

x86_64 register_irq() 把 irqchip 写 KVM_IRQCHIP_IOAPIC；aarch64 写 0（实际控制器由 GIC 承担，vm.rs:400）。aarch64 create_gic() 先 GICv3 失败 fallback GICv2（gic/mod.rs:172），FDT 暴露 GIC/timer/PSCI/MMIO/PCI host bridge；x86_64 依赖 boot params/MP table/ACPI。

与 Cloud Hypervisor 差异：FC 中断路径短（设备直接持 VirtioInterrupt，transport 直接写 eventfd，VM 直接维护 GSI route）；CH 多一层 InterruptManager/InterruptSourceGroup（设备经 group trigger index，route/eventfd/controller 由 manager 管）——这解释 FC 适合固定设备集 + 低开销，CH 适合热插拔/vhost-user/VFIO/vDPA + 迁移。
