    Firecracker vCPU / KVM_RUN 链路

    本文展开 Firecracker 如何创建 vCPU 线程、通过状态机进入 KVM_RUN，以及 KVM exit 如何回到 MMIO/PIO/设备模拟。

    源码基线：当前仓库工作树。

    相关：隔离机制/Seccomp/Jailer、API Event Loop 与线程协作、Snapshot/Restore。

    0. 术语与背景

    vCPU 是独立线程，受 VMM 经 channel 控制

    每个 vCPU 一个 fc_vcpu <index> 线程，持有自己的 KVM vCPU fd，经 VcpuEvent/VcpuResponse channel 受 VMM 线程控制。

    通道 方向 用途
    VcpuEvent channel VMM → vCPU Pause/Resume/SaveState/DumpCpuConfig/Finish
    VcpuResponse channel vCPU → VMM Paused/Resumed/Exited/SavedState
    exit eventfd vCPU → VMM vCPU 退出时通知 VMM

    状态机：Paused → Running

    vCPU 线程启动后加载 vcpu seccomp filter，进 StateMachine::run(self, paused)——初始 Paused，只有收到 Resume 才进 Running。

    KVM_RUN 是唯一虚拟化执行点

    self.kvm_vcpu.fd.run() 即 KVM KVM_RUN ioctl 封装。KVM exit 先经通用层处理 MMIO/fatal/system event，再交架构 run_arch_emulation()。

    immediate_exit + signal（打断 KVM_RUN 的原理）

    Pause/SaveState/DumpCpuConfig 对正在 KVM_RUN 的 vCPU 不会立即在 channel 轮询生效——必须先 set_kvm_immediate_exit(1) + 发实时 signal 把 vCPU 踢出 KVM_RUN，进 running 循环检查 channel。

    vCPU 线程不主动拥有完整 VMM 控制权——只在 KVM exit 时模拟必要 I/O，生命周期控制来自 VMM 线程。

    1. 核心结论

    • vCPU 是独立线程（fc_vcpu），经 channel 受 VMM 控制。
    • 启动后加载 vcpu seccomp，进状态机（初始 Paused）。
    • kvm_vcpu.fd.run() 是唯一 KVM_RUN 点；exit 经 handle_kvm_exit 通用层 + 架构 run_arch_emulation。
    • x86_64 有 PIO bus（处理 IoIn/IoOut），aarch64 只有 MMIO bus（架构特有 exit 当前 unexpected）。

    2. 总体流程图

    flowchart TD Build["build_microvm_for_boot"] --> Start["Vmm::start_vcpus"] Start --> Thread["Vcpu::start_threaded"] Thread --> Seccomp["apply vcpu seccomp"] Seccomp --> Paused["StateMachine::paused"] Paused -->|VcpuEvent::Resume| Running["StateMachine::running"] Running --> Run["VcpuFd::run / KVM_RUN"] Run --> Exit["KVM exit"] Exit --> Common["handle_kvm_exit"] Common --> MMIO["MMIO bus read/write"] Common --> Arch["arch run_arch_emulation"] Arch --> PIO["x86_64 PIO bus"] Common --> Stop["SystemEvent reset/shutdown"]

    channel 是 VMM 控制 vCPU 的主通道；exit eventfd 主要用于 vCPU 退出时通知 VMM，不承载普通控制命令。

    4. Vcpu::start_threaded

    start_threaded() 取出 event sender/response receiver，dup() KVM vCPU fd 经 create_vcpu_from_rawfd 进 VcpuHandle（供 VMM kick），建 fc_vcpu <index> 线程：

    // src/vmm/src/vstate/vcpu.rs:168
pub fn start_threaded(mut self, vm, seccomp_filter, barrier) -> Result<VcpuHandle, StartThreadedError> {
    let event_sender = self.event_sender.take().expect("vCPU already started");
    let response_receiver = self.response_receiver.take().unwrap();
    let vcpu_fd = self.copy_kvm_vcpu_fd(vm)?;                       // dup fd → VcpuHandle（供 VMM kick）
    let vcpu_thread = thread::Builder::new().name(format!("fc_vcpu {}", self.kvm_vcpu.index)).spawn(move || {
        self.register_kick_signal_handler();                        // 注册 kick signal handler
        barrier.wait();                                             // 等 barrier（线程本地数据初始化）
        self.run(&*seccomp_filter);                                 // 进状态机
    })?;
    Ok(VcpuHandle::new(event_sender, response_receiver, vcpu_fd, vcpu_thread))
}

    signal handler 本身只做 acquire fence——真正中断语义来自 VMM 先设 immediate_exit 再发实时 signal。Vmm::start_vcpus() 建 Barrier（vCPU 数+1）等所有线程初始化，每个 vCPU 绑 MMIO bus，x86_64 额外绑 PIO bus，启动后 instance_info.state = Paused（lib.rs:485/506）。

    5. vCPU Seccomp 与初始状态

    // src/vmm/src/vstate/vcpu.rs:203
pub fn run(&mut self, seccomp_filter: BpfProgramRef) {
    if let Err(err) = crate::seccomp::apply_filter(seccomp_filter) { panic!(/* vCPU seccomp 加载失败 */); }
    StateMachine::run(self, Self::paused);                          // 初始 Paused
}

    vCPU 线程开始时不立即进 KVM——只有 VMM 发 Resume 后 paused 返 running。这解释了为什么 build_microvm_for_boot() 只构建 paused VM，build_and_boot_microvm() 还要 resume_vm()。

    6. 状态机语义

    paused 状态用 blocking recv() 等事件：

    // src/vmm/src/vstate/vcpu.rs:296
fn paused(&mut self) -> StateMachine<Self> {
    match self.event_receiver.recv() {
        Ok(VcpuEvent::Resume) => {
            if self.kvm_vcpu.fd.get_kvm_run().immediate_exit == 1u8 { self.kvm_vcpu.fd.set_kvm_immediate_exit(0); }  // 清零
            self.response_sender.send(VcpuResponse::Resumed)?;
            StateMachine::next(Self::running)
        }
        Ok(VcpuEvent::SaveState) => { /* kvm_vcpu.save_state() → SavedState */ StateMachine::next(Self::paused) }
        // ... Pause / DumpCpuConfig ...
    }
}

    running 状态先进入紧密 emulation loop——只有 run_emulation() 返回 Interrupted 才跳出检查 channel：

    // src/vmm/src/vstate/vcpu.rs:218
fn running(&mut self) -> StateMachine<Self> {
    loop {   // 紧密循环，优化 emulation 路径
        match self.run_emulation() {
            Ok(VcpuEmulation::Handled) => (),            // 继续跑
            Ok(VcpuEmulation::Interrupted) => break,     // 跳出检查 channel
            Ok(VcpuEmulation::Stopped) => return self.exit(FcExitCode::Ok),  // ARM shutdown/reset
            #[cfg(feature="gdb")] Ok(VcpuEmulation::Paused) => { /* x86 kvmclock_ctrl */ return StateMachine::next(Self::paused); }
            Err(_) => return self.exit(FcExitCode::GenericError),
        }
    }
    match self.event_receiver.try_recv() {
        Ok(VcpuEvent::Pause) => { /* x86 kvmclock_ctrl */ state = StateMachine::next(Self::paused); }
        // ...
    }
}

    Pause/SaveState 对正在运行的 vCPU 不会立即在普通 channel 轮询生效——必须先 immediate_exit + signal 打断 KVM_RUN（见 §7）。

    7. KVM_RUN 执行点 + 控制链路

    run_emulation() 是 vCPU 进 KVM 的唯一主路径：

    // src/vmm/src/vstate/vcpu.rs:386
pub fn run_emulation(&mut self) -> Result<VcpuEmulation, VcpuError> {
    if self.kvm_vcpu.fd.get_kvm_run().immediate_exit == 1u8 {   // immediate_exit=1 → 不进 KVM
        self.kvm_vcpu.fd.set_kvm_immediate_exit(0);
        return Ok(VcpuEmulation::Interrupted);
    }
    match self.kvm_vcpu.fd.run() {                              // KVM_RUN
        Err(ref err) if err.errno() == libc::EINTR => { self.kvm_vcpu.fd.set_kvm_immediate_exit(0); Ok(VcpuEmulation::Interrupted) }
        #[cfg(feature="gdb")] Ok(VcpuExit::Debug(_)) => { /* gdb event */ Ok(VcpuEmulation::Paused) }
        emulation_result => handle_kvm_exit(&mut self.kvm_vcpu.peripherals, emulation_result),
    }
}

    VcpuHandle::send_event() 三步是打断 KVM_RUN 的原理（resume_vm 先 kick virtio 再发 Resume 等 Resumed，lib.rs:524；pause_vm 发 Pause 等 Paused，:548）：

    // src/vmm/src/vstate/vcpu.rs:601
pub fn send_event(&mut self, event: VcpuEvent) -> Result<(), VcpuSendEventError> {
    self.event_sender.send(event).expect("event sender channel closed");
    self.vcpu_fd.set_kvm_immediate_exit(1);                    // (1) 让下次 KVM_RUN 立即返回
    fence(Ordering::Release);
    self.vcpu_thread.as_ref().unwrap().kill(sigrtmin() + VCPU_RTSIG_OFFSET)?;  // (2) 发实时 signal 踢出 KVM_RUN
    Ok(())
}

    8. 通用 KVM Exit 处理

    // src/vmm/src/vstate/vcpu.rs:415
fn handle_kvm_exit(peripherals, emulation_result) -> Result<VcpuEmulation, VcpuError> {
    match emulation_result {
        Ok(VcpuExit::MmioRead(addr, data)) => { data.fill(0); peripherals.mmio_bus.read(addr, data)?; Ok(VcpuEmulation::Handled) }
        Ok(VcpuExit::MmioWrite(addr, data)) => { peripherals.mmio_bus.write(addr, data)?; Ok(VcpuEmulation::Handled) }
        Ok(VcpuExit::FailEntry(..)) | Ok(VcpuExit::InternalError) => Err(VcpuError::FaultyKvmExit(/* fatal */)),
        Ok(VcpuExit::SystemEvent(KVM_SYSTEM_EVENT_RESET|KVM_SYSTEM_EVENT_SHUTDOWN, _)) => Ok(VcpuEmulation::Stopped),  // guest shutdown/reset
        arch_specific_reason => peripherals.run_arch_emulation(arch_specific_reason),   // 架构特有
    }
}

    vCPU 不知道具体设备类型——只把地址和数据交给 Bus，Bus 按地址范围分发到具体 BusDevice（virtio transport/serial/RTC/PCI config MMIO/arch device）。vCPU/KVM 层只负责"guest exit → host bus"桥接。

    9. x86_64 PIO 差异 vs aarch64

    x86_64 Peripherals 同时有 PIO bus + MMIO bus，处理 IoIn/IoOut：

    // src/vmm/src/arch/x86_64/vcpu.rs:161
pub struct Peripherals { pub pio_bus: Option<Arc<Bus>>, pub mmio_bus: Option<Arc<Bus>> }
// :724  run_arch_emulation
match exit {
    VcpuExit::IoIn(addr, data) => { pio_bus.read(u64::from(addr), data)?; Ok(Handled) }
    VcpuExit::IoOut(addr, data) => { pio_bus.write(u64::from(addr), data)?; Ok(Handled) }
    unexpected_exit => Err(VcpuError::UnhandledKvmExit(/*...*/))
}

    aarch64 Peripherals 只有 MMIO bus，run_arch_emulation 统一 unexpected：

    // src/vmm/src/arch/aarch64/vcpu.rs:124
pub struct Peripherals { pub mmio_bus: Option<Arc<Bus>> }     // 无 PIO bus
// :502
pub fn run_arch_emulation(&self, exit: VcpuExit) -> Result<VcpuEmulation, VcpuError> {
    error!("Unexpected exit reason on vcpu run: {:?}", exit);
    Err(VcpuError::UnhandledKvmExit(format!("{:?}", exit)))   // 架构特有 exit 当前 unexpected
}

    aarch64 不代表没有 shutdown/reset——通用层已处理 KVM_SYSTEM_EVENT_RESET/SHUTDOWN。x86_64 pause/restore 还调 kvmclock_ctrl()（避免 resume 后 guest soft lockup watchdog 误判，:276）。aarch64 vCPU 初始化依赖 KVM_ARM_VCPU_PSCI_0_2，restore 时先 vcpu_init() 再恢复 register/MP state/PVTime；KVM_ARM_VCPU_PMU_V3 设置时当前拒绝初始化（Firecracker 未完成 PMU device attr 流程）。

    10. Snapshot 与 vCPU 状态 / 退出收尾

    snapshot 保存 vCPU state 只能在 paused VM：save_vcpu_states() 向每 vCPU 发 SaveState 等 SavedState（lib.rs:620）；vCPU 仍 running 则 SaveState 返 NotAllowed("save/restore unavailable while running")——这是 snapshot 要求 VM 先 paused 的底层原因之一。restore 构建的 vCPU 也先 paused（build_microvm_from_snapshot 启动线程后加载 seccomp 不自动 resume，builder.rs:535；是否恢复后立即运行由 load 的 resume_vm 决定）。

    退出收尾：guest 触发 shutdown/reset system event → running 调 exit(FcExitCode::Ok) → 写 exit eventfd + 循环发 VcpuResponse::Exited 直到收 Finish。Vmm::drop() 向每 vCPU 发 Finish + 清 handles，VcpuHandle::drop() join 线程（lib.rs:857）。

    vCPU 线程不是 detached worker——VMM 生命周期结束显式通知 + join。
