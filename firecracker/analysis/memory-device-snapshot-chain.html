Firecracker Balloon / Virtio-mem Snapshot 状态链路

本文展开 balloon 与 virtio-mem 在 snapshot state 中保存什么，restore 时如何重建设备/transport/queue/guest 协作状态。

源码基线：当前仓库工作树。

相关：snapshot/restore、balloon virtio-mem guest。

0. 术语与背景

两层保存：设备语义状态 + 通用 virtio/transport 状态

  • balloon：target/actual pages + statistics + stats descriptor + hinting state + 通用 virtio feature/queue/activated。
  • virtio-mem：hotpluggable region config + requested size + usable region size + slot size + plugged_blocks bitmap + 通用 virtio state。

plugged_blocks 是关键——restore 后 guest 能继续 plug/unplug（知道哪些 block 已插）。

3. 能力边界

问题 Firecracker 表现
balloon snapshot 存 target/actual pages + stats + hinting + virtio state
virtio-mem snapshot 存 region config + requested/usable size + plugged_blocks bitmap
restore 后能否继续协作 是（balloon 继续 inflate/deflate，virtio-mem 继续 plug/unplug）
snapshot 是否保存 host memory 状态 否（balloon discard 的页面、virtio-mem plugged 的 KVM slot 由 guest 协作重建）
