Firecracker ARM64 与 x86_64 架构差异链路

本文解释 Firecracker 在 ARM64 与 x86_64 上的差异：启动配置、KVM capability、vCPU、PIO/MMIO、FDT/ACPI、设备暴露、snapshot state。

源码基线：当前仓库工作树。

相关：build_microvm_for_boot、vCPU/KVM_RUN、snapshot/restore。

0. 术语与背景

不是两条产品线，是共享生命周期的关键点分叉

API/VmResources/builder 主链路/VMM runtime controller/virtio device worker 大体架构无关。真正差异集中在 src/vmm/src/arch/*、bus、机器描述、KVM state。

路径 x86_64（PC-like） ARM64（virt-like）
CPU 身份 CPUID + CPU template + MSR + LAPIC MPIDR + KVM ARM vCPU init + PSCI
中断控制器 PIT/PIC/IOAPIC + MSI-X GIC + MSI
bus MMIO + PIO MMIO
机器描述 mptable + PVH/LinuxBoot boot params + ACPI FDT（CPU/cache/GIC/设备都进 device tree）
额外 kvmclock CLIDR override + pvtime steal time + counter_offset

设备核心协议（block/net/vsock/balloon/pmem/virtio-mem queue 处理）不按架构分叉——差异在设备如何暴露给 guest + 中断如何送达。

1. KVM capability 差异

// src/vmm/src/arch/x86_64/kvm.rs:48  (x86_64)
pub fn init_arch(fd: KvmFd, kvm_cap_modifiers) -> Result<Self, KvmArchError> {
    request_dynamic_xstate_features()?;                          // 请求 dynamic XSTATE
    let supported_cpuid = fd.get_supported_cpuid(KVM_MAX_CPUID_ENTRIES)?;  // 保存 supported CPUID
    Ok(Kvm { fd, kvm_cap_modifiers, supported_cpuid })
}
// src/vmm/src/arch/aarch64/kvm.rs:40  (ARM64)
pub fn init_arch(fd: KvmFd, kvm_cap_modifiers) -> Result<Self, KvmArchError> {
    Ok(Self { fd, kvm_cap_modifiers })                           // 不保存 CPUID
}
pub fn optional_capabilities(&self) -> OptionalCapabilities {
    OptionalCapabilities { counter_offset: self.fd.check_extension_raw(KVM_CAP_COUNTER_OFFSET) != 0 }  // pvtime
}

x86_64 Kvm 保存 supported_cpuid（后续 vCPU 配置 + CPU template 的基础）；ARM64 不保存 CPUID，额外查 KVM_CAP_COUNTER_OFFSET（pvtime）。

2. 启动配置差异（configure_system_for_boot）

// src/vmm/src/arch/x86_64/mod.rs:175  (x86_64)
let cpu_config = CpuConfiguration::new(kvm.supported_cpuid.clone(), cpu_template, &vcpus[0])?;
load_cmdline(vm.guest_memory(), GuestAddress(CMDLINE_START), &boot_cmdline)?;   // cmdline 写固定地址（x86 特有）
mptable::setup_mptable(/*...*/)?;                                                // mptable
match entry_point.protocol { PvhBoot => configure_pvh(/*...*/), LinuxBoot => configure_64bit_boot(/*...*/) }
create_acpi_tables(/*...*/)?;                                                    // ACPI（仅 x86_64）

// src/vmm/src/arch/aarch64/mod.rs:93  (ARM64)
for vcpu in vcpus { vcpu.kvm_vcpu.configure(vm.guest_memory(), entry_point, &vcpu_config, &optional_capabilities)?; }
override_clidr(vcpus)?;                                                           // CLIDR 与 FDT cache 一致
let vcpu_mpidr = vcpus.iter_mut().map(|c| c.kvm_vcpu.get_mpidr()).collect::<Result<Vec<_>>>()?;
let fdt = fdt::create_fdt(vm.guest_memory(), vcpu_mpidr, cmdline, device_manager, vm.get_irqchip(), initrd)?;  // cmdline/CPU/cache/GIC/设备都进 FDT
vm.guest_memory().write_slice(fdt.as_slice(), fdt_address)?;

核心差异：x86_64 写 boot params + mptable + ACPI；ARM64 写 FDT（CPU/cache/GIC/设备描述都放 device tree）。ARM64 必须先配置 vCPU + 读 MPIDR/cache 再生成 FDT——guest CPU/cache 视图来自 FDT + 寄存器共同约束。

3. FDT vs ACPI

ARM64 FDT 根节点 linux,dummy-virt，创建 CPU（MPIDR 填 reg + host sysfs 读 cache）/memory/chosen/GIC/timer/clock/PSCI/devices/VMGenID/VMClock/PCI nodes（fdt.rs:create_fdt）。override_clidr() 让 vCPU CLIDR_EL1 与 FDT cache 一致。x86_64 ACPI 由 create_acpi_tables() 构造 DSDT/FADT/MADT/MCFG/XSDT/RSDP（描述 interrupt controller/vCPU/VirtIO 设备）。

4. vCPU / bus / 设备暴露 / snapshot 差异

  • vCPU：x86_64 save regs/sregs/xsave/xcrs/LAPIC/MP/CPUID/MSR/events/TSC；ARM64 save MP state/all regs/MPIDR/KVI/PVTime。
  • bus：x86_64 vCPU 持 MMIO + PIO bus（处理 IoIn/IoOut）；ARM64 只 MMIO。
  • 设备暴露：未启 PCI 时 x86_64 加 virtio_mmio.device=... cmdline + DSDT AML；ARM64 在 FDT 生成 virtio_mmio@... + compatible="virtio,mmio"。
  • snapshot：x86_64 直接存 VM state（CPUID/IRQ/ACPI/clock）；ARM64 据 vCPU state 构造 MPIDR 列表恢复 GIC + 拒绝 clock_realtime。
  • legacy：x86_64 i8042/CtrlAltDel/serial PIO；ARM64 system event/Mmio serial（依赖 console=）+ RTC MMIO + pvtime。

5. 能力边界

Firecracker 不是按架构拆两条产品线——共享 microVM 生命周期，只在 KVM/arch/device-description 关键点分叉。设备 queue 处理、rate limiter、TAP、MMDS 逻辑都架构无关。
