Firecracker Virtio Net 数据面链路

本文补齐 virtio-net 具体设备层：从网络 API、NetBuilder、TAP fd、TX/RX virtqueue、rate limiter、MMDS 分流，到 runtime update、snapshot/restore。

源码基线：当前仓库工作树。

相关：virtio device work、virtio block 数据面、MMDS 元数据网络、snapshot/restore。

0. 术语与背景

net = VMM 进程内 virtio 设备 + host TAP

后端是 host TAP：Tap::open_named() 打开 /dev/net/tun + TUNSETIFF 绑定 host_dev_name + IFF_TAP|IFF_NO_PI|IFF_VNET_HDR（tap.rs:120）。双队列（RX/TX），非多队列 RSS。

TX vs RX 方向

  • TX（guest → host）：guest TX descriptor 组装 IoVecBuffer → MMDS 帧同步交 MmdsNetworkStack，否则 writev 写 TAP。
  • RX（host → guest）：先消费 guest RX descriptors → 优先 MMDS 待发帧，无则 readv 从 TAP 收包。

双向 rate limiter + MMDS 分流

RX/TX 各独立 limiter。TX 限速不足 undo_pop() 回退 queue；RX 限速不足保留 deferred frame。MMDS 帧不进 TAP、不计 limiter（rate_limiter_replenish_op 补回 token）。

关键边界

  • runtime PATCH 只更新 RX/TX rate limiter，不能换 TAP/MAC、不能热插 net。
  • snapshot 只存 tap_if_name + virtio/limiter state（不存 host 网络拓扑/bridge/路由/iptables）；restore 重开同名 TAP（可用 network_overrides 替换）。

1. 核心结论

net 是 VMM 进程内 virtio 设备；TAP 后端；TX/RX 双队列 + 双向 limiter + MMDS 分流。runtime PATCH 只改 limiter。snapshot 不存 host 网络资源。ARM64/x86_64 共享数据面，差异在 transport/中断拓扑。

2. TX 路径（process_tx）

// src/vmm/src/devices/virtio/net/device.rs:681
fn process_tx(&mut self) -> Result<(), DeviceError> {
    let tx_queue = &mut self.queues[TX_INDEX];
    while let Some(head) = tx_queue.pop_or_enable_notification()? {
        unsafe { self.tx_buffer.load_descriptor_chain(mem, head) }?;          // IoVecBuffer 解析 frame
        if self.tx_buffer.len() > MAX_BUFFER_SIZE { tx_queue.add_used(head.index, 0)?; continue; }  // 超限→错误完成
        if !Self::rate_limiter_consume_op(&mut self.tx_rate_limiter, frame_len) { tx_queue.undo_pop(); break; }  // limiter 不足→回退
        Self::write_to_mmds_or_tap(self.mmds_ns.as_mut(), /* tx_rate_limiter, tx_buffer, tap */)?;   // MMDS detour 或 TAP writev
        tx_queue.add_used(head.index, 0)?;
    }
    self.try_signal_queue(NetQueue::Tx)?;
}

write_to_mmds_or_tap 先读 VNET header 后 L2 header，is_mmds_frame() 为真则 MMDS 消费（不写 TAP + 补回 limiter token），否则检查 MAC spoofing 后 Tap::write_iovec()（writev，device.rs:497/540）。

3. RX 路径（resume_rx + process_rx）

// src/vmm/src/devices/virtio/net/device.rs:668
fn resume_rx(&mut self) -> Result<(), DeviceError> {
    if self.rx_buffer.used_bytes != 0 {                                       // 先处理 deferred frame（限速未完成的）
        if !self.rate_limited_rx_single_frame(self.rx_buffer.used_bytes) { return Ok(()); }
    }
    self.process_rx()
}
// :628
fn process_rx(&mut self) -> Result<(), DeviceError> {
    loop {
        match self.read_from_mmds_or_tap() {                                  // 优先 MMDS，无则 TAP readv
            Ok(Some(bytes)) => { if !self.rate_limited_rx_single_frame(bytes) { break; } }  // 限速不足→保留 deferred
            Ok(None) => break,                                                // 无 RX buffer
            Err(NetError::IO(err)) if err == EAGAIN => break,                 // TAP 非阻塞无数据
            Err(err) => return Err(DeviceError::FailedReadTap),
        }
    }
    self.try_signal_queue(NetQueue::Rx)
}

read_from_mmds_or_tap 先确认 RX buffer 至少有一个 64K frame 容量，先问 MMDS 是否有响应帧，无才 read_tap()（readv，:567/584）。try_signal_queue 按 prepare_kick（notification suppression）决定是否触发 queue interrupt。

4. Rate Limiter 机制

rate_limiter_consume_op 先消费 ops token 再 bytes token；bytes 不足归还 ops token（:410）。RateLimiter::consume token 不足时 arm timerfd + timer_active=true（rate_limiter/mod.rs:388）。TX limiter 不足 → undo_pop()（descriptor 留 avail）；RX limiter 不足 → 不回退 TAP read（frame 已在 rx_buffer，resume_rx 下次优先处理 deferred）。limiter 不是丢包策略，是设备队列与 TAP 的调度门槛。

5. 事件注册 / Runtime Update / Snapshot

事件注册两阶段：未激活只注册 activate_evt；激活后注册 RX queue/TX queue/tap RX/RX limiter/TX limiter event。TAP fd 用 EventSet::IN | EDGE_TRIGGERED（host 侧有帧可读，不依赖 guest notify，event_handler.rs:20/49/120）。

runtime update：UpdateNetworkInterface → update_net_rate_limiters → with_virtio_device(id) 找 Net → patch_rate_limiters → update_buckets（只改 RX/TX limiter bucket，device.rs:800）。拒绝 InsertNetworkDevice（不能热插，rpc_interface.rs:793）。

snapshot：NetState 存 id/tap_if_name/RX+TX limiter state/MMDS namespace/MAC config space/virtio state（net/persist.rs:34）；TAP 不序列化只存 interface name；restore 据 tap_if_name 重调 Net::new()（重开 /dev/net/tun 绑同名 TAP，:89）。restore_from_snapshot 支持 network_overrides（按 iface_id 改 snapshot 中 tap_if_name，persist.rs:366）——snapshot 不携带 host 网络资源。

6. ARM64/x86_64 / 能力边界

net 的 Net/Tap/TX-RX queue/MMDS detour/limiter/persist 都在架构无关目录。差异在 transport 暴露（MMIO cmdline+DSDT vs FDT virtio,mmio）+ 中断拓扑（IOAPIC/MSI vs GIC/MSI，影响 delivery 不影响 descriptor 解析/TAP I/O）。

能力 Firecracker 表现
网络层级 L2 virtio-net，不管理 host bridge/IP/路由/NAT/防火墙
host_dev_name 必须指向可打开的 TAP interface；恢复时也一样（或 network_overrides）
runtime PATCH 只改 RX/TX 限速，不改 MAC/不触发重新枚举
MMDS 帧 不进 TAP、不计 limiter
snapshot 不保证 TCP/ARP/bridge/会话可无缝保留，只存 VMM 设备 + virtqueue 状态
