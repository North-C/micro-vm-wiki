Firecracker API 到 MicroVM 启动链路

本文追踪一次典型启动：配置 API 请求如何积累到 VmResources，InstanceStart 如何触发 microVM 构建，最后 vCPU 如何进入 KVM_RUN。

源码基线：当前仓库工作树。

相关：VmResources 配置边界、API Event Loop、build_microvm_for_boot。

0. 术语与背景

pre-boot 聚合 → StartMicroVm 分界 → runtime

Firecracker 启动边界清晰：pre-boot 只收集校验配置（VmResources），InstanceStart（→ VmmAction::StartMicroVm）才一次性转换成 KVM VM/guest memory/vCPU/virtio 设备。成功后 pre-boot controller 被 runtime controller 替换。

关键边界

  • API thread 不直接构建 VM——HTTP request 解析成 VmmAction，经 mpsc + eventfd 发 VMM thread。
  • StartMicroVm 是 pre-boot ↔ runtime 唯一分界（成功后 pre-boot loop 退出）。
  • 构建出的 vCPU 初始 paused；build_and_boot_microvm 构建后调 resume_vm() → vCPU 才进 KVM_RUN。
  • SendCtrlAltDel 在 aarch64 API 解析层就拒绝。

1. API 解析（ParsedRequest::try_from）

// src/firecracker/src/api_server/parsed_request.rs:65
match (request.method(), path, request.body.as_ref()) {
    (Method::Get, "", None) => parse_get_instance_info(),
    (Method::Put, "actions", Some(body)) => parse_put_actions(body),
    (Method::Put, "boot-source", Some(body)) => parse_put_boot_source(body),
    (Method::Put, "drives", Some(body)) => parse_put_drives(body),
    (Method::Put, "network-interfaces", Some(body)) => parse_put_net(body),
    // ... /machine-config /vsock /snapshot /balloon /memory-hotplug /entropy /pmem /mmds ...
}
// src/firecracker/src/api_server/request/actions.rs:31
match action_body.action_type {
    ActionType::InstanceStart => Ok(ParsedRequest::new_sync(VmmAction::StartMicroVm)),
    ActionType::SendCtrlAltDel => {
        #[cfg(target_arch = "aarch64")] return Err(RequestError::Generic(BadRequest, "SendCtrlAltDel not supported on aarch64."));
        #[cfg(target_arch = "x86_64")] Ok(ParsedRequest::new_sync(VmmAction::SendCtrlAltDel))
    }
}

SendCtrlAltDel 在 aarch64 解析层就拒绝（非 runtime 才拒）。

2. pre-boot → runtime 边界 / 构建 → resume

pre-boot controller 持续接收 API 聚合 VmResources（直到 built_vmm.is_some() → loop 退出，rpc_interface.rs:385）。start_microvm() → build_and_boot_microvm（builder + resume_vm()），成功存 built_vmm（:609）。

pre-boot 拒绝 runtime action（pause/resume/snapshot create/device update），runtime 拒绝 pre-boot action（boot source/insert/load snapshot/machine config update）。详见 VmResources 配置边界。构建后 vCPU paused，resume_vm() 发 VcpuEvent::Resume → vCPU 才进 KVM_RUN（见 vCPU/KVM_RUN）。

3. ARM64/x86_64

API 解析层唯一架构差异 = SendCtrlAltDel（aarch64 拒绝）。builder/VMM/virtio 主链路架构无关（差异在 arch/*，见 arch ARM64/x86_64）。
