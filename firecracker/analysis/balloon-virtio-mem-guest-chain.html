Firecracker Balloon 与 Virtio-mem Guest 协作链路

本文展开 balloon 与 virtio-mem 在 config interrupt 之后，guest driver 如何通过 virtqueue 与 Firecracker 协作完成内存回收/hinting/热插拔。

源码基线：当前仓库工作树。

相关：runtime device update、memory device snapshot。

0. 术语与背景

运行期内存类更新不是 VMM 单方面完成

API 只改 virtio config space 的目标值/命令值，再用 config interrupt 通知 guest driver。guest driver 观察后经 virtqueue 协作（把 PFN/page range 交设备），VMM 才真正 discard host memory 或更新 KVM slot。

三个协作路径

路径 API 触发 guest 经 queue 回报 VMM 动作
balloon inflate/deflate config_space.num_pages inflate queue 交 PFN discard/restore host backing memory
free page hinting free_page_hint_cmd_id hinting queue 回报空闲 page range discard range
virtio-mem plug/unplug requested_size + usable_region_size mem queue 发 PLUG/UNPLUG/STATE update_kvm_slots() 真正改 memory slot

virtio-mem 真正改 KVM memory slot 不是 API PATCH 时，而是 Firecracker 处理 guest queue 请求调 update_kvm_slots() 时。

1. 核心结论

运行期内存更新 = VMM 改 config space + config interrupt 通知 + guest driver 经 virtqueue 协作。balloon inflate discard host memory；hinting discard free range；virtio-mem PLUG 改 KVM slot。ARM64/x86_64 设备协议相同。

4. virtio-mem update_requested_size + guest PLUG

// src/vmm/src/devices/virtio/mem/device.rs:558
pub fn update_requested_size(&mut self, requested_size_mib: usize) -> Result<(), VirtioMemError> {
    let requested_size = usize_to_u64(mib_to_bytes(requested_size_mib));
    if !requested_size.is_multiple_of(self.config.block_size) { return Err(VirtioMemError::InvalidSize(requested_size)); }
    if requested_size > self.config.region_size { return Err(VirtioMemError::InvalidSize(requested_size)); }
    if self.config.usable_region_size < requested_size { self.config.usable_region_size = requested_size.next_multiple_of(self.slot_size); }
    self.config.requested_size = requested_size;   // guest driver 轮询 config → 经 mem queue 发 PLUG/UNPLUG
}

API PATCH 只改 requested_size/usable_region_size（config space，guest 轮询感知）。guest 发 PLUG 请求后，Firecracker 处理 mem queue → update_kvm_slots() 真正改 KVM memory slot。ARM64/x86_64 设备协议相同，差异在设备发现 + config interrupt 送达。
