Firecracker Virtio 设备工作机制链路

本文展开 vCPU/KVM_RUN 链路 的下一步：guest virtio driver 写 queue notify 后，Firecracker 如何处理 descriptor chain、后端 I/O、rate limiter、used ring 和中断。

源码基线：当前仓库工作树。

相关：vCPU/KVM_RUN、中断与事件通知、virtio block 数据面、virtio net 数据面。

0. 术语与背景

virtio 设备不是独立进程

block/net/vsock 都是 VirtioDevice + MutEventSubscriber，由 VMM 的 EventManager 驱动（在 VMM 进程事件循环里处理，非 process-per-device）。

guest notify 不走 vCPU 线程

guest 写 virtio notify 寄存器，KVM ioeventfd 把它转成设备自己的 queue eventfd，EventManager 调设备 process()。vCPU/KVM_RUN 只负责把 guest I/O exit/ioeventfd 接入 VMM，真正设备语义在 virtio device 的事件处理器。

virtio queue 三件套（avail/used/descriptor）

  • avail ring：guest 放"待处理"descriptor chain 的位置。
  • used ring：设备处理完写回的位置。
  • descriptor chain：一段 guest memory 描述（读/写方向 + 地址 + 长度）。
  • notification suppression：协商 VIRTIO_RING_F_EVENT_IDX 后，设备/guest 可抑制不必要的 notify（prepare_kick/pop_or_enable_notification）。

两阶段事件注册

设备创建后 EventManager 初始只注册 activate_evt；激活后才注册 queue/rate limiter/async completion/TAP fd——避免未激活设备处理运行期事件。

1. 核心结论

  • 普通设备在 VMM 进程事件循环处理（非多进程）；guest notify 经 ioeventfd 唤醒 queue eventfd。
  • 设备从 avail ring 取 descriptor chain → 访问 guest memory → 后端 I/O → 写 used ring → transport interrupt 通知 guest。
  • block 单队列；net RX/TX 双队列 + TAP + MMDS + 双向 rate limiter；vsock RX/TX/Event 三队列 + epoll backend。
  • ARM64/x86_64 设备工作机制基本相同，差异在 transport 暴露（MMIO/FDT vs PCI/ACPI）。

3. VirtioDevice 抽象

// src/vmm/src/devices/virtio/device.rs:73
pub trait VirtioDevice: AsAny + MutEventSubscriber + Send {
    fn avail_features(&self) -> u64; fn acked_features(&self) -> u64;

    fn queues(&self) -> &[Queue]; fn queue_events(&self) -> &[EventFd];   // 暴露给 transport
    fn interrupt_status(&self) -> Arc<AtomicU32>;
    // ... activate() ...
}

DeviceState 只有 Inactive/Activated——激活后保存 GuestMemoryMmap + VirtioInterrupt。设备本体不直接持有 transport 类型，MMIO/PCI transport 经 trait 方法读队列和 event fd。

4. Transport Notify 桥接（ioeventfd）

register_mmio_virtio() 把每 queue eventfd 注册成 KVM ioeventfd 到 NOTIFY_REG_OFFSET，并把 interrupt eventfd 接入 guest IRQ：

// src/vmm/src/device_manager/mmio.rs:175
pub fn register_mmio_virtio(&mut self, vm: &Vm, device_id, mut device, event_manager) -> Result<(), MmioError> {
    let gsi = device.resources.gsi.ok_or(MmioError::InvalidIrqConfig)?;
    for (i, queue_evt) in locked_device.queue_events().iter().enumerate() {
        let io_addr = IoEventAddress::Mmio(device.resources.addr + u64::from(NOTIFY_REG_OFFSET));
        vm.fd().register_ioevent(queue_evt, &io_addr, u32::try_from(i).unwrap())?;   // 每 queue 一个 ioeventfd
    }
    vm.register_irq(&mmio_device.interrupt.irq_evt, gsi)?;                            // interrupt eventfd → guest IRQ
}

PCI transport 类似：register_notification_ioevent() 把 notification BAR 每 queue notify 地址注册到对应 queue eventfd（pci/device.rs:595）。这就是 guest notify 能绕过普通 MMIO exit、直接唤醒 queue eventfd 的原因。

5. Queue 基础机制

Queue::initialize() 据 guest 配置的 desc/avail/used 地址映射 guest memory。pop_or_enable_notification() 在启用 notification suppression 时先设 avail_event，仍有 descriptor 则继续 pop：

// src/vmm/src/devices/virtio/queue.rs:511
pub fn pop_or_enable_notification(&mut self) -> Result<Option<DescriptorChain>, InvalidAvailIdx> {
    if !self.uses_notif_suppression { return self.pop(); }
    if self.try_enable_notification()? { return Ok(None); }   // 设通知条件，无 descriptor 可消费
    Ok(self.pop_unchecked())
}

add_used() 写 used ring + 推进 next_used；advance_used_ring_idx() 用 release fence 保证 used element 写入先于 idx 更新可见。prepare_kick() 类似 Linux vring_need_event()，决定是否通知 guest。

6. Block 设备主链路（process_queue）

VirtioBlock 单队列（BLOCK_QUEUE_SIZES）。queue event → process_queue_event 读 eventfd + 检查 rate limiter/async throttle → process_virtio_queues（实际处理 queue 0）：

// src/vmm/src/devices/virtio/block/virtio/device.rs:389
pub fn process_queue(&mut self, queue_index: usize) -> Result<(), InvalidAvailIdx> {
    let queue = &mut self.queues[queue_index]; let mut used_any = false;
    while let Some(head) = queue.pop_or_enable_notification()? {            // 取 descriptor chain
        match Request::parse(&head, &active_state.mem, self.disk.nsectors) {
            Ok(request) => {
                if request.rate_limit(&mut self.rate_limiter) { queue.undo_pop(); break; }  // 限速不足 → 回退
                request.process(&mut self.disk, head.index, &active_state.mem, &self.metrics)  // 后端 I/O
            }
            Err(err) => { /* parse 失败 → 错误完成 */ }
        };
        match processing_result {
            ProcessingResult::Submitted => {}                               // 异步已提交，等 completion
            ProcessingResult::Throttled => { queue.undo_pop(); self.is_io_engine_throttled = true; break; }
            ProcessingResult::Executed(finished) => {                       // 同步完成
                used_any = true; queue.add_used(head.index, finished.num_bytes_to_mem)?;
            }
        }
    }
    queue.advance_used_ring_idx();
    if used_any && queue.prepare_kick() { active_state.interrupt.trigger(VirtioInterruptType::Queue(0))?; }  // 通知 guest
}

Request::rate_limit() 同时消耗 ops + bytes token，不足则 undo_pop() 回退，稍后由 rate limiter event 继续。Request::process() 按 type 调 file engine read/write/flush（request.rs:364）；同步 engine 返 Executed，异步 engine 返 Submitted（等 async completion event 写 used ring）。

7. Block 完成与中断

同步/错误完成调 queue.add_used(head.index, num_bytes_to_mem) + advance_used_ring_idx()；本轮用了 descriptor 且 prepare_kick() true 则 interrupt.trigger(Queue(0))。异步 engine 的 process_async_completion_event() 读 completion fd + 消费 io_uring CQE + 把对应 request 加 used ring。prepare_save() drain/flush + 处理剩余 completion（保证 snapshot 前队列收敛）。

8. Net 设备主链路（双向）

Net 把 guest L2 frame 与 host TAP 互通：RX/TX queue + 对应 eventfd + TAP fd + RX/TX rate limiter + 可选 MMDS namespace。既响应 guest queue kick，也响应 host TAP fd 事件。

  • TX：TX queue event → process_tx 取 descriptor → IoVecBuffer 解析 frame → 消耗 TX limiter token → write_to_mmds_or_tap（MMDS frame 不计 limiter，普通 frame 经 TAP write_iovec）→ used ring + try_signal_queue(Tx)。
  • RX：RX queue event（guest 给了 buffer）→ parse_rx_descriptors + 检查 RX limiter；TAP RX event（host 有包）→ resume_rx 先处理 deferred frame 再 process_rx（优先 MMDS 再 TAP 读 frame 写 RX descriptor）→ try_signal_queue(Rx)。
// src/vmm/src/devices/virtio/net/device.rs:834
pub fn process_rx_queue_event(&mut self) {
    self.queue_evts[RX_INDEX].read();
    self.parse_rx_descriptors();
    if self.rx_rate_limiter.is_blocked() { /* throttled */ }
    else { self.resume_rx()?; }     // 处理 deferred frame + process_rx（MMDS/TAP）
}
// :389
fn try_signal_queue(&mut self, queue_type: NetQueue) -> Result<(), DeviceError> {
    let qidx = match queue_type { NetQueue::Rx => RX_INDEX, NetQueue::Tx => TX_INDEX };
    self.queues[qidx].advance_used_ring_idx();
    if self.queues[qidx].prepare_kick() { self.interrupt_trigger().trigger(VirtioInterruptType::Queue(qidx))?; }  // 通知
}

9. Vsock 设备主链路

vsock 有 RX/TX/Event 三 virtqueue（vsock/device.rs:45），backend 实现 VsockBackend（组合 VsockChannel + VsockEpollListener），唯一实现是 Unix backend（guest vsock connection → host Unix domain socket）。TX queue event → 包成 VsockPacketTx 调 backend send_pkt；RX queue event 仅在 backend has_pending_rx 时处理；backend fd event → notify(evset) + 重试 TX + 把 pending RX 放 guest RX。event handler 收集本次用过 queue index，最后 signal_used_queues() 一次性通知。prepare_save() 发 transport reset event——vsock 不支持连接跨 snapshot 保持。

10. Transport Interrupt 差异

MMIO interrupt 由 IrqTrigger 实现：queue interrupt 设 VIRTIO_MMIO_INT_VRING，config interrupt 设 VIRTIO_MMIO_INT_CONFIG，再写 irq_evt（mmio.rs:404）。register_mmio_virtio 经 vm.register_irq(&irq_evt, gsi) 接入 guest IRQ。PCI 用 MSI-X vector：VirtioPciDevice::trigger() 按 queue/config 选 vector 调 vectors.trigger()；vector 被 mask 则设 PBA bit（不立即注入）。

11. ARM64 与 x86_64 差异 / 能力边界

层 x86_64 aarch64
virtio-mmio notify KVM ioeventfd 同机制
virtio-pci 可启用，常见于 x86 取决于配置/平台
interrupt MMIO IRQ 或 PCI MSI-X MMIO IRQ 或平台支持的 PCI/MSI-X
queue/descriptor Queue 逻辑共用 同

block/net/vsock 核心 queue 处理几乎不分架构——真正差异在设备如何暴露给 guest + guest 如何接收中断（FDT/GIC vs ACPI/IOAPIC）。

问题 Firecracker 表现
设备是否默认多进程隔离 否，普通设备在 VMM 进程事件循环
guest notify 是否由 vCPU 线程处理 否，ioeventfd 唤醒 queue eventfd
block 是否多队列 当前普通 block 处理 queue 0
