Firecracker Runtime 设备更新链路

本文展开 microVM 启动后，Firecracker API 还能改变什么，以及这些变更如何落到 VMM/设备对象/virtio config interrupt/host I/O 后端。

源码基线：当前仓库工作树。

相关：virtio device work、VmResources 配置边界、device capability boundary。

0. 术语与背景

运行期更新 ≠ 通用热插拔

启动后不能新增 block/net/pmem/vsock/entropy/balloon/memory hotplug 设备，也不能重设 boot source/machine config/CPU config/MMDS 配置。运行期只改少量已有对象的参数。

更新落点分类

更新类型 落点 是否触发 config interrupt
block backing file + rate limiter with_virtio_device 找 Block → update_disk_image/patch_rate_limiters 换 backing file 时是（已激活触发 Config）
net RX/TX rate limiter with_virtio_device 找 Net → patch_rate_limiters 否（只改 token bucket）
pmem rate limiter with_virtio_device 找 Pmem 否
balloon target/stats/hinting update_balloon_config → balloon.update_size 是（trigger Config）
virtio-mem requested size update_memory_hotplug_size → virtio_mem.update_requested_size 否（改 config space，guest 轮询）
MMDS data mmds_put_data/mmds_patch_data 否

所有更新都先经 RuntimeApiController → 加锁 Vmm → DeviceManager::with_virtio_device(id, ...) 找到已有设备对象。

1. 核心结论

运行期更新不是通用热插拔框架。可改的是已有对象的窄字段（block backing/limiter、net limiter、pmem limiter、balloon target/stats、virtio-mem size、MMDS data）。block 换 backing/balloon target/virtio-mem size 更新 config 并触发 config interrupt；rate limiter 只改 host token bucket。ARM64/x86_64 核心逻辑相同（SendCtrlAltDel 只 x86_64 编译）。

2. runtime controller 允许列表 + with_virtio_device

pub fn handle_request(&mut self, request: VmmAction) -> Result<VmmData, VmmActionError> {
    match request {
        CreateSnapshot(cfg) => self.create_snapshot(&cfg),
        UpdateBlockDevice(cfg) => self.update_block_device(cfg),         // block backing + rate limiter
        UpdateNetworkInterface(cfg) => self.update_net_rate_limiters(cfg), // net RX/TX limiter
        UpdatePmemDevice(cfg) => self.update_pmem_rate_limiters(cfg),   // pmem limiter
        UpdateBalloon(cfg) => self.update_balloon_config(cfg.amount_mib), // balloon target
        UpdateBalloonStatistics(cfg) => /* stats polling interval */,
        UpdateMemoryHotplugSize(cfg) => self.update_memory_hotplug_size(cfg), // virtio-mem size
        PatchMMDS(value) => /* MMDS data */,
        PutMMDS(value) => /* MMDS data */,
        Pause => self.pause_vm(), Resume => self.resume_vm(),
        // ... FlushMetrics/GetBalloonConfig/GetBalloonStats/GetMemoryHotplugStatus/GetVmMachineConfig ...
    }
}
// src/vmm/src/device_manager/mod.rs:438
pub fn with_virtio_device<T, F, R>(&self, id: &str, f: F) -> Result<R, FindDeviceError>
where T: VirtioDevice + 'static + Debug, F: FnOnce(&mut T) -> R {
    if let Some(device) = self.get_virtio_device(T::const_device_type(), id) {  // 按 type + id 找
        let mut dev = device.lock().expect("Poisoned lock");
        Ok(f(dev.as_mut_any().downcast_mut::<T>().expect("Invalid device for type")))  // downcast
    } else { Err(FindDeviceError::DeviceNotFound) }
}

with_virtio_device 是所有运行期设备更新的统一入口——按 (VirtioDeviceType, id) 在 PCI 或 MMIO transport 里找设备，downcast 成具体类型，执行窄字段更新。

3. 能力边界

问题 Firecracker 表现
运行期新增 block/net/pmem/vsock 不支持
运行期重设 boot source/machine config/CPU config/MMDS 不支持
block 换 backing file 支持（已激活触发 Config interrupt）
net/pmem 换 rate limiter 支持（只改 token bucket，不触发 interrupt）
balloon target 支持（trigger Config interrupt）
virtio-mem requested size 支持（改 config space，guest 轮询）
vsock/entropy runtime update 无同级 PATCH
