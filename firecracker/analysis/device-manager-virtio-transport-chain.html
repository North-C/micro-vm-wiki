Firecracker DeviceManager / Virtio Transport 链路

本文展开 Firecracker 如何把 VmResources 中的 block/net/vsock/pmem/rng/balloon/virtio-mem 配置变成 guest 可见 virtio 设备。

源码基线：当前仓库工作树。

相关：build_microvm_for_boot、virtio device work、中断与事件通知、vCPU/KVM_RUN。

0. 术语与背景

设备模型三层：VirtioDevice + transport + DeviceManager

  • VirtioDevice（真实设备逻辑）：暴露 feature/queue/queue eventfd/config space/interrupt trigger/activate/reset。
  • transport（guest 可见总线协议）：未启用 PCI 走 virtio-mmio；启用走 virtio-pci。底层真实设备是同一个 VirtioDevice——transport 只换"暴露给 guest 的协议"。
  • DeviceManager：选 transport、分配 bus 资源、把真实设备注册给 EventManager。

激活时机（不是创建即处理）

设备创建后不立即处理 queue。transport 看到 guest driver 状态进 DRIVER_OK 后才调设备 activate()。激活后才把 queue event/tap/rate limiter/async completion 等 runtime event 注册进 EventManager。

性能关键三段

  • 配置寄存器访问 → MMIO bus（transport 的 BusDevice）。
  • 数据面 notify（queue notify）→ ioeventfd（绕过 vCPU exit，KVM 直接 signal queue eventfd）。
  • 设备处理 → EventManager（设备 process()）。

1. 核心结论

  • 设备模型核心 = DeviceManager + VirtioDevice + transport。
  • transport 决定 guest 可见协议（mmio vs pci）；真实设备同一 VirtioDevice。
  • MMIO：kernel cmdline/DSDT(或 FDT) 暴露 + 注册 ioeventfd + irqfd。PCI：PCI bus/BAR/MSI-X/virtio PCI capability + notification ioeventfd。
  • 设备在 guest DRIVER_OK 后才 activate；激活后才接 runtime event。
  • ARM64/x86_64 共用 device + transport 主体，差异在 legacy/机器描述/PIO/MMIO 暴露方式。

2. attach_virtio_device 分流点

所有 builder 里 block/net/pmem/vsock/rng/virtio-mem attach 最终进 attach_virtio_device()，只做关键判断：PCI enabled → attach_pci_virtio_device，否则 attach_mmio_virtio_device（device_manager/mod.rs:266）。is_pci_enabled() 检查 pci_devices.pci_segment 是否存在（:464）；PCI 启用来自 builder 的 enable_pci()（builder.rs:208，构建期决定，运行时不可切）。

3. VirtioDevice 抽象（扩展点）

// src/vmm/src/devices/virtio/device.rs:73
pub trait VirtioDevice: AsAny + MutEventSubscriber + Send {
    fn avail_features(&self) -> u64; fn acked_features(&self) -> u64;
    fn device_type(&self) -> VirtioDeviceType;
    fn queues(&self) -> &[Queue]; fn queue_events(&self) -> &[EventFd];   // 暴露给 transport
    fn read_config(&self, offset, data); fn write_config(&mut self, offset, data);
    fn activate(&mut self, mem, interrupt, ...) -> ActivateResult;        // guest DRIVER_OK 后调
    fn reset(&mut self);
}

Firecracker 的设备扩展点是"实现一个 VirtioDevice"，而不是扩展完整 PC 设备模型。VirtioDeviceType 当前含 net/block/rng/balloon/vsock/mem/pmem。

4. MMIO Transport 注册 + ioeventfd

MMIO 路径建 IrqTrigger + MmioTransport（mod.rs:244）。register_mmio_virtio() 分配 MMIO 地址 + legacy GSI，为每 queue eventfd 注册 ioeventfd，把 interrupt eventfd 注册成 irqfd，插入 MMIO bus，注册真实 device 给 EventManager：

// src/vmm/src/device_manager/mmio.rs:175
pub fn register_mmio_virtio(&mut self, vm: &Vm, device_id, mut device, event_manager) -> Result<(), MmioError> {
    let gsi = device.resources.gsi.ok_or(MmioError::InvalidIrqConfig)?;
    for (i, queue_evt) in locked_device.queue_events().iter().enumerate() {
        let io_addr = IoEventAddress::Mmio(device.resources.addr + u64::from(NOTIFY_REG_OFFSET));
        vm.fd().register_ioevent(queue_evt, &io_addr, u32::try_from(i).unwrap())?;   // 每 queue ioeventfd
    }
    vm.register_irq(&mmio_device.interrupt.irq_evt, gsi)?;                            // interrupt eventfd → irqfd
}

关键：guest 写 notify MMIO 地址时，KVM 直接 signal queue eventfd（不经 vCPU exit 返回用户态）；EventManager 再把事件交真实设备处理。x86_64 还把 virtio-mmio 设备写 kernel cmdline + 生成 DSDT AML（:255）。

5. MMIO Transport 激活时机 + 中断

MmioTransport 实现 BusDevice，guest 写 device status register 时 set_device_status() 检查状态机：进 ACKNOWLEDGE|DRIVER|FEATURES_OK|DRIVER_OK 时调真实设备 activate(mem, interrupt)；失败设 DEVICE_NEEDS_RESET + config interrupt（mmio.rs:168）。中断由 IrqTrigger 实现 VirtioInterrupt：

// src/vmm/src/devices/virtio/transport/mmio.rs:404
impl VirtioInterrupt for IrqTrigger {
    fn trigger(&self, interrupt_type: VirtioInterruptType) -> Result<(), InterruptError> {
        match interrupt_type {
            VirtioInterruptType::Config => self.trigger_irq(IrqType::Config),    // 设 VIRTIO_MMIO_INT_CONFIG
            VirtioInterruptType::Queue(_) => self.trigger_irq(IrqType::Vring),   // 设 VIRTIO_MMIO_INT_VRING
        }   // 再向 irq_evt 写 1（已注册为 irqfd → KVM 注入 guest）
    }
}

6. PCI Transport 注册 + MSI-X

enable_pci() → attach_pci_segment()（单 PCIe segment，PCI virtio 用 MSI-X 不分配传统 IRQ，pci_mngr.rs:75）。attach_pci_virtio_device 分配 SBDF + 按 queue 数建 MSI-X vector group + 构造 VirtioPciDevice + 分配 BAR + attach_common（加 PCI bus、BAR 插 MMIO bus、注册 notification ioeventfd、真实 device 注册 EventManager，pci_mngr.rs:107/139）：

// src/vmm/src/devices/virtio/transport/pci/device.rs:357
pub fn new(id, memory, device, msix_vectors, sbdf) -> Result<Self, VirtioPciDeviceError> {

    let virtio_common_config = VirtioPciCommonConfig::new(/* msix_config: VIRTQ_MSI_NO_VECTOR, msix_queues */);
    let interrupt = Arc::new(VirtioInterruptMsix::new(msix_config, /* config_vector, queues_vectors, msix_vectors */));
    Ok(VirtioPciDevice { configuration, common_config: virtio_common_config, device, virtio_interrupt: Some(interrupt), /*...*/ })
}
// :595  register_notification_ioevent
pub fn register_notification_ioevent(&self, vm: &Vm) -> Result<(), errno::Error> {
    let bar_addr = self.config_bar_addr();
    for (i, queue_evt) in self.device.lock().queue_events().iter().enumerate() {
        let notify_base = bar_addr + u64::from(NOTIFICATION_BAR_OFFSET);
        let io_addr = IoEventAddress::Mmio(notify_base + i as u64 * u64::from(NOTIFY_OFF_MULTIPLIER));
        vm.fd().register_ioevent(queue_evt, &io_addr, NoDatamatch)?;     // 每 queue 一个 notification ioeventfd
    }
}

7. PCI Transport 激活 + 中断

VirtioPciDevice 经 PCI config + BAR 暴露 virtio modern capabilities。write_bar() 分发 common/device config + MSI-X table/PBA；写 common config 后检查 needs_activation()，driver ready 且未激活则调真实设备 activate()（pci/device.rs:909）。中断由 VirtioInterruptMsix 实现：Queue interrupt 按 queue index 查 MSI-X vector，config interrupt 用 config vector；vector 被 mask 则设 PBA bit，否则 MsixVectorGroup 触发 vector（:668）。

PCI 路径不用 MMIO irq status register 语义，也不支持 legacy INTx virtio interrupt——只用 MSI-X。

8. Block / Net 设备事件模型 + 与 vCPU exit 关系

block activate() 初始化 queue + 按 VIRTIO_RING_F_EVENT_IDX 开 notification suppression + 写 activate_evt + 状态 Activated；MutEventSubscriber::init() 未激活只注册 activate event，激活后才注册 queue/rate limiter/async completion event（block/.../event_handler.rs:68）。net activate() 初始化 queue + 按 negotiated features 配 tap offload + 设 RX buffer 最小大小 + 写 activate event；runtime events = RX queue/TX queue/tap RX/RX limiter/TX limiter（net/event_handler.rs:20）。

为什么 guest 未 ready 前写 queue event 不被处理：设备 runtime event 是 activation 后才接 EventManager 的。

vCPU KVM_RUN 遇 MMIO exit 访问 mmio_bus（见 vCPU/KVM_RUN）；MMIO transport 和 PCI BAR 都插同一 vm.common.mmio_bus。queue notify 不一定经 vCPU exit——MMIO/PCI attach 都注册了 ioeventfd，guest 写 notify 地址 KVM 可直接 signal queue eventfd。

9. ARM64/x86_64 差异 / 能力边界

维度 x86_64 aarch64
legacy serial PIO legacy serial MMIO serial（依赖 console=）
reset i8042/CtrlAltDel system event/no CtrlAltDel
virtio-mmio 暴露 cmdline + DSDT AML FDT 设备描述
PIO bus vCPU 设 PIO bus 不走 PIO bus
PCI 可启用 segment 同一 PciDevices 抽象
virtio device logic 共用 共用

主要差异不在 block/net 设备逻辑，而在设备如何被 guest 发现、如何中断、是否有 PIO legacy 路径。

能力 Firecracker 表现
完整 PCI/PC 设备模型 不追求，只保留必要 PCI/ACPI/legacy
virtio-mmio 支持，适合小设备模型
virtio-pci 支持（modern capability + MSI-X）
运行时新增设备 启动后大多不支持，只支持有限 update
host 网络编排 不内置，net 后端是 tap
设备进程隔离 普通 virtio 在 VMM 进程内，vhost-user block 可外置

Firecracker 设备模型不是"功能少所以简单"，而是把复杂度压在 virtio 标准 + KVM ioeventfd/irqfd/MSI-X + host 预配置资源上。
