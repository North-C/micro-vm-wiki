TAP FD 与 NetworkInfo 闭环

本文解释 host TAP 如何从 network-agent 创建，经过 Cubelet 和 CubeShim，最终成为 VM 内 virtio-net 设备和 guest 网络配置。

源码基线：当前仓库工作树。

相关：network-agent EnsureNetwork、CubeVS eBPF 数据面、中断与事件通知。

0. 术语与背景

两条并行链路

链路 做什么
配置链路 TAP name/MAC/IP/route/ARP 写进 cube.net annotation（经 CubeShim → guest agent 配置）
fd 链路 Unix socket + SCM_RIGHTS 传递 TAP fd（network-agent → Cubelet pool → hypervisor lookup_from_pool）

TAP fd 的生命周期

network-agent 是 TAP 的创建者和原始 fd 持有者 → Cubelet 经 requestNetworkAgentTapFile 取 fd 放入 Name2MvmNet 池 → CubeShim/hypervisor 启动 virtio-net 时经 Tap::lookup_from_pool 向 Cubelet cubetap socket 取 fd。

CubeShim 本身主要拿 TAP name + guest 网络配置——真正打开 TAP fd 发生在 hypervisor net_util::Tap::lookup_from_pool。

1. Cubelet requestNetworkAgentTapFile（SCM_RIGHTS 取 fd）

// Cubelet/network/plugin_tap.go:984
func requestNetworkAgentTapFile(socketPath, sandboxID, tapName string, timeout time.Duration) (*os.File, error) {
    conn, err := net.DialUnix("unix", nil, addr)
    reqBody, _ := json.Marshal(&networkAgentTapFDRequest{ Name: tapName, SandboxID: sandboxID })
    conn.Write(reqBody)
    n, oobn, _, _, err := conn.ReadMsgUnix(buf, oob)                       // 读响应 + oob data
    msgs, _ := syscall.ParseSocketControlMessage(oob[:oobn])
    for _, msg := range msgs {
        fds, _ := syscall.ParseUnixRights(&msg)                             // 从 SCM_RIGHTS 取 fd
        if len(fds) > 0 { return os.NewFile(uintptr(fds[0]), "/dev/net/tun"), nil }
    }
}

2. CubeShim NetConfig（TAP name + QoS → VM 配置）

// CubeShim/shim/src/hypervisor/config.rs:248
pub fn add_nets(&mut self, net: &Net) -> CResult<&mut Self> {
    for n in net.interfaces.iter() {
        let nc = NetConfig {
            id: Some(format!("{}-{}", utils::NET_DEVICE_ID_PRE, nets.len())),
            tap: n.name.clone(),   // TAP name（不是 fd，fd 在 lookup_from_pool 时取）
            mac: MacAddr::from_str(&n.mac)?,
            rate_limiter_config: n.qos.as_ref().map(|q| RateLimiterConfig { bandwidth: /*...*/, ops: /*...*/ }),
        };
        nets.push(nc);
    }
}

CubeShim 只拿到 TAP name + guest 网络配置 + QoS rate limiter——不直接持有 TAP fd。fd 在 hypervisor open_tap() 的 fast path 中经 Tap::lookup_from_pool(name, sandbox_id) 向 Cubelet cubetap socket 请求（见 中断与事件通知 §8-9 TAP fd passing）。

3. 能力边界

TAP fd 生命周期完整链路：network-agent 创建 TAP + 持原始 fd → SCM_RIGHTS 传 Cubelet fd pool → hypervisor lookup_from_pool 取 donated fd → virtio-net 设备绑定。这条 fd 链决定 virtio-net 绑哪个 host TAP，但不触发 guest interrupt——中断仍由 virtio queue + ioeventfd + MSI-X + irqfd 完成。
