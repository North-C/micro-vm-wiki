CubeSandbox Rollback / Runtime Update 链路

本文展开 rollback 到 snapshot 与运行时 fs update 的关系——两者都穿过 shim/VMM，但语义完全不同。

源码基线：当前仓库工作树。

相关：virtio net/fs restore、snapshot catalog restore binding、runtime control vmm update。

0. 术语与背景

Rollback ≠ 在线修改 VM 状态

Cubelet 经 containerd Task.Update 把 rollback action 送到 CubeShim → CubeShim 断开 agent + 删除当前 VM → 从指定 snapshot 恢复新 VM。

两条截然不同的链路

操作 做什么 删 VM？
Rollback 删除当前 VM → 从 snapshot restore 新 VM 是
VmSetFs 只更新 VMM config + virtio-fs worker update_filter 否

关键边界

  • Master rollback job 只发逻辑 snapshot_id + sandbox_id + new_gen；物理 rootfs/memory/meta 由 Cubelet 本地 snapshot catalog 解析。
  • Cubelet rollback config 当前只注入 source_url + memory_vol_url + root disk 替换；shim wire format 支持 net/fs/vsock/pmem 但 Go 侧构造器未填。
  • 成功 rollback 后更新 runtime snapshot binding + restore-base binding → 影响后续 CommitSandbox 增量内存基线。

1. rollback_vm（CubeShim）

// CubeShim/shim/src/sandbox/sb.rs:rollback_vm
pub async fn rollback_vm(&mut self, target_config: RestoreConfig) -> CResult<()> {
    if target_config.source_url.as_os_str().is_empty() { return Err("rollback restore_config.source_url is empty".into()); }
    {
        let mut state = self.state.lock().await;
        if *state != SandBoxState::Normal { return Err("sandbox not running, cannot rollback".into()); }
        if self.pause_vm_forbidding().await { return Err("sandbox pause forbidding, terminate exec tasks first".into()); }
        *state = SandBoxState::Paused;
    }
    // ... 断开 agent + VmDelete + drain stale event + restore_vm(target_config) ...
}

rollback 要求 sandbox Normal 状态 + 无 exec 任务阻塞。pause 后 drain 旧 VmShutdown（避免新 monitor 误判恢复后 VM 崩溃）。本质是 snapshot-backed restore，不是冻结旧 VM。

2. VmSetFs（运行时 fs update）

// CubeShim/shim/src/hypervisor/cube_hypervisor.rs
let fs_config = Arc::new(config);
ch.send_request(ApiRequest::VmSetFs(fs_config))??    // 更新 VMM config
// VMM 把 FsEvent 放入 pending message → 写 dev_evt 唤醒 fs worker
// fs worker 收 DEVICE_EVENT → server.update_filter(&allowed_dirs)

VmSetFs 不删 VM——只更新 VMM config + 唤醒 fs worker 调 server.update_filter 更新 allowed dirs。详见 virtio net/fs restore §7。

3. 能力边界

Rollback = "删旧 VM + restore 新 VM"（snapshot-backed，非冻结）。VmSetFs = "在线更新 fs allowed dirs"（不删 VM）。两者都经 CubeShim/VMM，但 rollback 重建整个 VM 生命周期，VmSetFs 只改一个 virtio-fs 设备的过滤策略。
