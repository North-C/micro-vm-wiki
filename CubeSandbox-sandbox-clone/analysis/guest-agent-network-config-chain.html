Guest Agent 网络配置链路

本文解释 CreateSandboxRequest 中的 interfaces/routes/ARPNeighbors/dns 如何落成 guest 内的 eth0/IP/路由/ARP//etc/resolv.conf。

源码基线：当前仓库工作树。

相关：TAP FD NetworkInfo、cubeshim sandbox hypervisor。

0. 术语与背景

CubeShim → guest agent 的网络字段

CubeShim 在 create_sandbox 中把 cube.net annotation 转成 CreateSandboxRequest 的 interfaces/routes/ARPNeighbors/dns。

guest agent 的配置方式

配置 方式
接口（eth0） 按 MAC 地址查找 link（不是按名称）→ 删旧地址 → 添新 IP → 改名 eth0 → 设 MTU → 开 ARP → UP
路由 先查删旧路由（保留 kernel protocol + lo），再按"无 gateway 优先，有 gateway 靠后"添加新路由
ARP 邻居 手工构造 RTM_NEWNEIGH netlink message 添加
DNS 写 /run/cube-containers/sandbox/resolv.conf → bind mount 到 /etc/resolv.conf

1. update_interface（按 MAC 查找）

// agent/src/rpc.rs:970
async fn update_interface(&self, ctx: &TtrpcContext, req: UpdateInterfaceRequest) -> ttrpc::Result<Interface> {
    is_allowed!(req);   // policy check
    let interface = req.interface.into_option().ok_or_else(|| ttrpc_error!("empty update interface request"))?;
    self.sandbox.lock().await.rtnl.update_interface(&interface).await?;   // rtnetlink 修改 guest 内核
    Ok(interface)
}

接口配置不是按 eth0 名称查找设备——而是按 MAC 地址查找 link（因为 guest 枚举顺序不保证名称）。找到后删除旧地址、添加请求中的 IP、改名为 eth0、设置 MTU、打开 ARP 并置 UP。

2. 路由 + ARP + DNS

路由配置先查询删除旧路由（保留 kernel protocol + 跳过 lo），再按优先级添加新路由。ARP 邻居通过手工构造 RTM_NEWNEIGH netlink message 添加（非 ioctl）。DNS 不走 netlink——写 /run/cube-containers/sandbox/resolv.conf 再 bind mount 到 /etc/resolv.conf。

3. 能力边界

guest agent 网络配置是 guest 内最后一层 ready——host 侧 TAP/CubeVS/端口映射由 network-agent 完成，VM 内 virtio-net 设备由 CubeHypervisor 创建，但 guest 内 interface/route/ARP/DNS 必须由 cube-agent 经 netlink/bind mount 完成。三层全部收敛才进入平台可用状态（见 sandbox ready lifecycle）。
