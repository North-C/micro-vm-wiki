    CubeSandbox Redis Benchmark 静态大页/zram 对比报告

    测试条件

    项目 值
    远端机器 root@192.168.25.61
    主机 k8s-master, aarch64, Linux 6.6.0-132.0.0.111.oe2403sp3.aarch64
    CubeSandbox 模板 tpl-irqbypass-xarray-envd-shm2g-20260624101600
    沙箱规格 2 vCPU / 2G（模板资源 cpu=2000m,mem=2000Mi）
    Redis Redis 7.2.6，在每个沙箱内从源码编译，避免宿主/沙箱 glibc ABI 差异
    测试对象 redis-server + Redis 自带 redis-benchmark
    预加载数据集 redis-benchmark -t set -n 1600000 -d 1024 -r 1600000 -c 50 -P 16
    性能测试 redis-benchmark --csv -t set,get -n 300000 -d 1024 -r 1600000 -c 50 -P 16
    本地结果目录 analysis/remote-results/cubesandbox-redis-benchmark-20260627-1523/

    每一轮测试均新建一个沙箱，完成 Redis 编译、启动、预加载、benchmark、结果打包后删除沙箱。第二、三组在沙箱启动后对宿主机配置内存场景，测试结束后恢复 nr_hugepages 并移除临时 zram。

    zram 使用情况

    第三组 zram 配置生效，宿主机 /proc/swaps 在测试期间包含：

    /dev/zram1                              partition   421958756   0       -3

    测试期间 zram Used=0，mm_stat/io_stat 未显示实际 swap I/O。因此本轮结果不能解释为“Redis 使用 zram 换出后性能提升”；更准确的表述是，在 40% 静态大页压力下启用 40% zram swap 后，Redis benchmark 观测吞吐较高，但 zram 没有实际承载换出数据。

    清理状态

    远端测试结束后已确认：

    SwapTotal:       4194300 kB
SwapFree:        4194300 kB
HugePages_Total:       0
HugePages_Free:        0
Hugetlb:               0 kB

    最终 /proc/swaps 只剩测试前已有的 /dev/dm-1，无 /dev/zram* 残留；cubemastercli cubebox list --all 只剩一个历史 exited 沙箱，不属于本次测试。

    结论

    在本次单轮 Redis 业务型负载中，静态大页占用 40% 宿主机内存后，SET 吞吐下降 3.50%，GET 吞吐提升 18.31%。在同样静态大页压力下启用 40% zram swap 后，SET 吞吐相对基线提升 11.48%，GET 吞吐相对基线提升 26.08%。

    需要注意，Redis benchmark 本轮没有触发 zram swap 使用，且每个场景只跑了一轮；GET/SET 的提升更可能受到短时调度、NUMA、缓存状态或 benchmark 波动影响。若要把该结果作为稳定基线，建议后续每个场景至少重复 3-5 次，取中位数和 p95，并固定沙箱 NUMA placement 后再比较。
