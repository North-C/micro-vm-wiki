CubeSandbox ARM64 与 x86_64 架构差异链路

本文分析 CubeSandbox 在 ARM64 与 x86_64 的能力边界、虚拟化机制和实现差异。

源码基线：当前仓库工作树。

相关：CubeShim sandbox hypervisor、CubeVS eBPF 数据面、横向 ARM64/x86_64 差异。

0. 术语与背景

x86_64 是当前主路径

README 明确 x86_64 为 primary/fully-supported，aarch64/arm64 是 preliminary support（前提是主机有 /dev/kvm）。PVM 部署也被 README 限定为 x86_64-only for now。

差异从 README 支持声明一直到 CubeVS eBPF

不是只存在于 VMM——从部署资产、CubeShim 启动参数、VMM arch crate、设备/中断模型、snapshot/restore、CubeVS eBPF 一路向下。

关键架构分叉点

层 x86_64 aarch64
CubeShim seccomp 放行 SYS_mkdir 放行 SYS_mkdirat
kernel cmdline console=hvc0 + no_timer_check 等 console=ttyAMA0,115200
VMM arch CPUID/ACPI/IOAPIC/PIO MPIDR/FDT/GIC/MMIO
PVM x86_64-only 不支持
CubeVS eBPF bpf2go wrapper amd64-only 复用 little-endian eBPF object（bpf_arm64.go）
snapshot restore TSC/clock/CPUID GIC/ITS/MPIDR/vGIC

1. CubeShim seccomp + cmdline 差异

// CubeShim/shim/src/hypervisor/cube_hypervisor.rs:79
cube_hypervisor::set_runtime_seccomp_rules(vec![
    #[cfg(target_arch = "x86_64")] (libc::SYS_mkdir, vec![]),
    #[cfg(target_arch = "aarch64")] (libc::SYS_mkdirat, vec![]),
    (libc::SYS_getsockopt, vec![]), (libc::SYS_setsockopt, vec![]), (libc::SYS_faccessat2, vec![]),
]);
// CubeShim/shim/src/hypervisor/config.rs:79
#[cfg(target_arch = "aarch64")] params.push("console=ttyAMA0,115200".to_string());
#[cfg(not(target_arch = "aarch64"))] params.push("console=hvc0".to_string());

ARM64 syscall ABI 弃用了 mkdir/open/unlink，统一用 *at 系列——这是 seccomp allowlist 差异的根因（与 FC/CH 同源）。console=ttyAMA0 是 ARM64 PL011 串口，console=hvc0 是 x86 virtio-console。

2. VMM arch / snapshot restore / CubeVS 差异

VMM arch crate 差异（CPUID vs MPIDR/FDT/GIC）已在 interrupt event notification 和 interrupt state restore 详述。snapshot restore 在 ARM64 上额外恢复 GIC/ITS/MPIDR（见 vmm snapshot restore state）。CubeVS eBPF 在 ARM64 复用 x86 eBPF object（bpf_arm64.go，注释：bpf2go wrapper 是 amd64-only，但 eBPF bytecode 可跨架构，bpf_arm64.go:46）——ARM64 关注点不在 Go 层 API，而在内核 verifier、TC attach、helper 支持和对象兼容性。

3. 能力边界

x86_64 = 当前主路径（fully-supported + PVM + bpf2go wrapper）。aarch64 = preliminary support（有独立 FDT/GIC/MPIDR/MMIO/VGIC 逻辑，差异在产品集成成熟度与端到端验证面——尤其 CubeVS eBPF + GIC/ITS restore + ARM64 kernel 能力）。
