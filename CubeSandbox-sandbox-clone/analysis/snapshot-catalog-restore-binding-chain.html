Snapshot Catalog / Restore Binding 链路

本文分析 logical snapshot id 如何变成 Cubelet 本地物理对象，并最终注入到新 sandbox 或 running rollback 中。

源码基线：当前仓库工作树。

相关：snapshot create/commit、CubeCoW 存储引擎、rollback runtime update。

0. 术语与背景

"Master thin、Cubelet authoritative" 的 snapshot 物理状态模型

Master 只携带 logical snapshot/template id + replica 状态；rootfs/memory 物理对象由 Cubelet 本地 catalog.json 解析。

注入分两层

  • rootfs：storage create 阶段经 CubeCoW 从 template/snapshot rootfs 派生（CoW reflink）。
  • memory URL：storage prefetch 后由 CBRI 插件写入 OCI annotation cube.vm.snapshot.memory_vol_url。

关键边界

  • create-from-template 和 create-from-runtime-snapshot 都不让 Master 下发物理 memory_vol 或 dev path——Cubelet storage 阶段查本地 catalog 解析。
  • rollback 也走本地 catalog 解析（resolveRollbackTargets）。

1. RestoreConfig 构造（CubeShim）

// CubeShim/shim/src/sandbox/sb.rs  RestoreConfig
let config = RestoreConfig {
    source_url: PathBuf::from(snapshot),   // snapshot 目录（config.json + state.json）
    fs: Some(fss), net: Some(nets), disks: Some(disks), pmem: Some(pmems), vsock: Some(vsock),
    memory_vol_url: restore_memory_vol_url,  // 外部 memory volume URL（file://<devpath>）
    ..Default::default()
};

2. catalog binding labels

// Cubelet/services/cubebox/snapshot_runtime_binding.go:21
func runtimeSnapshotBindingLabels(snapshotID string, attachedAt time.Time) map[string]string {
    return map[string]string{ constants.MasterAnnotationRuntimeSnapshotID: snapshotID, /* attachedAt */ }
}
// Cubelet/services/cubebox/rollback.go  resolveRollbackTargets
entry, err := storage.GetLocalSnapshot(ctx, req.GetSnapshotID())  // 本地 catalog 查
return entry.RootfsVol, entry.MemoryVol, entry.MemoryKind, entry.MetaDir, nil

rollback 经 resolveRollbackTargets 从本地 catalog 查 logical snapshot id 对应的 rootfs/memory/meta 物理路径。成功 rollback 后更新 runtime snapshot binding + restore-base binding（影响后续 CommitSandbox 增量内存基线）。

3. 能力边界

Master 只存 logical snapshot id（不存物理路径）；Cubelet 本地 catalog 是 snapshot 物理状态的权威源。这意味着：rollback/restore 能否成功的前提是请求落到持有 catalog + CubeCoW 文件对象的 Cubelet 节点。跨节点 restore 需要先复制 catalog + CubeCoW 对象（template replica reconciler 负责，见 snapshot replica reconciler）。
