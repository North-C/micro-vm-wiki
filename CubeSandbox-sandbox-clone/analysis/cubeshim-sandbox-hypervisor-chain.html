CubeShim sandbox 与 CubeHypervisor 创建链路

本文承接 API 到 Cubelet 创建链路，从 containerd NewTask 之后追踪 CubeShim 如何创建 VM、连接 guest agent、完成 sandbox/container 生命周期。

源码基线：当前仓库工作树。

相关：cubehypervisor API request、sandbox ready lifecycle。

0. 术语与背景

CubeShim = containerd shim v2 + 内嵌 CubeHypervisor

containerd NewTask 触发 CubeShim（shim v2），CubeShim 内嵌 CubeHypervisor（Cloud Hypervisor 派生 VMM）。经 ApiRequest mpsc + eventfd 控制 VMM thread，经 NotifyEvent channel 接收 guest 生命周期事件。

关键链路

containerd NewTask → TaskService.create → SandBox.init → SandBox.create_sandbox
  → CubeHypervisor launch_vmm → VMM thread
  → start_vm/boot_vm 或 restore_vm
  → wait_notify(VsockServerReady) → connect_agent → CreateSandboxRequest
TaskService.start → agent StartContainer

1. start_vm（launch VMM + wait VsockServerReady）

// CubeShim/shim/src/sandbox/sb.rs:781
async fn start_vm(&mut self) -> CResult<bool> {
    ch.launch_vmm().await?;    // 创建 VmmInstance + 启动 VMM thread
    // ... boot_vm 或 restore_vm ...
    // :810  wait VsockServerReady
    let total_wait = Duration::from_secs(30);
    let wait_res = ch.wait_notify(total_wait).await;
    match &wait_res {
        Ok(ev) if *ev == CH::NotifyEvent::VsockServerReady => { /* agent 可连 */ }
        Ok(ev) => { /* 其他事件 → fallback vsock probe */ }
        Err(_) => { /* 超时 → fallback vsock probe */ }
    }
}

launch_vmm() 建 VmmInstance（VMM thread + ApiRequest mpsc + eventfd + NotifyEvent channel）。boot_vm() 发 ApiRequest::VmBoot，restore_vm() 发 ApiRequest::VmRestore。VMM thread 经 event_notify! 发 NotifyEvent::VsockServerReady（guest 写 sys_ctrl 设备）。

3. 能力边界

CubeShim 不直接实现 virtio queue notify / irqfd 注入——它通过 ApiRequest 下发 VM/device 操作，通过 NotifyEvent 等待生命周期事件。真正设备中断/VMM 执行在 CubeHypervisor VMM thread。ready 不是单点——VM boot ready（VsockServerReady）只表示 VMM 已启动 guest + vsock 可连；sandbox ready 还需 agent CreateSandbox 完成。
