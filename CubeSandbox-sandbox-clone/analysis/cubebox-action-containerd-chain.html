Cubebox Action 到 Containerd / CubeShim 链路

本文承接 Cubelet workflow create 编排链路，展开 create flow 最后一个 cubebox action：前面 workflow action 产出的 StorageInfo/NetworkInfo/CgroupInfo/NetFile 如何被转成 CubeBox 元数据/OCI spec annotations/containerd container/task，并进入 CubeShim。

源码基线：当前仓库工作树。

相关：Cubelet workflow create、CubeShim sandbox hypervisor。

0. 术语与背景

cubebox action = Cubelet create flow 的物化阶段

不是单纯调 containerd——先构造 cubeboxstore.CubeBox + 每 cubeboxstore.Container，再转 workflow 上下文为 OCI spec options，最后 containerd NewContainer() + NewTask() 触发 shim v2。

关键边界

  • workflow 上下文（StorageInfo/NetworkInfo/CgroupInfo/NetFile）经 genSandboxOptions/genContainerTmpOpt/genNetworkAnnotationOpt/genCgroupAnnotationOpt 转成 OCI annotation。
  • containerd task 的 runtime 是 cube shim——NewTask() 是 Cubelet → CubeShim 的真实边界。
  • rootfs/memory 由 storage action 产出；网络由 network action 产出；cgroup 由 cgroup action 产出——cubebox 只负责物化这些上下文。

1. local.Create + createContainers

// Cubelet/services/cubebox/cube_container_create.go:86
func (l *local) Create(ctx context.Context, opts *workflow.CreateContext) error {
    opts.CubeBoxCreated = true
    if err := l.createContainers(ctx, opts); err != nil { return err }
    if cgInfo, ok := opts.CgroupInfo.(*cgroupp.Info); ok {
        cgroupp.SetCubeboxCgroupLimit(ctx, cgInfo.CgroupID, /*...*/)   // host cgroup 限制
    }
}

2. genSandboxOptions（上下文 → OCI annotation）

// Cubelet/services/cubebox/cube_container_create.go:360
func (l *local) genSandboxOptions(ctx, realReq, sandBox, flowOpts) ([]oci.SpecOpts, error) {
    if !flowOpts.IsRetoreSnapshot() { additionalSandboxOpt, _ = WithCubeFsAnnotation(ctx, realReq, sandBox) }
    additionalSandboxOpt = append(additionalSandboxOpt, prepareVolumePmems(flowOpts))
    sOpts, _ := l.genStorageMediumDefaultAnnotationOpt(ctx, flowOpts, sandBox)   // storage medium
    // sandbox DNS → annotation
    dnsServers, _ := sandboxDNSServersFromContainers(realReq)
    if len(dnsServers) > 0 { additionalSandboxOpt = append(additionalSandboxOpt, oci.WithAnnotations(map[string]string{AnnotationsSandboxDNS: string(data)})) }
    l.genImageReferenceForCubebox(ctx, flowOpts, sandBox)
}

genContainerTmpOpt 从 opts.StorageInfo 生成 cube.mount.list；genNetworkAnnotationOpt 从 opts.NetworkInfo 生成网络 annotation；genCgroupAnnotationOpt 从 opts.CgroupInfo 生成 VM spec annotation。这些 annotation 告诉 CubeShim/guest 有哪些 host disk/image device/网络/cgroup。

3. runContainer（Cubelet → CubeShim 边界）

runContainer() 调 l.client.NewContainer(ctx, ci.ID, cOpts...) 创建 containerd container，再 c.NewTask(ctx, ioCreater, taskOpts...) 创建 task（runtime = cube shim）。pod container 从 shim manager 取 endpoint 保存到 sandbox endpoint。详见 cubelet workflow create §7。

4. 能力边界

cubebox action 保证"context 物化 + containerd container/task 创建 + 进入 CubeShim"——不直接保证 VM 已启动或 guest agent 已完成配置。这些靠 CubeShim/CubeHypervisor/cube-agent 完成。
