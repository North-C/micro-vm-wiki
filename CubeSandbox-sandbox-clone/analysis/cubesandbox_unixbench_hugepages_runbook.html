CubeSandbox UnixBench HugePages Runbook

This runbook is for an approved private benchmark host.

Purpose

Measure UnixBench inside one CubeSandbox sandbox using:

  • Baseline: 2 vCPU / 2048 MiB sandbox.
  • Comparison: a new 2 vCPU / 2048 MiB sandbox, then reserve static host hugepages equal to 40% of host memory before running UnixBench.

The driver script restores nr_hugepages after the second run and writes raw data plus REPORT.md.

Run

export REMOTE_TARGET='root@approved-private-host'
export REMOTE_WORKDIR='/approved/private/workdir'
scp analysis/cubesandbox_unixbench_hugepages_benchmark.py "${REMOTE_TARGET}:${REMOTE_WORKDIR}/"
ssh "${REMOTE_TARGET}" "python3 ${REMOTE_WORKDIR}/cubesandbox_unixbench_hugepages_benchmark.py"

If a suitable 2 vCPU / 2 GiB template already exists:

ssh "${REMOTE_TARGET}" \
  "CUBE_TEMPLATE_ID=<tpl-id> python3 ${REMOTE_WORKDIR}/cubesandbox_unixbench_hugepages_benchmark.py"

Expected Output

The remote script prints the report path, usually:

${REMOTE_WORKDIR}/cubesandbox-unixbench-YYYYmmdd-HHMMSS/REPORT.md

Collect the artifacts:

scp -r "${REMOTE_TARGET}:${REMOTE_WORKDIR}/cubesandbox-unixbench-YYYYmmdd-HHMMSS" ./analysis/

Current Blocker

From the original collection environment, SSH to the private benchmark host failed before key exchange:

kex_exchange_identification: Connection closed by remote host
Connection closed by <remote-host> port 22

ssh-keyscan also reports Connection closed by remote host, and HTTP requests to the CubeAPI port return an empty response. This prevents collecting real benchmark data from the remote host in the current session.
