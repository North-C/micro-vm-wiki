Snapshot Replica Reconciler 链路

本文分析 snapshot/template replica 如何被 Master 发现、缓存、校验和用于调度——承接 catalog/restore binding：如果 Cubelet local catalog 是物理权威，Master 的 replica ready 状态就必须能被 catalog 证明。

源码基线：当前仓库工作树。

相关：snapshot catalog restore binding、snapshot create/commit。

0. 术语与背景

TemplateReplica 是控制面状态

Master 的 TemplateReplica 不保存 snapshot path/rootfs vol/memory vol/dev path——只表示某个 logical template/snapshot 在某个节点上应当可用。

权威校验：GetLocalSnapshot

定时 reconciler 调对应节点 Cubelet GetLocalSnapshot——只有 Cubelet local catalog 能返回该 snapshot id，Master 才认为 replica 没漂移。

1. reconcileSnapshotReplicaPresence

// CubeMaster/pkg/templatecenter/snapshot_reconciler.go:201
func reconcileSnapshotReplicaPresence(ctx context.Context) error {
    for _, def := range defs {        // 遍历 READY/FAILED/DELETING 的 snapshot definitions
        replicas, _ := ListReplicas(ctx, def.TemplateID)
        for _, model := range replicas {
            // 经 Cubelet GetLocalSnapshot 校验本地 catalog 是否真有该 snapshot
            rsp, err := cubelet.GetLocalSnapshot(ctx, cubelet.GetCubeletAddr(hostIP), &cubeboxv1.GetLocalSnapshotRequest{ SnapshotID: def.TemplateID })
            switch retCode {
            case ErrorCode_Success:
                if rsp.GetSnapshot() == nil { /* orphan: replica says ready but catalog 没有标记 failed */ }
            case ErrorCode_PreConditionFailed:
                /* orphan: catalog 明确没有 → 清理 replica + 标 definition failed */
            }
        }
    }
}

reconciler 逐个 replica 校验（不是扫全量列表）——每个 replica 调一次 GetLocalSnapshot。catalog 返回空或 PreConditionFailed → orphan → 清理 replica + 标 definition failed。

2. 能力边界

Master replica = 控制面状态（应在某节点可用）；Cubelet local catalog = 物理权威（实际有/没有）。reconciler 的作用是让控制面状态与物理权威一致。ListLocalSnapshots 暴露节点全量 catalog 视图，但当前主 reconciler 不用它——逐个 GetLocalSnapshot 更精确（按 logical id 校验）。
