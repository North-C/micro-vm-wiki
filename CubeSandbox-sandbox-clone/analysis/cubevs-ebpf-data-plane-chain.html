CubeVS eBPF 数据面链路

本文深入 CubeVS：Go API、pinned map、TC program 和包路径分开说明，避免把控制面动作误认为数据面动作。

源码基线：当前仓库工作树。

相关：network-agent EnsureNetwork、CubeShim container agent lifecycle。

0. 术语与背景

CubeVS 不是独立 daemon

它是 network-agent 调用的 Go library + 一组 pinned eBPF maps + 三个 TC program。

层 职责
Go API（控制面） 加载对象、重写全局常量、挂载 TC filter、写入 TAP/端口/SNAT/policy map
TC program（数据面） src/*.bpf.c 逐包执行 NAT、policy、ARP proxy、redirect

三个 TC program

程序 挂载点 作用
from_cube sandbox TAP ingress 出站包：SNAT/端口映射/重定向到 nodenic/cubegw0
from_world host NIC ingress 入站外部流量：TCP/UDP/ICMP NAT，端口映射回 guest
from_envoy cube-dev egress 本地代理回包：DNAT/SNAT + 重定向到目标 TAP

ARM64 复用 x86 eBPF object

bpf_arm64.go 直接嵌入 *_x86_bpfel.o——注释说明 eBPF bytecode 可在 arm64 Linux 上使用（eBPF 是独立字节码，不依赖 host CPU 架构）。

1. AddTAPDevice（控制面入口）

// CubeNet/cubevs/tap.go:43
func AddTAPDevice(ifindex uint32, ip net.IP, id string, version uint32, opts MVMOptions) error {
    mvmIP := ipToUint32(ip)
    mvmID := mvmMetadata{ IP: mvmIP, UUID: stringToByteArray(id), Version: version }
    m, err := borrowPinnedMap(MapNameIfindexToMVMMetadata)   // ifindex → MVM metadata
    // ... 写入 ifindex_to_mvmmeta + mvmip_to_ifindex + remote/local_port_mapping + egress/ingress_sessions ...
}

AddTAPDevice 把 ifindex → MVM metadata（IP/UUID/version/tunnels）和 mvm IP → ifindex 写入 pinned map，并应用网络策略（allow internet/allow out/deny out）。后续逐包处理由 TC program 从这些 map 读取。

2. 关键 pinned maps

map 名 用途
mvmip_to_ifindex guest IP → TAP ifindex（入站查找）
ifindex_to_mvmmeta TAP ifindex → MVM IP/UUID/version（出站查找）
remote_port_mapping host port → guest listen port（入站端口代理）
local_port_mapping guest src port → host port（出站 SNAT）
egress_sessions / ingress_sessions NAT session 跟踪

3. 能力边界

CubeVS 控制面（Go API）由 network-agent 调用，数据面（TC program）由内核执行。ARM64 关注点不在 Go 层 API，而在内核 verifier、TC attach、helper 支持和 eBPF object 兼容性。CubeVS 不参与 virtio 中断——它只处理 host 侧 TAP 的包转发/NAT/policy。
