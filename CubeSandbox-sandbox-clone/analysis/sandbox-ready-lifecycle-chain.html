CubeSandbox Sandbox Ready 生命周期链路

本文追踪创建请求如何从 Cubelet workflow 进入 containerd/CubeShim/VM/guest agent，回答：平台返回成功时哪些层级已 ready。

源码基线：当前仓库工作树。

相关：cubeshim sandbox hypervisor、Cubelet workflow create、guest-agent network config。

0. 术语与背景

ready 是分层收敛结果

VM boot ready（VsockServerReady）只表示 VMM 已启动 guest + vsock 可连；sandbox ready 还需 CubeShim 连接 agent + guest agent 完成 CreateSandbox。

ready 层级

层级 ready 含义 证据
Cubelet workflow 镜像/存储/网络/netfile/cgroup 准备完成 service.Create 返回成功
cubebox action containerd container/task 创建 → 进入 CubeShim runContainer 返回
CubeShim VM boot VMM 启动 + vsock 可连 NotifyEvent::VsockServerReady
CubeShim agent CubeShim 连接 cube-agent connect_agent 成功
guest agent guest 内 CreateSandbox 完成（网络/storage/namespace） agent RPC 成功
平台层 CubeAPI/CubeMaster 收到终态 + metadata 一致 API response

外部 Create 成功的边界在 Cubelet workflow（service.Create 构造 CreateContext → engine.Create → 最终错误码写入 response）。

1. start_vm + wait_notify

// CubeShim/shim/src/sandbox/sb.rs:547  轮询 try_wait_notify
if let Ok(ev) = ch.try_wait_notify() {
    if ev != CH::NotifyEvent::VmShutdown { /* 正常事件 */ }
    else { aborted = true; }   // VM 崩溃
}
// :810  最终等待 VsockServerReady
let total_wait = Duration::from_secs(30);
let wait_res = ch.wait_notify(total_wait).await;
match &wait_res {
    Ok(ev) if *ev == CH::NotifyEvent::VsockServerReady => { /* agent 可连，进入 connect_agent */ }
    Ok(ev) => { /* 其他事件 → fallback vsock probe */ }
    Err(_) => { /* 超时 → fallback vsock probe */ }
}

start_vm 先 launch_vmm + boot_vm（或 restore_vm），再等 VsockServerReady。收到后 connect_agent 连接 cube-agent → 发 CreateSandboxRequest（含 interfaces/routes/ARP/DNS/storages）→ agent 配置 guest 内网络/storage/namespace → 返回。整个链路成功后才算 sandbox ready。

2. 能力边界

CubeSandbox 的 ready 不是单点状态——需 VMM boot + SysCtrl ready + vsock server ready + agent RPC CreateSandbox 全部收敛。任何一步失败都会导致 workflow failover（异步 destroy + cleanup）。ARM64/x86_64 在 workflow 层不分支——差异在 CubeShim/CubeHypervisor/guest kernel/CubeVS eBPF 的 ARM64 端到端验证面。
